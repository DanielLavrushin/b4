Which interface is which

Three settings take an interface name: the capture filter of the packet engine and two fields of a routing set. They sit in different places of the web interface and do different things.

SettingWhereWhat it filtersNone selected
Capture InterfacesSettings > Core > Packet EngineWhich packets the engine inspectsEvery interface
Source InterfacesDNS & Routing > Traffic Routing of a setWhich arriving traffic the set's rules are offeredAny interface
Output InterfaceDNS & Routing > Traffic Routing of a setWhere a matched packet is sentThe set routes nothing

The first two are filters and narrow what b4 does. Only the third sends traffic anywhere. The interface lists of NAT Masquerade and DSCP, and the Uplink interface of the TUN engine, take interface names as well.

Capture Interfaces​

The field is described under Capture Interfaces. For forwarded traffic the engine compares the interface a packet leaves by, because its capture rules run after the kernel has chosen the route. Only the reply direction and DNS are matched on the interface they arrive on.

The leaving interface comes from the routing table. A VPN client, a policy route or a transparent proxy that moves the default route changes it without touching this list, and a selection made before that stops matching. While the selection matches nothing, b4 inspects nothing and no set applies.

Source Interfaces​

Each name becomes an iifname qualifier (-i on iptables) on the set's marking, TPROXY and block rules, so it selects which arriving traffic those rules are offered. The match is on arrival:

  • A WAN interface here never matches traffic from the local network. A LAN client's traffic arrives on the bridge, br0 on most consumer routers, not on the uplink.
  • Traffic the router originates arrives on no interface, so a set with a source interface does not route, proxy or block the router's own connections. See Router's own traffic.

Source devices listed under Targets > Source Devices have the same effect, unless the list is an exclude list. No selection is the usual choice; a name here belongs to a set meant to cover one segment.

Output Interface​

The set's addresses are marked, and an ip rule sends the mark to a routing table whose default route points at this interface. See Network interface and How routing sets work.

Finding which one is wrong​

SymptomSetting to check
Nothing on the Traffic page, or only traffic from the router itselfCapture Interfaces
Sets apply to the router but never to a clientCapture Interfaces, then Source Interfaces
A set's marking rule shows zero packets in the firewall countersSource Interfaces
Traffic is marked but leaves by the wrong pathOutput Interface, and any other service with ip rule entries

The Traffic page answers the first two. When the router is the only source (Router in the device list, or its own address in the raw feed), the engine sees only the traffic the router originates.

When another service also does policy routing, a set can mark traffic correctly and still not use its own table. Using b4 with Xray or XrayUI covers that case.
