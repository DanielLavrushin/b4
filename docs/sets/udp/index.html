UDP

The UDP tab decides which UDP traffic the set matches, QUIC above all, and what b4 does with it. Its most common use is not a bypass over UDP but refusing QUIC, so that the browser falls back to TCP, where the set's TCP strategies apply.

Blocking QUIC​

FieldWhat it doesDefault
Block QUIC (force TCP)Matches every QUIC packet to the set's targets and answers it with ICMP port unreachable. It sets QUIC Matching to By SNI or matched destination and Action Mode to Reject.Off

QUIC carries HTTP/3 for YouTube, Google, Discord and other sites. Its packets are encrypted end to end, so b4 cannot desync the handshake the way it does with TLS over TCP: only decoys and a fragmented Initial packet are left, and both are weak. When a provider silently drops UDP to port 443, a video stalls without an error, and nothing tells the browser to stop trying QUIC. Browsers also remember that a host offered HTTP/3 and keep trying QUIC with it. A refusal from the router makes the browser switch to TCP at once.

Sets for calls​

With Calls on Handle only calls, the set applies its Action Mode, such as fakes, only to the packet that opens each call on the ports in its Port Filter, whatever the address. Which calls decides which calls it takes:

Which callsThe set takes
Discord app and browsersCalls in the Discord app, in browsers and in other apps that start calls with STUN.
Discord appCalls and voice channels in the Discord app.
BrowsersCalls in browsers, Discord in a browser included, and in other apps that start calls with STUN.

The rest of a call the set takes belongs to the set: its later packets pass untouched, or are blocked when the set blocks. Fakes go only before the packet that opens the call. Every other packet on those ports is left to the other sets, or passes untouched. A set with an empty UDP Port Filter leaves those ports alone. A call the set takes belongs to it even when another set matches its destination address, such as a GeoIP set that covers the same servers. The same holds when that address belongs to a domain another set handles.

A set for calls has three requirements. When it breaks one, b4 refuses to save it, and a warning on the tab names the cause.

  • No targets: no domains, IPs, GeoSite or GeoIP categories and no ASNs. Source devices are allowed.
  • A Port Filter on this tab with the ports the calls arrive on. While it is empty, the warning offers Use Discord ports, which enters 19294-19344,50000-50100.
  • An empty Port Filter on the TCP tab. Without targets, a TCP port filter would make the set act on every TCP connection on those ports. The TCP tab shows a warning too.

While Handle only calls is chosen, the tab hides Blocking QUIC and QUIC Matching. With Action Mode on Drop or Reject, or with Block (blackhole) routing on the DNS & Routing tab, the set blocks the packet that opens each call, and a warning says so. The IP Version Filter on the Targets tab limits such a set as well.

Choosing Handle only calls changes Fake Packet Payload from (zero fill) or (auto: QUIC Initial) to (auto: STUN request), and any other payload stays. On some networks zero-filled fakes cut Discord calls short. Leaving Handle only calls in the same edit restores the previous payload. When a set without targets leaves Handle only calls and keeps its UDP Port Filter, it acts on all UDP on those ports, and a hint on the tab says so. Discord voice calls sets up such a set step by step.

How to Handle Matched Traffic​

FieldWhat it doesDefault
Action ModeWhat b4 does with the UDP the set matched, see the table below.Fake & Fragment
ModeWhat happens
OffMatched UDP passes unchanged. b4 still reads the QUIC ClientHello, so a set with domains keeps learning their addresses, for example for routing.
Fake & FragmentDecoy packets go before the real one, and the Initial packet is fragmented. Weak against QUIC.
DropThe packet is dropped without an answer, and for QUIC so is the rest of its connection. The client falls back to TCP once it stops waiting, usually after several seconds.
RejectThe packet is dropped, and for QUIC so is the rest of its connection. An ICMP port unreachable goes back to the client, which switches to TCP at once. The recommended way to refuse QUIC.
Coalesce QUIC InitialSends the handshake packet that carries the server name behind a padding packet in the same datagram. Inspection that reads only the first packet of a datagram no longer sees the name. The rest of the connection goes out untouched, and the handshake itself is unchanged.

When the set blocks its traffic on the DNS & Routing tab, the block action applies instead of the action mode.

Whether the rest of a dropped QUIC connection is dropped too depends on the router. System Info shows it under Kernel Capabilities in the row QUIC drop holds for the whole connection. Where the row reads unavailable, only the first packets of the connection are dropped, and the row shows what the router lacks. Dropped QUIC connections describes the cases.

Everything on this tab applies to IPv6 only while Enable IPv6 Support is on under Settings > Core. With it off, b4 sees no IPv6 packets, and a destination that answers over IPv6 keeps working over QUIC there.
