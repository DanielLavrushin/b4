Faking

The Faking sub-tab sends fake packets that DPI reads and the server discards, and it can change the real ClientHello. Each technique is a separate panel. Discovery picks the fake settings, the TTL included, for the strategies it finds, and manual changes are for tuning. Fake payloads are generated and uploaded under Settings > Payloads.

Fake SNI Packets​

Fake ClientHello packets sent before the real one. DPI reads the fake, and the real ClientHello passes unnoticed.

FieldWhat it doesDefault
Enable Fake SNISends fake packets before the real ClientHello.On
Fake Packet CountHow many fakes to send, 1 to 20.1

Fake payload​

FieldWhat it doesDefault
Fake Payload TypeWhat the fake carries, see the table below.Preset: Google (classic)
Match Fake SizeBuilds the fake from the real ClientHello with the payload's domain fitted to the length of the real name, so both have the same size. A payload that is not a ClientHello is repeated or cut to that size.Off
Randomize TLS RandomReplaces the 32-byte Random field of the fake, so that it differs from the real one.Off
Duplicate Session IDCopies the Session ID of the real ClientHello into the fake.Off

The last two are under Fake Packet TLS Modification, shown for every payload type except Random.

Payload typeThe fake carries
RandomRandom bytes.
Preset: Google (classic), Preset: DuckDuckGoA ClientHello for that site.
Preset: STUNA STUN request.
My own Payload FileA ClientHello generated or uploaded under Settings > Payloads, chosen in Generated Payload.

Inverted OriginalThe real ClientHello with every bit inverted.

Fake strategy​

The How the server rejects it section decides why the server discards the fake while DPI reads it.

FieldWhat it doesDefault
Fake StrategyHow the fake becomes unusable to the server, see the table below.Past Sequence
Sequence OffsetHow far the sequence number is moved, for Random Sequence and Past Sequence.10000
Timestamp DecreaseHow much the TCP timestamp is decreased, for TCP Timestamp.600000
Fake TTLThe TTL of the fakes, 1 to 64. It has to reach the DPI and expire before the server.7
Apply Fake TTLUses Fake TTL whatever the strategy. Without it, the TTL applies only with the TTL strategy.Off
MD5 Signature on FakePuts the TCP MD5 option on the fake, so the server discards it while DPI still reads it.Off
StrategyWhy the server discards the fake
TTLThe fake expires on the way and never reaches the server.
Random SequenceIts TCP sequence number is random.
Past SequenceIts sequence number is one the server has already processed.
TCP CheckIts TCP checksum is wrong.
MD5 SumIt carries a TCP MD5 option that the server has not configured.
TCP TimestampIts TCP timestamp is too old.

The right TTL depends on how many hops away the DPI is. Discovery finds it, and for manual tuning 3 is a starting point.

SYN Fake Packets​

Fake SYN packets sent during the TCP handshake, before the real connection starts. An aggressive technique: fake SYNs can upset some network equipment.

FieldWhat it doesDefault
SYN Fake PacketsSends fake SYN packets during the handshake.Off
SYN MD5 SignatureSends a fake SYN with a TCP MD5 option before the real handshake.Off
SYN Fake Payload Length0 sends the header only, a larger value adds a fake TLS payload, up to 1200 bytes.0
SYN Fake TTLThe TTL of the fake SYNs, 1 to 100.7

TCP Desync Attack​

Fake TCP control packets with broken checksums and a low TTL. They confuse DPI that tracks connections, and the server drops them.

FieldWhat it doesDefault
Desync ModeWhich packets to send, see the table below.Disabled
Desync TTL1 to 50, low enough for the packets to expire before the server.7
Desync Packet CountFake packets per desync with RST Packets, FIN Packets or ACK Packets, 1 to 20. The two combined modes send a fixed set.3
Post-ClientHello RSTSends a fake RST after the ClientHello, to remove the connection from the DPI's tracking table.Off
ModeWhat it sends
RST PacketsFake RSTs, so DPI takes the connection as torn down.
FIN PacketsFake FINs with old sequence numbers, so DPI takes the connection as finished.
ACK PacketsFake ACKs with random future sequence and acknowledgment numbers.
Combo (RST + FIN)RST, FIN and ACK packets in sequence.
Full (RST + FIN + ACK)A fake SYN, then RST, PSH and URG packets.

Window Manipulation​

Fake ACK packets with changed TCP window sizes, sent with a low TTL before the real packet.

FieldWhat it doesDefault
Window ModeDisabled. Zero Window sends a window of 0, then 65535. Random Window sends 3 to 5 fakes with sizes from the list. Oscillate goes through the list in order. Escalate grows from 0 to 65535 in steps.Disabled
Custom Window ValuesThe list for Random Window and Oscillate, values 0 to 65535. An empty list uses the defaults.0, 1460, 8192, 65535

Incoming Response Bypass​

For DPI that slows a connection down once about 15-20 KB have come from the server. b4 sends fake packets towards the server that DPI sees and that expire before they reach it.

FieldWhat it doesDefault
Incoming ModeDisabled. Fake Packets sends a broken ACK for every incoming data packet. Reset Injection, FIN Injection and Desync Combo send fake RST, FIN, or RST, FIN and ACK once the incoming data reaches the threshold.Disabled
Corruption StrategyHow the fakes are made unusable: Bad Checksum, Bad Sequence, Bad ACK, Random for each packet, or All Corruptions.Bad Checksum
Fake TTL1 to 20.7
Fake CountFake packets per injection, 1 to 10.3
Threshold Min, Threshold MaxThe incoming data, in KB, that triggers an injection. Each connection picks a value between the two. Not used by Fake Packets.14, 14

In NFQUEUE mode, while any enabled set has an incoming mode other than Disabled, the server's first packets reach b4 on every connection b4 sends fakes or split segments into, whichever set takes the connection. While no set has one, only the SYN-ACKs and resets of those connections reach b4. See Packet marks.

ClientHello Mutation​

Changes the real ClientHello, not a fake, so that it does not match known DPI signatures.

warning

Mutation changes the ClientHello that reaches the server. When a site stops opening after mutation is turned on, turning it off is the first check.

FieldWhat it doesDefault
Mutation ModeDisabled, Random (random extension order and noise), GREASE Extensions, Padding, Fake Extensions (unknown TLS extensions), Fake SNIs (extra server names) or Advanced (All), which combines them with all their settings.Disabled
GREASE Extension Count1 to 10.3
Padding SizeThe size of the ClientHello with padding, 256 to 16384 bytes.2048
Fake Extension Count1 to 15.5
Add Fake SNIExtra server names put into the ClientHello next to the real one.ya.ru, vk.com, max.ru
