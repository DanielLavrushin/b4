Core

The Core tab decides how traffic reaches b4 and what b4 does with it. Some fields apply only after a restart, see Saving and restarting. Packet capture explains how the engine works.

Packet Engine​

The sub-tab decides how packets reach b4, which address families it handles and how much of each connection it reads.

Ingestion mode​

Ingestion mode selects how packets reach b4. A change applies after a restart.

ModeHow packets reach b4
NFQUEUE (default)Firewall rules hand packets to b4. The usual choice.
TUN interfaceTraffic is routed through a virtual interface that b4 reads. For kernels without the modules NFQUEUE needs.

TUN settings​

Shown while TUN interface is selected.

FieldWhat it doesDefault
Uplink interfaceWhere b4 sends processed packets. Auto (follow default route) moves with the default route when the WAN or VPN changes. A selected interface pins the uplink.Auto (follow default route)
Uplink gatewayThe gateway of a pinned uplink. Empty takes it from the default route.Empty
TUN addressAddress and prefix of the TUN device. Must not overlap a LAN or VPN subnet.10.255.0.1/30
TUN device nameName of the interface b4 creates. Must not be the uplink or another existing interface.b4tun0

Capture Interfaces​

Capture Interfaces, shown in NFQUEUE mode, limits b4 to traffic that leaves the router through the selected interfaces. An empty selection, the default, covers every interface and is the usual choice.

A VPN client or a tunnel can move traffic to another interface, and traffic outside the selection gets no set. When nothing works after an interface is selected, clearing the selection is the first check, see Capture Interfaces match nothing. See also Which interface is which.

When the engine does not start​

When the packet engine fails to start, the web interface keeps working, but traffic passes through the router untouched. The dashboard and the Packet Engine card show the reason. When the kernel lacks the modules NFQUEUE needs, installing them or switching to TUN interface fixes it. b4 retries the start three times within about two minutes, which covers a WAN or VPN that comes up late. Engine start and retries has the details.

IP Block Detection​

IP block detection is turned on per set, on the TCP > General tab. This card holds its global setting.

FieldWhat it doesDefault
Retest interval (seconds)How long an address marked unreachable stays marked before it is tested again. Recovery after a block is lifted can take this long. The interval also paces the checks of pinned DNS addresses.300

IPv4 / IPv6​

FieldWhat it doesDefault
Enable IPv4 Supportb4 handles IPv4 traffic.On
Enable IPv6 Supportb4 handles IPv6 packets, DNS answers and firewall rules. While it is off, sets with Remove ECH keys from DNS answers on still remove ECH keys from IPv6 DNS answers in NFQUEUE mode.Off
Force IPv4 for matched domainsWhile IPv6 support is off, b4 removes IPv6 addresses from DNS answers for domains a set matched, so clients reach them over IPv4.On
IPv6 support off

With IPv6 support off, a targeted site that also answers over IPv6 can be reached over IPv6 past every set. Force IPv4 for matched domains narrows the gap for devices that resolve names through the router, see The IPv4 fallback.

Queue & Packet Processing​

FieldWhat it doesDefault
Queue Start NumberThe first NFQUEUE number b4 reads. Another value is needed only when another program uses the same numbers.537
Packet MarkThe mark on the packets b4 sends itself, such as fakes, so that they pass its processing unchanged. See Packet marks.32768
Worker ThreadsHow many workers process packets in parallel, from 1 to 16.4
TCP Connection Packets LimitHow many packets at the start of each TCP connection reach b4, up to 100. A set can lower it, not raise it.19
UDP Connection Packets LimitThe same for UDP, up to 30.8

Devices​

The Device Filtering card limits DPI bypass to selected devices, or excludes selected devices from it. Applying b4 to selected devices explains what the filter covers and how to set it up.

FieldWhat it doesDefault
Enable Device FilteringTurns the selection on. While it is off, every device gets DPI bypass.Off
Exclude Selected Devices (Blacklist)Off, only the selected devices get DPI bypass. On, the selected devices are excluded from it.Off
Vendor LookupDownloads the IEEE vendor list, about 6 MB, to name each device's manufacturer. A randomized MAC address shows as Private.Off

Available Devices​

While filtering is on, the card lists the devices from the router's ARP table and those added by hand.

ColumnWhat it shows
CheckboxSelects the device.
MAC AddressThe MAC address, or matched by IP for a device added by hand.
IPThe current address. manual marks a device added by hand, offline a named device not on the network now.
NameThe name set with the edit icon, otherwise the vendor.
MSSAn MSS clamp for the device's TCP connections to port 443, from 10 to 1460. Applies whether or not filtering is on.

Manual Devices​

Adds a device that the ARP table does not show, such as one behind another router, by IP Address and an optional Name. Such a device is matched by its IP address. It counts for routing sets, set source devices and its MSS value, but not for DPI bypass, which matches MAC addresses only.

Firewall​

The sub-tab sets how b4 manages its firewall rules, and the rules it adds besides capture.

Firewall Rules​

FieldWhat it doesDefault
Skip IPTables/NFTables SetupFor setups that add the rules by hand. In NFQUEUE mode b4 then installs no capture rules, and masquerade, MSS clamping, DSCP, DNS over TCP interception and Expose to internet are off.Off
Firewall EngineThe backend for the rules of b4. Auto-detect, the usual choice, uses nftables when it works and iptables otherwise.Auto-detect
Firewall Monitor Interval (seconds)How often b4 puts back rules that the router's firewall removed. 0 turns this off in NFQUEUE mode. In TUN mode the minimum is 10.10

Global MSS Clamping​

The clamp sets the TCP maximum segment size of every connection to port 443, the router's own included. The client's ClientHello then leaves in several small segments.

FieldWhat it doesDefault
Enable Global MSS ClampingTurns the clamp on.Off
MSS SizeThe segment size in bytes, from 10 to 1460.88

A device's value in Available Devices wins over this one, and a set's value, on its TCP > General tab, wins over both.

NAT Masquerade​

Masquerading rewrites the source address of forwarded packets to the address of the outgoing interface. Container and gateway setups need it.

FieldWhat it doesDefault
Enable NAT MasqueradeTurns masquerading on.Off
Interface tagsLimits it to the selected outgoing interfaces, typically the uplinks. None selected means every interface.None

DSCP​

b4 can write a DSCP value into the packets it sends, so that a router in front of it can tell its traffic apart. Passing sets to another router shows the setup.

FieldWhat it doesDefault
Set DSCPWrites DSCP value into the packets this host sends out.Off
DSCP valueFrom 0 to 63. Turning the switch on fills in a free value, usually 7, which keeps normal priority on Wi-Fi and on Linux routers.0
Interface tagsThe outgoing interfaces that get the values. None selected means every interface except loopback.None

A set can write its own value into the packets to its addresses, see DSCP, and the card lists such sets.

The value reaches the internet

The router that reads the value is expected to reset it on its internet uplink. Otherwise the provider sees it on every connection b4 carries.

DNS​

The sub-tab holds the DNS settings that apply to every set. The resolver itself is chosen per set, see DNS.

FieldWhat it doesDefault
Intercept DNS over TCPSends DNS over TCP to b4 too. Without it, a client that falls back to TCP skips the set's DNS server.On
Listener portThe local port for DNS over TCP. Another value is needed only when another program holds it.5453
Query timeoutSeconds to wait for a set's DNS server.5
Idle timeoutSeconds an idle DNS-over-TCP connection stays open.30
Read/write timeoutSeconds for one query or answer on an open connection.10
Forward timeoutSeconds to wait for the client's own resolver when no set matched a TCP query.5

SOCKS5​

The sub-tab configures the built-in SOCKS5 proxy. Connections through it leave from the router, and the sets apply to them, see Connections through the built-in SOCKS5 proxy.

FieldWhat it doesDefault
Enable SOCKS5 ProxyStarts the proxy.Off
Bind Address0.0.0.0 listens on every address. 127.0.0.1 is the router only.0.0.0.0
PortThe proxy port.1080
Expose to internetAdds a firewall rule that opens the port to any address, see Access from the internet.Off
Username, PasswordThe login of the proxy, set together. Both empty means no login.Empty
Allowed SourcesThe client addresses allowed to connect. Empty means any.Empty

A change to Enable SOCKS5 Proxy, Bind Address or Port restarts the proxy and closes its connections.

Allowed Sources​

Add IP or CIDR adds an address or a range, IPv4 or IPv6, and From device adds the address of a known device. Other addresses are refused. A client on the router itself needs 127.0.0.1/32.

Chrome and Chromium cannot log in to a SOCKS5 proxy, so a source list is the way to limit them. With a login and a list, a client needs both. The list is not authentication: addresses can be spoofed. It adds no firewall rule either, and binding the proxy to the LAN address is what keeps it off the WAN.
