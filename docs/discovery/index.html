Discovery

Discovery searches for a bypass strategy for the sites named in its field, or for the pages of one set. The result becomes a new set or goes into an existing one. Configured sets keep working during a run.

Unblocking a site walks through a first run, and Keeping sets working shows how the watchdog runs Discovery on its own. How Discovery searches explains a run in detail.

Input​

Site or URL takes domains or full URLs, separated by commas or new lines. A domain is fetched as https://<domain>/, a URL as given. Local and private addresses are refused.

Find a strategy for a set runs Discovery for one set instead and fills the field with the set's Discovery addresses, or with suggestions. A run for a set tests at most five addresses. A set that routes its traffic to a proxy or an interface cannot be picked. When another set handles an address in the field, a warning names that set. Find a strategy in a set card's menu, or on the set editor's Discovery tab, opens this page with the set picked.

The defaults are the usual choice.

A run​

Start begins a run through six steps: DNS, Without bypass, Strategies, Tuning, Combining and Confirming. A row per site shows what has been found so far, and Show log opens the log. A run takes from one to ten minutes, depending on the network.

Stop and confirm ends the search and confirms what was found, without tuning it. Stop ends a run that has found nothing. Stop now, during the confirmation, ends the run at once and keeps the results unconfirmed.

A run stops when b4 rewrites its DSCP rules during it, for example after a set's new DSCP value is saved. Its results cannot be applied, and the history marks the row stopped: firewall rules changed during the search, run it again.

One run is in progress at a time, the searches of the watchdog included. A watchdog search shows on this page but cannot be stopped here.

A run for a set​

A run for a set ends with one verdict for the whole set, above Results per address. The set's own strategy is tested first, as Current strategy of the set, and a strategy is confirmed on all addresses together.

For a set with its own DSCP value, the probes carry that value, as the set's traffic does, and take the set's route through the router in front of b4. The progress and the results show DSCP <value>, as the set's traffic. The probes of any other run carry the value of Set DSCP under Settings > Core > Firewall while it is on, or none, also to the addresses of such a set.

VerdictMeaning and what the card offers
one strategy covers every addressApply to <set> writes the strategy into the set, see Writing into an existing set.
current strategy worksThe set's strategy loads every address. For sites that still fail in a browser, the card names the addresses another set handles. It also notes that the browser may use QUIC (HTTP/3), which Discovery does not test, or another IP version than the run, such as IPv6. IP version for the probes sets the version a run tests.
covers some addressesApply to <set> anyway writes the best strategy. Remove them from this set's Discovery addresses drops the uncovered addresses.
no bypass neededEvery address loads without b4, so these pages cannot show whether the set works.
nothing workedThe cards below show what happened to each address.
stopped before a resultNothing to apply.

The set's Discovery tab shows the last run for it.

Results​

Every site gets one card, under Results per address in a run for a set.

BadgeMeaning and next step
confirmed 3 of 3, not confirmedA strategy, a DNS fix, an alternative address or removing an ECH key made the site load. The card describes the set it creates.
no bypass neededThe site loads without b4.
address blockedConnections to every known address fail, so no strategy can help. The site needs a VPN or a proxy.
intercepted by the gatewayThe first hop in front of this host answers the connection itself. b4 has to run on that gateway, or this host has to be excluded from its redirect. When b4 is the router itself, only a proxy helps.
does not resolveThe name has no address, as with a misspelled domain.
link answers 400The link answers HTTP 400 even without b4. A link to a page or a file the site serves is needed.
nothing foundNo strategy worked. A new run with TLS 1.2 or a captured ClientHello sometimes helps.

Sites that won with the same strategy share one card and one set. N other strategies worked lists the other strategies that loaded the site, fastest first, each with Use instead. The winner is the fastest on a single fetch, which is a noisy measure: a strategy from the list is as valid a choice.

Applying​

Apply as a set, Apply in the history and Use instead open one dialog. It previews the set and offers:

  • Create a new set, then Create set: see Creating a set.
  • Write the strategy into an existing set, then Replace strategy: see below. This is the default when the run was for a set or a set lists the site exactly.
  • Add to <set>, which already uses the same strategy, then Add to set: adds the sites to that set. When the set's strategy changed after the dialog opened, nothing is added.

Copy JSON copies the set without creating it, in the Import/Export format.

A result is applied only to a set whose traffic takes the network path the run tested: the DSCP value of the run's probes, written on the same interfaces. A change to the set's DSCP value, to Set DSCP or to its interface list after the run can change that path. The error then names the difference, and a new run for the set tests the new path. For a few seconds after such a change is saved, while b4 applies its DSCP rules, applying and starting a run are refused.

Writing into an existing set​

Which set to change lists the run's set and the enabled sets without routing that already match the site. Another set picks any other set without routing. Only the bypass strategy is written: TCP, fragmentation, fake packets and, when the result uses them, a DNS redirect, pinned addresses and removing ECH keys. The port filter, RST protection, UDP, targets, routing and escalation stay as they are. Use these addresses as the set's discovery URLs also replaces the set's Discovery addresses.

When the set does not match the sites, Add <sites> to this set adds them and moves them out of other enabled sets. The dialog warns when another set actually handles a site, since the new strategy has no effect there.

Creating a set​

The suggested Set name is the site without its prefix and top-level domain. Match can shorten a single site to a parent domain, so the set also covers its subdomains. A site listed in another enabled set moves into the new one.

The new set goes to the top of the list, enabled. It gets a DNS redirect or pinned addresses only for a site that needed them. The tested addresses become its Discovery addresses, so the set can be searched again or watched.

Alternative addresses​

Some blocks hand out an address that refuses every connection, while clients in other regions get addresses that work. With Check DNS for tampering on, Discovery looks for such addresses when every known address of a site fails. The set pins the site's name to up to three addresses that complete a TLS handshake, so devices get those in DNS answers.

The pins are fixed at the time of the run. When the block moves, a new run with the DNS check on finds new ones. Watchdog searches skip the DNS check and do not refresh pins.

Sites with an ECH key​

A site that publishes an ECH key is probed the way a browser with the key connects, so the ClientHello names the key's public name, such as cloudflare-ech.com. The set targets that name as well.

When the network drops ClientHellos with ECH and the site loads without it, the card is marked ECH blocked. The result is ECH keys removed: a set that turns on Remove ECH keys from DNS answers and changes no packets. A browser with its own secure DNS still sends ECH, so it needs one of the other strategies listed under the result.

History​

The history keeps the latest result of each site, newest first.

  • Apply creates the set the run built, without a new run.
  • Run again repeats the run for the site, or for the set the row came from.
  • Remove from history and Clear history remove one row or all of them.
  • A row expands to the other strategies that worked, each with Use instead.
  • Tried marks a strategy that has been applied as a set, also after the set is deleted.
  • via watchdog and via MCP mark runs that the watchdog or an AI assistant over MCP started.

Last run log opens the log of the last run, also after a restart, and can download it as a text file.
