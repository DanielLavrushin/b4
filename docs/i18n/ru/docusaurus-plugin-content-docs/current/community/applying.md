# Применение сета

**Применить** на карточке или в диалоге подробностей превращает опубликованный сет в локальный. На хабе ничего не меняется; сет создаётся на этом роутере и сразу начинает работать.

## Что делает применение

1. Файлы payload, на которые ссылается сет, загружаются с хаба по хешу. Если ни один хаб не ответил, сет не применяется: фейковый пакет без своего payload - не та стратегия, которая была опубликована.
2. Сет раскрывается с теми же проверками, что и [общий сет](../sets/sharing.md#что-проверяет-импорт), вставленный в **Импорт**: неизвестные этой b4 настройки отбрасываются, неприемлемые значения заменяются значениями по умолчанию, пин для домена вне сета или на частный адрес отбрасывается, DNS-перенаправление на DoH-резолвер вне известного публичного списка отбрасывается. Обо всём этом сообщается после создания сета.
3. Файлы payload устанавливаются в `captures/` и появляются в **Настройки, Пэйлоады** под именем из протокола и имени сервера; существующий файл с тем же именем и другим содержимым сохраняется, а новый получает суффикс с хешем.
4. Категории geosite и geoip, которые называет сет, сверяются с локальными базами. Об отсутствующих в базе категориях сообщается; если базы нет вовсе, категории убираются из сета, а сет, у которого не осталось целей, которые этот роутер может сопоставить, отклоняется.
5. Сет создаётся включённым, с названием из публикации, и ставится первым на странице **Сеты**. Домены, которые он перечисляет, убираются из всех остальных включённых сетов, где они были, чтобы один домен обрабатывался одним сетом; сообщение называет, что и откуда перенесено.
6. Изменение применяется без перезапуска, как сет, сохранённый из редактора.

Сообщение после применения предлагает **Открыть сет**, который открывает его в редакторе, и **Отменить**, который удаляет сет обратно.

:::warning
Домены, перенесённые из других сетов, **Отменить** обратно не возвращает. Домен, который намеренно держали в другом сете, после применения сета сообщества с тем же доменом оказывается в новом сете; в прежний он возвращается только вручную.
:::

## Применён и изменён

Локальный сет помнит, из какого сета на хабе он взят: идентификатор, версию, отпечаток стратегии и дату. Карточка на странице Сообщество показывает **Применён** и получает кнопку **Открыть сет**; карточка на странице Сеты показывает метку **Сет сообщества**, которая открывает сет на странице Сообщество.

Отпечаток покрывает настройки, меняющие пакеты, и настройки DNS-перенаправления. Их изменение в редакторе превращает метку в **Применён, изменён**, а метку на карточке сета - в **Сет сообщества, изменён**. Изменение целей, фильтров портов, пинов, имени, маршрутизации и фильтров устройств правкой не считается, поэтому сет сообщества можно ограничить доменами, которые важны в этой сети, или направить через прокси, не потеряв связь.

Связь важна для двух вещей: для [отметок «работает» и «не работает»](./feedback.md), которые принимаются только пока стратегия не изменена, и для обновления, описанного ниже.

## Обновление и повторное применение

Когда автор публикует новую версию, на карточке применённого сета вместо **Применить** появляется **Обновить до версии N**. У изменённого сета вместо этого **Применить заново**. Обе кнопки заменяют стратегию и цели локального сета опубликованными, после подтверждения; сет сохраняет идентификатор, позицию в списке и состояние включения, а всё остальное, включая маршрутизацию и фильтры устройств, остаётся как было. Правки стратегии и целей теряются, о чём и говорит подтверждение.

:::info
Вытесненные версии остаются рабочими. Роутер, применивший версию 1, продолжает использовать версию 1, пока не нажата кнопка **Обновить**; каталог хранит только новейшую версию, поэтому оценка по отчётам на карточке относится к ней.
:::

## Проверка применённого сета

**Проверить** на применённом сете загружает один домен дважды: один раз через b4 с активным сетом и один раз в обход b4, и показывает оба результата. Домен по умолчанию - тот, по которому был отфильтрован список, иначе первый домен из списка сета; можно ввести любой домен, который сет покрывает.

| Через b4 | В обход b4 | Вердикт |
| --- | --- | --- |
| OK | OK | Сейчас домен ничто не блокирует, сет для него не нужен. |
| OK | не открывается | Сет делает своё дело. |
| не открывается | OK | Сет ломает домен. |
| не открывается | не открывается | Адрес может быть заблокирован целиком, или сайт лежит. |

Результат проверки - загрузка одной страницы в один момент времени, а не отчёт; в хаб ничего не уходит. Это проверка перед тем, как нажать **Работает** или **Не работает**.

## Дискавери и каталог

У [Дискавери](../discovery.md) есть параметр **Сначала пробовать сеты сообщества**, который показывается, пока хаб сообщества включён, и включён по умолчанию. С ним запуск обновляет каталог, если копия старше десяти минут, ищет в нём каждый сайт так же, как страница Сообщество, и берёт до трёх опубликованных сетов на сайт, лучшие по отчётам первыми. Они проверяются после стратегий, запомненных с прошлых запусков, и до встроенных пресетов, под именами `community-<название>-v<версия>`; журнал запуска сообщает, сколько их поставлено в очередь. Сет, payload которого не удалось загрузить, пропускается.

Стратегия сообщества, победившая в запуске, применяется как любой другой результат Дискавери, и созданный ею сет сохраняет связь с сетом на хабе, поэтому на странице Сообщество он показан как **Применён**, и по нему можно отправлять отметки.
