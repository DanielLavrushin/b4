b4 обновляется из веб-интерфейса или скриптом установки. Обновление сохраняет настройки, но перед ним рекомендуется сделать бэкап.

## Обновление из веб-интерфейса {#web-interface}

Внизу бокового меню показана работающая версия. Когда выходит более новый стабильный релиз, там появляется **Доступно обновление** с номерами обеих версий.

1. Скачайте бэкап в разделе **Настройки > Система > Бэкап**, см. [Бэкап настроек](#backup).
2. Нажмите на версию внизу бокового меню. Откроется окно **Управление версиями**.
3. Выберите релиз в списке **Выбрать версию**. **Включить пре-релизы** добавляет в список тестовые сборки.
4. Нажмите **Обновить** или, для более старого релиза, **Откатить**.

b4 запускает установщик, который скачивает релиз, заменяет бинарник и перезапускает сервис. Когда b4 снова работает, страница перезагружается. Файл `update.log` в папке логов, по умолчанию `/var/log/b4`, хранит запись последнего обновления, запущенного отсюда. **Больше не показывать** скрывает уведомление об этом релизе в текущем браузере.

В Docker окно обновить b4 не может и вместо этого показывает команду `docker pull`, см. [Docker](docker.md#management). Не обновляет оно и b4, запущенный вручную, а не как сервис.

Если у роутера нет доступа к GitHub, зеркала и **Установить из файла** описаны на странице [Загрузка b4 при блокировке GitHub](../advanced/update-mirrors.md).

## Обновление установщиком {#installer}

По SSH от root:

```bash
curl -fsSL https://raw.githubusercontent.com/DanielLavrushin/b4/main/install.sh | sh -s -- --update
```

До конкретного релиза, в том числе более старого:

```bash
curl -fsSL https://raw.githubusercontent.com/DanielLavrushin/b4/main/install.sh | sh -s -- --update v1.46.5
```

Установщик откладывает текущий бинарник, останавливает сервис, ставит новую версию и запускает её. Если новый бинарник не запускается, на его место возвращается предыдущий. Настройки остаются как есть.

На MikroTik и в Docker обновление заменяет контейнер, см. [MikroTik](mikrotik.md#update) и [Docker](docker.md#management).

## Бэкап настроек {#backup}

Инструменты бэкапа находятся на вкладке **Бэкап** в разделе **Настройки > Система** и описаны на странице [Система](../settings/system.md#backup):

| Кнопка | Что делает |
| --- | --- |
| **Скачать бэкап** | Сохраняет папку конфигурации в архив `.tar.gz` |
| **Загрузить и восстановить** | Записывает такой архив обратно. Изменения применяются после перезапуска |
| **Скачать безопасную копию** | Сохраняет только `b4.json`, с замаскированными паролями и токенами, чтобы им можно было поделиться |

Архив бэкапа содержит пароли, токены и секреты без маскировки, поэтому его не стоит передавать другим.

Обновление, запущенное из веб-интерфейса, ещё и сохраняет копию `b4.json` рядом с ним под именем `b4.json.bak.v<версия>`, по номеру заменённой версии.

## Удаление b4 {#remove}

```bash
curl -fsSL https://raw.githubusercontent.com/DanielLavrushin/b4/main/install.sh | sh -s -- --remove
```

Установщик останавливает b4, убирает правила файрвола и маршрутизации, которые ставил b4, и удаляет сервис и бинарник. Если b4 остановить не удаётся, ничего не удаляется. В конце установщик спрашивает, удалить ли папку конфигурации, `/etc/b4` или `/opt/etc/b4`, и оставляет её, если ответ не «да».

:::warning
`--remove --quiet` удаляет папку конфигурации без вопроса. Без терминала, например из cron или по `ssh` без `-t`, `--remove` завершается с ошибкой, если не указан `--quiet`.
:::

## Диагностика {#diagnostics}

```bash
curl -fsSL https://raw.githubusercontent.com/DanielLavrushin/b4/main/install.sh | sh -s -- --sysinfo
```

Установщик выводит сведения о системе, установленную версию и состояние модулей ядра. В веб-интерфейсе собственный отчёт b4 открывает **Информация о системе** в разделе **Настройки > Система > Сервис**, см. [Информация о системе](../settings/system.md#system-info).

## Непроверенный TLS {#unverified-tls}

Если ни `curl`, ни `wget` не могут проверить сертификат GitHub, а установка CA-сертификатов не помогает, установщик спрашивает, прежде чем скачивать по непроверенному TLS. С `--quiet` он вместо этого завершается. Переменная окружения `B4_ALLOW_INSECURE_TLS=1` разрешает такую загрузку для этого запуска. Контрольная сумма, полученная по тому же соединению, показывает только то, что загрузка не повреждена.
