О проблемах с b4 сообщают через [issues на GitHub](https://github.com/DanielLavrushin/b4/issues). Форма отчёта об ошибке просит версию b4, платформу, отчёт «Информация о системе» и трассировку лога. Трассировка, записанная в момент проблемы, показывает, что b4 делал с трафиком.

## Что собрать {#what-to-collect}

| Что | Где |
| --- | --- |
| Версия b4 | Внизу бокового меню |
| Информация о системе | **Информация о системе** в разделе **Настройки > Система > Сервис**, затем **Копировать JSON** в окне **Диагностика системы**, см. [Информация о системе](../settings/system.md#system-info) |
| Трассировка лога | Страница **Логи**, см. [Запись трассировки](#recording-a-trace) |
| Сет, о котором идёт речь | **Копировать JSON** на вкладке **Импорт/Экспорт** сета, см. [Импорт/Экспорт](../sets/index.md#импорт-и-экспорт) |
| Конфигурация, если её попросят | **Скачать безопасную копию** в разделе **Настройки > Система > Бэкап**, см. [Безопасная копия](../settings/system.md#safe-copy) |

В тексте отчёта стоит описать, что ожидалось и что произошло вместо этого, какие сет, устройство или приложение затронуты и как часто это повторяется: каждый раз, только на некоторых сайтах или только после того, как b4 поработал какое-то время.

## Запись трассировки {#recording-a-trace}

В трассировку попадают только строки текущего уровня логирования, поэтому сначала уровень повышают.

1. В разделе **Настройки > Система > Сервис** выберите в поле **Уровень логирования** значение **Отладка** и нажмите **Сохранить**.
2. На странице **Логи** нажмите **Начать трассировку**.
3. Воспроизведите проблему, например откройте сайт, который не работает.
4. Нажмите **Остановить и сохранить**. Браузер скачает файл трассировки, а **Скачать последнюю трассировку** скачивает его ещё раз.
5. Верните в поле **Уровень логирования** значение **Инфо**.

Трассировка останавливается сама через 15 минут. Файл описан в разделе [Запись трассировки](../logs.md#запись-трассировки) страницы «Логи».

## Если веб-интерфейс не открывается {#web-interface-does-not-open}

По SSH установщик выводит сведения о системе, установленную версию и состояние модулей ядра, см. [Диагностика](../install/update.md#diagnostics):

```bash
curl -fsSL https://raw.githubusercontent.com/DanielLavrushin/b4/main/install.sh | sh -s -- --sysinfo
```

Если включена запись логов в файл, ошибки b4 и предупреждения при запуске хранит `errors.log` в папке логов, по умолчанию `/var/log/b4`. Команды для чтения лога на OpenWrt и MikroTik приведены в разделе [Особенности платформ](./platforms.md).

## Что может быть личным {#what-can-be-private}

Issues на GitHub видны всем. Собранные файлы содержат сведения о роутере и сети:

| Что | Что содержит |
| --- | --- |
| Информация о системе | Имя хоста, адреса и MAC-адреса интерфейсов, правила файрвола и адрес прокси каждого прокси-сета. Отчёт не маскируется. |
| Трассировка лога | Отчёт «Информация о системе», включённые сеты с первыми доменами каждого, не больше восьми, и строки лога. В строках видны сайты, которые открывают устройства, с IP- и MAC-адресами устройств. Адрес прокси у прокси-сета указан, а логин - нет. |
| JSON сета | Домены и адреса сета. У прокси-сета - ещё адрес прокси, имя пользователя и пароль. |
| Безопасная копия | Сеты, устройства с именами и MAC-адресами, интерфейсы и порты. Пароли, токены, секреты и приватные имена хостов скрыты. |
| Вывод установщика | Имя хоста. |

Каждый из этих файлов - обычный текст, и перед отправкой его содержимое можно просмотреть в текстовом редакторе. Имя или адрес, которые должны остаться личными, заменяют заглушкой, одной и той же везде, где они встречаются.
