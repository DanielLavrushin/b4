## Сайт не открывается {#a-site-does-not-open}

Проверки идут от самой быстрой к самой долгой. Первая проверка, которая не проходит, указывает на причину.

### 1. b4 работает {#b4-is-running}

В штатном режиме поле **Состояние** на [дашборде](../dashboard.md) показывает **Работает**. **Сбой движка** означает, что движок пакетов не запустился: веб-интерфейс работает, но трафик идёт через роутер без изменений, и ни один сет не применяется. Карточка под строкой состояния показывает ошибку, а способы её устранить перечислены в разделе [Сбой движка](./traffic.md#engine-failed).

### 2. Соединения сайта доходят до сета {#reaches-a-set}

1. Откройте сайт на устройстве за роутером.
2. Откройте **Трафик** и найдите домен сайта. Столбец **Сет** показывает сет, с которым он совпал.

| Что видно на странице «Трафик» | Причина и решение |
| --- | --- |
| Домены сайта без сета | Сет выключен, или сайт загружается с доменов, которых в сете нет. Кнопка **+** рядом с доменом добавляет его в сет, см. [Добавление сайтов в сет](../guides/add-sites.md). |
| Другой сет | Сайт обрабатывает этот сет, и стратегия нужного сета к нему не применяется. Как записать стратегию в сет, который обрабатывает сайт, показано в руководстве [Обход блокировки сайта](../guides/unblock.md#если-не-работает). |
| От устройства ничего нет | b4 не видит трафик устройства, см. [b4 не видит трафик](./traffic.md). |

Ссылка **Домены вне сетов** на панели **Активность** дашборда открывает страницу «Трафик» только с соединениями, которые не совпали ни с одним сетом.

### 3. Браузер открывает новые соединения {#browser}

b4 обрабатывает только первые пакеты соединения. Соединение, которое браузер открыл до появления сета или пока стратегия ещё не работала, остаётся без обхода, а браузер продолжает им пользоваться. DNS-ответы он тоже какое-то время хранит.

В Chrome, Edge и других браузерах на основе Chromium:

1. Откройте `chrome://net-internals/#sockets` и нажмите **Flush socket pools**.
2. Откройте `chrome://net-internals/#dns` и нажмите **Clear host cache**.
3. Обновите страницу сайта.

Полный перезапуск браузера даёт тот же результат, в том числе в Firefox. В Windows команда `ipconfig /flushdns` ещё и очищает системный DNS-кэш.

У адреса, введённого без `https://`, есть ещё одна ловушка. Chrome сначала пробует HTTPS и переходит на обычный HTTP, если HTTPS не открылся, например пока сайт заблокирован. После этого он какое-то время выбирает для сайта HTTP, а адресная строка может подсказывать адрес с `http://`. Стратегии, которые находит Дискавери, проверяются по HTTPS, поэтому по обычному HTTP заблокированный сайт обычно так и не открывается. Адрес с `https://` открывает сайт по HTTPS. Shift+Delete (Shift+Fn+Delete на Mac) удаляет подсказку с `http://` из адресной строки.

### 4. DNS {#dns}

b4 видит DNS-запросы, которые устройства отправляют на порт 53. Устройство с зашифрованным DNS, например с защищённым DNS в браузере или с Android Private DNS, обращается к DNS мимо b4. DNS-настройки сетов к нему тогда не применяются: другой резолвер, закреплённые адреса, [откат на IPv4](../dns.md#откат-на-ipv4). Помогает выключить зашифрованный DNS на устройстве, см. [Какой DNS видит b4](../dns.md#что-перехватывает-b4).

Фильтр `flags:dns` на странице **Трафик** показывает запросы доменов из сетов и то, что b4 сделал с каждым, см. [Проверка результата](../dns.md#как-посмотреть-результат). Если запросы устройства там не появляются, оно использует зашифрованный DNS.

Если DNS провайдера отвечает на домены сайта неверными адресами, сет может отправлять свои домены на другой резолвер, см. [Отдельный резолвер для доменов сета](../dns.md#типы-резолверов). Подменяет ли провайдер ответы DNS, показывает [DPI Детектор](../detector.md). Уже полученный ответ устройство использует, пока у него не истечёт срок.

### 5. IPv6 {#ipv6}

Пока **Поддержка IPv6** выключена, b4 обрабатывает только IPv4, и соединение по IPv6 идёт мимо всех сетов. Если у роутера есть IPv6, дашборд показывает в блоке **Требует внимания** сообщение **Трафик IPv6 обходит все сеты**. **Форсировать IPv4 для совпавших доменов** убирает IPv6-адреса доменов сетов из DNS-ответов. Устройство с зашифрованным DNS или с уже полученным адресом всё равно подключается по IPv6. **Поддержка IPv6** в разделе [Настройки > Основные > Движок пакетов](../settings/core.md#protocols) подключает IPv6 к сетам. В режиме TUN IPv6 всегда идёт мимо b4.

### 6. QUIC {#quic}

YouTube, Google, Discord и другие сайты загружаются по QUIC (HTTP/3), а он работает поверх UDP. На странице **Трафик** такие соединения отмечены `UDP` рядом с доменом сайта. Против QUIC у b4 есть только слабые приёмы. **Блокировать QUIC (форсировать TCP)** на вкладке [UDP](../sets/udp.md#блокировка-quic) сета отказывает QUIC, и браузер сразу переходит на TCP, где действует стратегия сета.

### 7. Стратегия ещё работает {#strategy}

Если сайт открывался с сетом, а потом перестал, хотя страница **Трафик** по-прежнему показывает этот сет, стратегия больше не работает. **Найти стратегию** в меню карточки сета или на его вкладке **Дискавери** открывает [Дискавери](../discovery.md) с уже выбранным сетом. Запуск по шагам описан в руководстве [Обход блокировки сайта](../guides/unblock.md). [Поддержание работы сетов](../guides/keep-working.md) показывает, как мониторинг сам находит новую стратегию и записывает её в сет.

### 8. Адрес не заблокирован {#address-blocked}

Некоторые блокировки не обходит ни одна стратегия. Дискавери отмечает их на карточке сайта:

- **адрес заблокирован** - соединения со всеми адресами сайта не проходят;
- **перехвачен шлюзом** - на соединение отвечает сам первый узел перед хостом b4. Если это другой роутер, b4 должен работать на нём, либо хост b4 нужно исключить из его перенаправления.

Такому сайту нужен другой путь: [Маршрутизация сайтов через VPN](../guides/vpn.md) или [Отправка сайтов через прокси SOCKS5](../guides/proxy.md). Если соединения перехватывает шлюз, а b4 уже работает на основном роутере, поможет только прокси. Как провайдер блокирует сайт, показывает [DPI Детектор](../detector.md).

Если все проверки пройдены, а сайт так и не открывается, в разделе [Сообщение о проблеме](./reporting.md) перечислено, что собрать для отчёта об ошибке.
