Страница **Трафик** показывает соединения, которые разбирает b4, по мере их появления: протокол, домен, адрес назначения, устройство и совпавший сет. По ней видно, доходят ли соединения сайта до сета, и с неё домены, адреса и сети добавляются в сеты. Раздел [DNS для сетов](dns.md#как-посмотреть-результат) проверяет на ней ответы DNS.

b4 видит только первые пакеты каждого соединения - в пределах лимитов на соединение из раздела [Настройки > Основные > Движок пакетов](settings/core.md#queue-and-packet-processing). Поэтому одно соединение даёт несколько записей, а число пакетов ничего не говорит о скорости или объёме. DNS-запросы, совпавшие с сетом, тоже попадают на страницу вместе с решением b4 по каждому, пока **Уровень логирования** - **Инфо** или подробнее. Соединение, которое [прокси-сет](sets/routing.md#вышестоящий-прокси-socks5) отправляет в свой upstream, появляется один раз.

Страница открывается в режиме **Группы**. **Сырой поток** в правом верхнем углу показывает вместо них отдельные пакеты.

![Трафик, режим Группы](/img/connections/ru/20260923214001.png)

## Группы

Пакеты сводятся в группы по устройству, протоколу и домену, а пакет без домена - по адресу назначения. Группы накапливаются, пока открыта страница. Уход со страницы, переключение на **Сырой поток** и очистка начинают их заново.

| Столбец | Что показывает |
| --- | --- |
| **Протокол** | `TCP` или `UDP` |
| **Домен** | Домен из рукопожатия или **(без домена)**, версию TLS (`1.2`, `1.3`) и [метки](#метки). У домена вне сетов есть кнопка **+**, см. [Добавление доменов в сеты](#добавление-доменов-в-сеты) |
| **Назначение** | Последний адрес назначения, `+N`, если адресов было несколько, и его [ASN](#asn) |
| **Сет** | Сет, совпавший по домену, и сет, совпавший по IP, если это другой сет |
| **Источник** | Устройство, см. [Устройства](#устройства) |
| **Активность** | Число пакетов по секундам за последнюю минуту |
| **Пакеты** | Число пакетов в группе |
| **Давность** | Время с последнего пакета |

Клик по строке открывает панель **Детали**: активность, число пакетов, время от первого пакета до последнего, источник, все адреса назначения группы и совпавшие сеты. Для домена вне сетов там же есть **Добавить домен в сет**.

Провайдеры могут блокировать TLS 1.2 и TLS 1.3 по-разному, а сет можно ограничить одной версией TLS на вкладке [Цели](sets/targets.md).

### Панель управления

| Элемент | Действие |
| --- | --- |
| Поле фильтра | Оставляет подходящие строки, см. [Фильтр](#фильтр) |
| **30s**, **1m**, **5m**, **15m**, **Всё** | Показывает группы, в которых были пакеты за этот период. По умолчанию **1m** |
| **Только без правил** | Оставляет только группы, не совпавшие ни с одним сетом |
| **Только домены** / **Все пакеты** | См. [Только домены и все пакеты](#только-домены-и-все-пакеты) |
| Корзина | **Очистить пакеты**, см. [Пауза и очистка](#пауза-и-очистка) |

Дашборд открывает эту страницу с включённым **Только без правил** по ссылке **Домены вне сетов** на панели [Активность](dashboard.md#активность) и с выбранным устройством с панели [Блокировки](dashboard.md#блокировки), в обоих случаях с периодом **Всё**.

### Устройства

Панель **Устройства** слева перечисляет источники за выбранный период: давность последнего пакета, активность и число пакетов. Клик по устройству оставляет в списке только его группы, **Все устройства** снимает выбор. **Скрыть устройства** сворачивает панель. **Сортировка устройств** упорядочивает её **По имени** (по умолчанию), **По последней активности** или **По числу пакетов**.

Устройство определяется по MAC-адресу. Если MAC неизвестен, например у устройства за другим роутером, источник показывается по IP-адресу. Псевдонимы из таблицы [фильтрации устройств](settings/core.md#device-filtering) показываются всегда. Когда там включена фильтрация или определение производителя, подставляются и имена обнаруженных устройств, а собственные адреса роутера подписываются **Роутер**.

## Сырой поток

**Сырой поток** показывает последние 1000 пакетов по одному, новые - внизу.

![Трафик, режим Сырой поток](/img/connections/ru/20260923214002.png)

| Столбец | Что показывает |
| --- | --- |
| **Время** | Время пакета |
| **Протокол** | `TCP` или `UDP` и [метки](#метки) |
| **Сет** | Сет, совпавший по IP, а если такого нет - по домену |
| **Домен** | Версию TLS и домен. У домена вне сетов есть кнопка **+** |
| **Источник** | Имя устройства или IP-адрес и порт источника |
| **Назначение** | Адрес и порт назначения, [ASN](#asn) и кнопку **+** для адреса вне сетов |

## Метки

Метки отмечают особые случаи: в режиме **Группы** рядом с доменом, в сыром потоке и в панели **Детали** - рядом с протоколом.

| Метка | Значение |
| --- | --- |
| `dup` | Пакет продублирован, см. [Дублирование пакетов](sets/tcp/general.md#дублирование-пакетов) |
| `ip` | Адрес назначения признан заблокированным по IP. Контурная метка - адрес уже был в кэше заблокированных |
| `block` | Пакет заблокировал [сет блокировки](sets/blocking.md) |
| `proxy` | Соединение пришло через [SOCKS5-прокси](settings/core.md#socks5-proxy) b4 |
| Значок Telegram | Соединение [MTProto-прокси](telegram/mtproto-proxy.md) b4, с именем секрета |
| Значок Telegram с надписью **Мост Telegram** | Соединение, переправленное мостом [Telegram через WebSocket](telegram/websocket-bridge.md) |
| `doh`, `forward`, `pin`, `sinkhole` и другие | Решение b4 по DNS-запросу, см. [DNS для сетов](dns.md#как-посмотреть-результат) |

## Только домены и все пакеты

Переключатель в панели управления действует в обоих режимах.

| Режим | Что показывается |
| --- | --- |
| **Только домены** | Пакеты с распознанным доменом. Режим по умолчанию |
| **Все пакеты** | Все разобранные пакеты, в том числе TCP-рукопожатие до ClientHello, соединения без SNI и трафик на адреса без имени |

## Фильтр

Поле фильтра работает в обоих режимах.

- `+` соединяет условия: должны выполниться все.
- `!` перед условием исключает совпадения.
- `поле:значение` проверяет одно поле. Несколько условий на одно поле выполняются, если совпало любое из них. Пустое значение, например `set:`, совпадает с пустым полем.
- Слово без поля ищется во всех полях.

Поиск не учитывает регистр и ищет подстроку. Поля обоих режимов: `protocol`, `domain`, `destination`, `tls`, `flags`, `asn` и `device` (синоним `alias`). Поле `set` есть только в режиме **Группы**, `source` - только в сыром потоке.

| Фильтр | Что покажет |
| --- | --- |
| `protocol:udp` | UDP-пакеты |
| `domain:youtube` | Пакеты с «youtube» в домене |
| `protocol:tcp+!domain:google.com` | TCP-пакеты, кроме доменов google.com |
| `asn:AS13335` | Адреса назначения в AS13335 (Cloudflare), для которых определён ASN |
| `flags:dns` | DNS-запросы и решения b4 по ним |
| `set:` | Группы, не совпавшие ни с одним сетом |

## Добавление доменов в сеты

Кнопка **+** рядом с доменом открывает окно **Добавить домен в список**.

1. Выберите домен или один из его родительских доменов: они перечислены от самого точного до самого широкого. Для `rr1---sn-ab5l6ne7.googlevideo.com` это само имя и `googlevideo.com`.
2. В поле **Целевой сет** выберите один из включённых сетов или **Создать новый сет** и введите **Название сета**.
3. Нажмите **Добавить домен**.

Домен в сете покрывает и свои поддомены. Сервис, который раздаёт контент со множества поддоменов, например YouTube или CDN, покрывается родительским доменом, например `googlevideo.com`.

## Добавление адресов и сетей в сеты

Кнопка **+** рядом с адресом назначения, а в сыром потоке и клик по самому адресу, открывает окно **Добавить в сет**. b4 выясняет через [RIPEstat](https://stat.ripe.net/), какая сеть анонсирует адрес. Затем окно показывает адрес, анонсированный префикс, который его покрывает, и сеть, например **AS15169 Google LLC**. Если префикс анонсируют несколько сетей, одна из них выбирается в окне. У частного адреса сети нет. Неудачный поиск можно повторить кнопкой **Повторить**, а сам адрес можно добавить в любом случае.

### Что добавить

| Вариант | Что попадает в сет |
| --- | --- |
| **Один IP** | Только этот адрес, как `/32`, для IPv6 - `/128`. Вариант по умолчанию |
| **Анонсированный префикс, который покрывает этот адрес** | Префикс, например `142.250.0.0/15`, если он известен и шире самого адреса |
| Более широкий диапазон | Адрес с маской вроде `/24` или `/16`, для IPv6 - `/64` или `/48`. Сохраняется как сеть: `142.250.120.139/24` становится `142.250.120.0/24` |
| Вся сеть | Сам ASN, см. [ASN](sets/targets.md#asn). b4 загружает его префиксы и обновляет их раз в сутки |

Для всей сети окно показывает число префиксов ASN и примерное число IPv4-адресов в нём и предупреждает о большой сети так же, как редактор сета. Вариант недоступен, если в сете этот ASN уже есть. ASN, префиксы которого ещё неизвестны, добавляется всё равно, а b4 загружает их в фоне.

Сет выбирается в поле **Целевой сет**, как в окне для домена, а кнопка подтверждения называет то, что добавляется, например **Добавить AS15169**.

Когда на вкладке **Настройки > Интеграции** указан токен IPInfo, кнопка **Обогатить через IPInfo** показывает имя хоста, организацию и расположение адреса по данным [ipinfo.io](https://ipinfo.io), а имя хоста можно добавить в домены сета.

[DPI Детектор](detector.md) открывает то же окно из своих результатов по хостингам и CDN, где сеть затронутого провайдера уже выбрана.

## ASN

Иконка сети рядом с адресом назначения определяет сеть без открытия окна. b4 находит ASN, который анонсирует адрес, и загружает его префиксы в свой кэш ASN. После этого адреса этой сети получают метку вида **AS15169 Google LLC**, а фильтр `asn:` их находит. Все браузеры видят одни и те же метки, а ASN, на которые нацелены сеты, тоже подписывают свои адреса.

Крестик на метке удаляет этот ASN из кэша. ASN, на который ещё нацелен какой-либо сет, не удаляется: b4 называет сеты, которые его используют, и метка остаётся.

## Пауза и очистка

Круглая кнопка в правом нижнем углу ставит поток на паузу и возобновляет его. На паузе новые пакеты не собираются. **Очистить пакеты** - корзина в панели управления - удаляет собранные пакеты, группы и устройства.

Число рядом с пунктом **Трафик** в боковом меню считает пакеты, совпавшие с каким-либо сетом. Клик по **Трафик** в меню или очистка пакетов сбрасывает его, а на паузе оно не растёт.
