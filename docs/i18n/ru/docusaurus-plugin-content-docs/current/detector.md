DPI Детектор показывает, что провайдер делает с трафиком, уходящим с роутера. Он определяет, какие сайты заблокированы и как, подменяются ли ответы DNS, обрываются ли длинные соединения с хостингами и доступен ли Telegram. Каждый сайт запрашивается дважды, напрямую и через b4, поэтому результат показывает и блокировку, и то, исправляет ли её сет. Место детектора в общей последовательности описано в руководстве [Обход блокировки сайта](./guides/unblock.md).

Проверки и списки целей взяты из проекта [dpi-detector](https://github.com/Runnin4ik/dpi-detector).

## Настройка проверки

**Сайты для проверки** принимает домены или URL через пробел или с новой строки. URL с путём проверяется по этому пути. Если сайты не добавлены, проверяется встроенный список. **Заполнить из:** подставляет встроенный список или домены, перечисленные вручную в разделе **Цели** включённых сетов.

**Что проверять** предлагает четыре области:

| Область | На какой вопрос отвечает | По умолчанию |
| --- | --- | --- |
| **Сайты** | Открывается ли каждый сайт, как он заблокирован и исправляет ли это b4. | Вкл. |
| **DNS** | Честно ли резолверы отвечают на заблокированные имена, перехвачен ли порт 53, какие серверы DoH и DoT работают. | Вкл. |
| **Хостинги и CDN** | Обрываются ли длинные соединения с Hetzner, Cloudflare, Akamai и другими сетями после первых килобайт. | Выкл. |
| **Telegram** | Доступны ли датацентры, скорость скачивания и отправки. | Выкл. |

Остальное собрано в разделе **Дополнительно**:

| Параметр | Что делает | По умолчанию |
| --- | --- | --- |
| **Семейство IP** | IPv4, IPv6 или оба. Виден, когда движок захвата обрабатывает оба семейства. При выборе обоих сайт с IPv6-адресом получает вторую строку. | оба |
| **Параллельных проверок** | Сколько проверок идёт одновременно. Меньшее значение щадит слабый роутер. | 5 |
| **Режим запросов** | **напрямую и через b4** или **только напрямую**. | напрямую и через b4 |
| **Пробовать и TLS 1.2** | Если сайт заблокирован по TLS 1.3, проверяет, проходит ли TLS 1.2. | Вкл. |
| **Искать рабочий SNI для заблокированных хостингов** | Для каждой сети, которая обрывает длинные соединения, перебирает известные белые имена в SNI. | Выкл. |

**Запустить проверку** начинает проверку, а **Остановить и сохранить результаты** завершает её досрочно.

## Чтение результатов

Первым идёт вердикт со счётчиками сайтов, заблокированных провайдером, починенных b4 и всё ещё заблокированных. **Починить N через Дискавери** открывает [Дискавери](./discovery.md) с уже подставленными заблокированными сайтами. **Скопировать отчёт** копирует текстовый отчёт для issue или форума.

### Сайты

В таблице строка на сайт со столбцами **Напрямую**, **Через b4** и **Итог**:

| Итог | Значение |
| --- | --- |
| **Работает** | Открывается обоими способами. |
| **Починено b4** | Напрямую заблокирован, через b4 открывается. В строке назван сет. |
| **Всё ещё заблокирован** | Заблокирован обоими способами. Строка сообщает, что сайт не покрыт ни одним сетом, сет выключен или сет не помогает. |
| **Ломается через b4** | Напрямую открывается, через b4 нет. Подходящий сет вредит. |
| **Ошибка на стороне сайта** | Сам сайт ответил ошибкой обоими способами. |
| **Резолвер не дал адреса** | Резолвер хоста b4 не даёт адреса для сайта, а DoH даёт, и по этому адресу сайт открывается. |

Прямой результат показывает, как заблокирован сайт:

| Статус | Значение |
| --- | --- |
| **Сброс** | TCP reset на TLS-рукопожатии. |
| **Дроп** | TLS-рукопожатие остаётся без ответа. |
| **Недоступен** | Соединение не устанавливается. |
| **Обрыв** | Передача останавливается после первых килобайт. |
| **Подмена DNS** | Резолвер отвечает адресом-заглушкой. Адрес из DoH показан рядом. |
| **Нет адреса** | Резолвер не даёт адреса для имени. |
| **Заглушка** | Перенаправление на страницу провайдера или сама эта страница. |
| **Подменённый сертификат** | Сертификат подменён. |
| **TLS alert**, **Мусорный ответ** | Поддельный TLS alert или мусор вместо TLS. |
| **Отказ**, **Таймаут** | Соединение отклонено, или ответа нет в отведённое время. |
| **Шлюз** | На соединение отвечает сам первый узел перед этим хостом, как это делает прозрачный прокси. Ничто из того, что b4 делает на этом хосте, дальше него не проходит. |

У сайтов со статусом **Шлюз** и итогом **Резолвер не дал адреса** свои счётчики, и **Починить через Дискавери** их не подставляет: стратегия им не поможет.

Имена разрешаются через резолвер хоста, на котором работает b4, из его `/etc/resolv.conf`. Устройства в сети могут пользоваться другим резолвером, поэтому то, что таблица показывает про DNS, относится к хосту b4. Строка над таблицей называет использованные резолверы.

### DNS

В таблице строка на резолвер, первыми идут резолверы хоста b4. Ячейки задержки показывают самый быстрый ответ по UDP, DoH и DoT. **Честность** сравнивает ответы резолвера на заблокированные имена с ответами шифрованных резолверов:

| Значение | Что означает |
| --- | --- |
| **Честный** | Ответы совпадают. |
| **Подменяет** | Адрес-заглушка или адрес из зарезервированного диапазона там, где шифрованные резолверы дают настоящий. |
| **Не отвечает** | Обычные имена резолвятся, а на заблокированные - таймаут или ошибка. |
| **Фильтрует** | NXDOMAIN или пустой ответ на заблокированные имена, без подделки адреса. |

**На порт 53 ответил** - сеть, которая ответила на запрос к резолверу. Если это не сеть самого провайдера и не известный публичный резолвер, строка помечается как **перехват**. **скопировать DoH URL** копирует рабочий DoH-сервер для DNS-перенаправления сета.

### Хостинги и CDN

В таблице строка на сеть с числом целей, у которых соединение оборвалось, и точкой обрыва (**Обрыв на**). **Рабочий SNI**, если поиск был включён, перечисляет прошедшие имена для фейкового SNI сета. **Добавить &lt;ASN&gt; в сет** открывает диалог добавления со страницы [Трафик](./connections.md#добавление-адресов-и-сетей-в-сеты), где уже выбрана эта сеть.

### Telegram

Панель показывает, сколько датацентров доступно, и скорость скачивания и отправки.

## Списки целей

Списки сайтов, целей хостингов и резолверов встроены в b4 и датированы. **Скачать актуальные списки проекта** загружает свежие списки из репозитория dpi-detector и хранит их рядом с конфигурацией. Так умершие сайты и адреса заменяются без обновления b4. **Вернуть встроенные списки** возвращает встроенную копию.

## История

Сохраняется до пятидесяти запусков с вердиктом. Запуск можно открыть снова, скопировать как отчёт или удалить.
