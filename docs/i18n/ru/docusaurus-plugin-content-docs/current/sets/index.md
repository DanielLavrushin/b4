Сет связывает список целей - доменов, адресов, сетей - с тем, что b4 делает с их трафиком: со стратегией обхода DPI, с маршрутом через другой интерфейс или прокси либо с блокировкой. Страница **Сеты** показывает список сетов и открывает редактор сета.

Руководства, которые начинаются здесь: [Обход блокировки сайта](../guides/unblock.md), [Добавление сайтов в сет](../guides/add-sites.md), [Блокировка рекламы и сайтов](./blocking.md), [Импорт из zapret или byedpi](./import.md) и [Передача сета](./sharing.md).

![Страница «Сеты» с двумя сетами](/img/index/20260323210109.png)

## Панель инструментов

| Элемент | Что делает |
| --- | --- |
| **Включить все** / **Отключить все** | Включает или выключает все сеты разом. |
| **Поиск сетов...** | Оставляет только сеты, в названии, доменах, категориях GeoSite или ASN которых есть введённый текст. |
| **Выбрать** | Выбор нескольких сетов. **Удалить** удаляет выбранные сеты после подтверждения, **Отмена** снимает выбор. |
| **Импорт** | Создаёт сеты из командной строки byedpi или zapret, см. [Импорт из zapret или byedpi](./import.md). |
| **Создать сет** | Открывает редактор для нового сета. |

## Порядок сетов

Ручка в левом верхнем углу карточки перетаскивает сет на другое место. Когда под один и тот же трафик подходит несколько сетов, b4 выбирает самое точное совпадение, а не первый сет в списке, и отдаёт предпочтение сету, ограниченному исходными устройствами. Порядок решает только между одинаково точными совпадениями. Исключение - маршрутизация: там длина диапазона роли не играет. Первыми идут сеты, ограниченные выбранными устройствами или исходными интерфейсами, а среди сетов одного вида побеждает тот, что выше в списке.

Полный порядок проверок описан на странице [Как сеты сопоставляются с трафиком](../internals/matching.md).

## Карточка сета

Нажатие на карточку открывает сет в редакторе.

| Часть | Что показывает |
| --- | --- |
| Переключатель и номер | Переключатель включает и выключает сет. Номер - место сета в списке. |
| Название и цели | Название сета и краткая сводка его целей. |
| Строка маршрута | Что сет делает с совпавшим трафиком: **Маршрут по умолчанию** у сета, который только применяет стратегию обхода, интерфейс или прокси `socks5`, через который он ведёт трафик, **Мост Telegram** либо `block` с действием блокировки. |
| Полоса граней | Отметки вдоль верхнего края карточки: **Цели**, **Разделение**, **Фейки**, **Маршрут**, **DNS** и **Эскалация**. Отметка открывает сводку по этой части сета со ссылкой на её вкладку в редакторе. **Сравнить по сетам** над списком открывает ту же часть сразу на всех карточках. |
| Значки | **переключается на** называет [запасной сет](./escalation.md), а **запасной для** - сеты, для которых этот сет запасной. **N ASN не загружен** значит, что у [ASN](./targets.md#asn) ещё нет префиксов. **Мониторинг** виден, пока для сета включено **Поддерживать работу сета с помощью мониторинга**, и открывает страницу [мониторинга](../watchdog.md). **Импортированный общий сет** и **Сет сообщества** отмечают сет, полученный от кого-то другого. |

Меню в правом верхнем углу карточки:

| Пункт | Что делает |
| --- | --- |
| **Редактировать** | Открывает сет в редакторе. |
| **Дублировать** | Создаёт копию сета. |
| **Сравнить** | Открывает **Сравнение сетов**: этот сет и другой рядом. **Только отличия** скрывает совпадающие поля. |
| **Найти стратегию** | Открывает [Дискавери](../discovery.md) для сета. Нет у сета, который маршрутизирует трафик. |
| **Удалить** | Удаляет сет после подтверждения. |

## Редактор сета

В верхней строке - название сета. **Сохранить**, а для нового сета **Создать сет**, сохраняет его, как и круглая кнопка в правом нижнем углу. **Назад** и **Отмена** возвращают к списку без сохранения.

![Редактор сета на вкладке «Цели»](/img/index/20260323210150.png)

| Вкладка | Что на ней |
| --- | --- |
| [Цели](./targets.md) | К какому трафику применяется сет: домены, категории GeoSite, адреса, категории GeoIP, ASN и исходные устройства. |
| [TCP](./tcp/index.md) | Стратегия обхода DPI для TCP на подвкладках **Основные**, **Разделение** и **Фейкинг**. |
| [UDP](./udp.md) | С каким трафиком QUIC и другим UDP совпадает сет и что b4 с ним делает. |
| [DNS & Маршрутизация](./routing.md) | Перенаправление DNS, маршрутизация через интерфейс или прокси, блокировка и собственное значение DSCP сета. |
| [Эскалация](./escalation.md) | Запасной сет для сайтов, с которыми этот сет раз за разом не справляется. |
| [Дискавери](./discovery.md) | Адреса, которые Дискавери проверяет для сета, последний поиск для него и переключатель мониторинга. |
| [Импорт/Экспорт](#импорт-и-экспорт) | Сет в виде JSON и общий сет для других людей. |

## Импорт/Экспорт {#импорт-и-экспорт}

Вкладка показывает сет в виде JSON в поле **JSON конфигурации сета**. **Копировать JSON** копирует его. JSON, вставленный в поле и загруженный кнопкой **Импорт**, заменяет содержимое редактора и вступает в силу после **Сохранить**.

JSON нужен, чтобы переносить сет между своими роутерами. В него не попадает то, что имеет смысл только на этом роутере:

- исходные устройства, а вместе с ними и собственное [значение DSCP](./routing.md#dscp) сета;
- настройки [Эскалации](./escalation.md), которые ссылаются на другие сеты;
- переключатель мониторинга. [Адреса Дискавери](./discovery.md) переносятся, а переключатель мониторинга у сета, в который импортируется JSON, остаётся прежним.

Это настраивается заново на другом роутере. Сет может использовать файл payload, которого на этом роутере нет. Тогда после импорта предупреждение называет файл, и фейковые пакеты используют встроенный payload, пока файл не загрузят в **Настройки > Пэйлоады**.

Сет для другого человека - это [общий сет](./sharing.md), в котором нет ничего привязанного к этому роутеру. Когда в **Настройки > Интеграции** включён Community Hub, его готовит эта же вкладка. Поле **Импорт** принимает обе формы.
