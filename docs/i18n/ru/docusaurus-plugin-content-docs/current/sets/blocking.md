Сет блокировки останавливает совпавший трафик, а не направляет его куда-либо. Он блокирует домены рекламы и трекеров, нежелательные сайты или адреса для каждого устройства в сети и для самого роутера, и ему не нужны ни интерфейс, ни прокси.

## Требования

- Устройства разрешают имена через роутер. Устройство со своим шифрованным DNS всё равно блокируется по имени сервера в его соединениях, см. [Если не работает](#если-не-работает).
- Для категорий GeoSite вроде `category-ads-all` - база GeoSite, загруженная в [Настройки > Geodat настройки](../settings/geodata.md).
- Для IPv6 - включённая **Поддержка IPv6** в [Настройки > Основные](../settings/core.md#protocols). Без неё блокировка работает только для IPv4, см. [IPv6](#ipv6).

## Настройка

1. Откройте **Сеты** и нажмите **Создать сет**.
2. На вкладке **Цели** добавьте то, что нужно блокировать: домены или шаблоны `regexp:`, IP-адреса и диапазоны CIDR, категории GeoSite вроде `category-ads-all` или категории GeoIP. Способы перечислены в руководстве [Добавление сайтов в сет](../guides/add-sites.md).
3. На вкладке **DNS & Маршрутизация** откройте **Маршрутизация трафика** и включите **Включить маршрутизацию**.
4. Выберите в **Режим маршрутизации** значение **Блокировка (чёрная дыра)**.
5. Выберите **Действие блокировки**, см. [Варианты блокировки](#варианты-блокировки). Для рекламы обычно выбирают **Отклонить (быстрый отказ)**.
6. Нажмите **Создать сет**. Изменения применяются без перезапуска.

## Варианты блокировки {#варианты-блокировки}

**Действие блокировки** определяет, что увидит устройство. По умолчанию - **Отклонить (быстрый отказ)**.

| Вариант | Что видит устройство |
| --- | --- |
| **Отклонить (быстрый отказ)** | Соединение сразу завершается ошибкой: TCP reset или ICMP unreachable для UDP и QUIC. Страница сразу отказывается от рекламного блока. |
| **Отбросить (молча)** | Ответа нет: соединение завершается по таймауту, а запрос заблокированного имени остаётся без ответа. |

b4 блокирует сайт тремя способами:

1. **DNS.** На запрос заблокированного домена приходит ответ, что имя не существует (NXDOMAIN), а с **Отбросить (молча)** - никакого ответа. Это действует на каждое устройство, чей DNS идёт через роутер.
2. **Имя сервера.** Устройство, у которого адрес уже есть - из шифрованного DNS или кэша, - всё равно останавливается: b4 читает имя сервера в рукопожатии TLS или QUIC и обрывает соединение.
3. **Адрес.** IP-адреса, диапазоны CIDR и категории GeoIP блокируются в файрволе.

Первые два способа работают по имени, поэтому другие сайты на тех же серверах, что и заблокированный хост, продолжают работать. Блокировка по адресу на общем CDN блокирует все сайты за этим адресом.

## Проверка результата

- На устройстве заблокированный сайт или реклама не загружаются, а остальная страница загружается.
- Пока включён сет блокировки, на главной странице видна панель [Блокировки](../dashboard.md#блокировки): **Домены** - что было заблокировано, **Устройства** - какие устройства туда обращались. Соединения, которые файрвол отбрасывает, когда адреса заблокированного сайта уже известны, там не учитываются. Строка сета на панели **Сеты** показывает, сколько DNS-запросов он заблокировал.
- На странице [Трафик](../connections.md) заблокированные пакеты отмечены меткой `block`, а ответы, которые подменил сет, - DNS-меткой `sinkhole`.

Страницы для проверки блокировки рекламы показывают результат в браузере. Если собственный блокировщик рекламы браузера на время проверки выключен, они показывают, что перехватывает сет блокировки:

- [superadblocktest.com](https://superadblocktest.com/)
- [adblock.turtlecute.org](https://adblock.turtlecute.org/)
- [getblockify.com](https://getblockify.com/adblock-test)
- [obfusgated.com](https://obfusgated.com/tools/ad-block-test)
- [paileactivist.github.io](https://paileactivist.github.io/toolz/adblock.html)
- [adblocktester.pages.dev](https://adblocktester.pages.dev/)

Сет блокировки останавливает DNS-запросы и соединения, но не меняет страницы, поэтому пункты теста, которые проверяют скрытие элементов страницы, проходят только с расширением браузера.

## Если не работает

**Устройство всё равно открывает заблокированный сайт.** Возможно, у устройства свой шифрованный DNS (защищённый DNS в браузере, частный DNS в Android) или адрес из кэша. b4 всё равно останавливает его по имени сервера, но не по IPv6, пока поддержка IPv6 выключена, см. [IPv6](#ipv6). Помогает выключить шифрованный DNS на устройстве или включить поддержку IPv6 в b4. По QUIC блокировка действует на всё соединение, только пока строка **Блокировка QUIC действует на всё соединение** в разделе **Возможности ядра** окна [Информация о системе](../settings/system.md#system-info) показывает **доступно**. Если там **недоступно**, строка называет, чего не хватает роутеру.

**Устройство с собственным VPN не блокируется.** Трафик внутри туннеля, которого роутер не видит, b4 недоступен.

**Категория GeoSite ничего не блокирует.** База GeoSite не загружена или в ней нет этой категории.

**Блокируется слишком много.** Шаблон `regexp:` может захватить гораздо больше, чем задумано, как и адрес на общем CDN. Цель по домену делает блокировку точечной.

### IPv6

Правила блокировки пишутся только для тех семейств адресов, которые обрабатывает b4. **Поддержка IPv6** по умолчанию выключена, и тогда сет блокировки не пишет IPv6-правил:

- DNS по-прежнему скрывает имя от устройств, которые разрешают имена через роутер, и для A, и для AAAA. Запрос, который приходит на роутер по самому IPv6, проходит без изменений.
- Имя сервера в IPv6-соединениях не проверяется.
- Адресные цели блокируются только для IPv4.

Поэтому устройство, у которого уже есть IPv6-адрес заблокированного хоста, открывает его по IPv6. Когда **Поддержка IPv6** включена в [Настройки > Основные](../settings/core.md#protocols) и сервис перезапущен, блокировка охватывает оба семейства. Это не то же самое, что выключить IPv6 для сети: это делается настройками роутера вне b4.
