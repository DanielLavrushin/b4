b4 читает командную строку byedpi или zapret либо целый файл конфигурации и превращает их в сеты. b4 - самостоятельная реализация, у неё нет общего с этими инструментами ни кода, ни формата конфигурации, ни названий опций, поэтому импорт - это перевод: что-то ложится точно, что-то приближённо, а для чего-то соответствия нет вовсе. Отчёт показывает, что стало с каждой опцией.

Это не вкладка **Импорт/Экспорт** редактора сета, которая переносит сет b4 между установками b4, см. [Сеты](./index.md#импорт-и-экспорт).

## Требования

- Командная строка или файл конфигурации byedpi (`ciadpi` 0.13 или 0.15-0.17) или zapret (`nfqws`). Любой другой инструмент отклоняется с сообщением, которое его называет. zapret2 тоже отклоняется: стратегии он хранит в Lua-скриптах, а не в опциях.
- Домены, с которыми работает исходный инструмент. Список хостов - это файл на другой машине, прочитать его импорт не может.

## Настройка

1. Откройте **Сеты** и нажмите **Импорт**.
2. Вставьте исходный текст в поле **Командная строка**. Подходят:
   - список опций, например `-Ku -a1 -An -s1+s`, с именем программы или без него;
   - строки `ExecStart=` и `Environment=` юнита systemd;
   - переменная вида `NFQWS_OPT="..."`;
   - файл конфигурации целиком и без правок, например `/opt/zapret/config`, `/opt/etc/nfqws/nfqws.conf` или `.bat`, который запускает `winws` в Windows.
3. Оставьте в **Исходный инструмент** и **Версия** значение **Определить автоматически**. Если отчёт пишет **Версия определена предположительно** и результат выглядит неверным, выберите версию вручную: между 0.13 и 0.15 byedpi поменял значение нескольких опций.
4. Нажмите **Разобрать**. На этом шаге ничего не сохраняется.
5. Прочитайте отчёт, см. [Отчёт](#отчёт).
6. Укажите домены, см. [Домены](#домены). **Общие домены** достаются первому сету без собственного списка хостов, а у каждого сета есть своё поле **Домены (необязательно)**.
7. Нажмите **Создать N сетов**.

:::warning Импорт забирает домены у существующих сетов
Домен работает только в одном сете. Если импортированный сет забирает домен, который уже указан во включённом сете, домен удаляется оттуда. Сообщение после импорта называет сеты, потерявшие домены. Импортированные сеты встают перед существующими.
:::

## Профили становятся сетами

byedpi и zapret делят конфигурацию на профили, и каждый профиль становится отдельным сетом в том же порядке.

- **byedpi** начинает профиль с `-A/--auto`: «попробовать это, если предыдущая попытка не удалась». Сеты связываются [Эскалацией](./escalation.md), и домены нужны только первому. Триггеры byedpi на HTTP-редирект или ошибку TLS отмечаются в отчёте как приближённые.
- **zapret** начинает профиль с `--new` - это альтернатива, которая выбирается по собственным фильтрам. Такие сеты независимы.
- Профиль byedpi только для UDP без собственных фильтров присоединяется к сету, который обрабатывает остальной трафик: один сет b4 покрывает оба протокола.

Файл конфигурации читается так же, как его читает скрипт запуска, поэтому сеты повторяют профили, которые реально работают на исходной машине. Закомментированные альтернативы, переменные другого демона вроде tpws и заполнители списков хостов вроде `<HOSTLIST>` попадают в отчёт, но не конвертируются. Альтернатива импортируется, если раскомментировать её и разобрать заново.

## Домены

Сет b4 действует только на свои [цели](./targets.md). В командной строке byedpi списка хостов обычно нет, а zapret ссылается на файл на своей машине, поэтому импорт запрашивает домены для каждого сета. Сет, оставшийся без целей, создаётся выключенным.

- **У запасного сета нет поля доменов.** До него доходят через эскалацию из предыдущего сета, а те же домены заставили бы его соперничать с этим сетом.
- **Домен обрабатывает только один сет.** Профили с общим списком хостов, которые отличаются только портом, становятся сетами, которые создаются выключенными и перечисляются в отчёте. Каждому нужны свои домены, иначе его можно удалить.
- **Файл списка хостов** (`--hostlist=...`, `-H ...`) указан рядом с полем доменов своего сета. Его содержимое копируют на другой машине и вставляют в это поле.
- **Файл фейкового payload** (`--dpi-desync-fake-tls=/opt/.../tls_clienthello.bin`) заменяется встроенным payload. Оригинал можно загрузить в [Настройки > Пэйлоады](../settings/payloads.md). Нулевой hex-шаблон становится нулевым payload b4.

## Отчёт

По каждой опции - одна строка о том, что с ней стало. Процент над отчётом учитывает перенесённые опции полностью, приближённые частично, а неприменимые не учитывает вовсе.

| Результат | Значение |
| --- | --- |
| **Перенесено** | В b4 есть то же самое. Поля b4, которые были заполнены, перечислены под пояснением. |
| **Приближённо** | Использовано ближайшее поведение b4. В строке сказано, чем оно отличается. |
| **Нет аналога** | b4 не может это выразить. |
| **Неприменимо** | Опция настраивает собственный процесс другого инструмента, например его порт или режим демона, и для b4 ничего не значит. |
| **Без эффекта** | Опция прочитана, но ничего не меняет, и в исходном инструменте тоже, или её перекрывает более поздняя копия. |
| **Не распознано** | Неизвестная опция для этого инструмента и версии. |
| **Ошибка** | Значение не удалось прочитать. |

Не переносятся:

- **Автоматический TTL** (`--dpi-desync-autottl`, подбор числа хопов в byedpi). b4 отправляет фейки с фиксированным TTL, который берётся из `--dpi-desync-ttl`, если он задан в исходной строке.
- **Изменения обычного HTTP** (`--hostcase`, `--domcase`, `--mod-http` в byedpi).
- **Списки исключений** (`--hostlist-exclude`, `--ipset-exclude`). В b4 нет списка исключений, поэтому такие записи нужно самостоятельно убрать из целей сета.
- **Диапазоны пакетов** (`--dpi-desync-start`, `--dpi-desync-cutoff`, `--round` в byedpi). В b4 есть лимит пакетов соединения на подвкладке [Основные](./tcp/general.md).
- **Фильтры портов с отрицанием** (`--filter-tcp=~80`). Фильтр портов b4 перечисляет порты, с которыми работать.
- **Настройки прокси.** byedpi - это SOCKS5-прокси, и его адрес прослушивания, буферы и лимиты соединений к b4 не относятся.

## Проверка результата

Новые сеты появляются на странице **Сеты** перед существующими. Результат - отправная точка, а не проверенная конфигурация: провайдер, маршрут и способ блокировки на исходной машине и на этой разные. Запуск [Дискавери](../discovery.md) на импортированных доменах покажет, работает ли стратегия здесь, и найдёт лучшую, если нет.

## Если не работает

**Ни у одного сета нет стратегии.** Отчёт пишет, что не распознана ни одна опция, которая делает обход. Так бывает с вариантом инструмента с другим синтаксисом опций. Такую конфигурацию стоит отправить в [трекер задач b4](https://github.com/DanielLavrushin/b4/issues).

**Сет пропускает трафик без изменений.** Отчёт предупреждает о сетах, у которых нет ни одной опции обхода. Такой сет ничего не меняет, пока стратегию не зададут на его вкладке [TCP](./tcp/index.md) или не найдёт Дискавери.

**Сайты не открываются.** Импортированная стратегия не работает в этой сети. Следующие шаги - в руководстве [Обход блокировки сайта](../guides/unblock.md).
