Подвкладка **Основные** вкладки [TCP](./index.md) содержит настройки, которые действуют при любом методе разделения и фейкинга.

![Верх подвкладки «Основные»](/img/general/20260323224155.png)

## Задержка, порты и заголовки

| Поле | Что делает | По умолчанию |
| --- | --- | --- |
| **Задержка сегмента 2** | Задержка между частями, которые отправляет b4, в миллисекундах. Если задан диапазон, каждое соединение выбирает из него случайное значение. | `0` |
| **Фильтр портов** | TCP-порты, на которых работает сет, например `443` или `80,5222,8000-9000`, причём без `443` в списке сет не работает с HTTPS. Пустое поле - все порты, которые перехватывает b4: 443 и порты, указанные в любом сете. | Пусто |
| **Удалить опции SACK** | Убирает опцию Selective Acknowledgment из TCP-заголовков. Некоторые DPI по ней восстанавливают порядок фрагментов. | Выкл. |
| **Пустая строка перед методом HTTP** | Для обычного HTTP на порт 80: перед запросом добавляется пустая строка, а User-Agent укорачивается на два символа, чтобы длина не изменилась. Инспекция, которая ждёт метод в начале запроса, перестаёт находить заголовок Host. Нужен заголовок User-Agent, подходит для серверов nginx. | Выкл. |

## Дублирование пакетов

Для провайдеров, которые замедляют трафик, отбрасывая часть исходящих пакетов на определённые диапазоны адресов, например на подсети Telegram. b4 отбрасывает исходный пакет и вместо него отправляет несколько копий.

![Раздел «Дублирование пакетов»](/img/general/20260323224129.png)

| Поле | Что делает | По умолчанию |
| --- | --- | --- |
| **Включить дублирование пакетов** | Отправляет каждый пакет TCP-соединений сета несколькими копиями. К дублируемым пакетам остальные техники обхода сета не применяются. | Выкл. |
| **Количество копий** | Сколько копий отправлять, от 1 до 10. | `3` |

На странице [Трафик](../../connections.md) дублированные пакеты отмечены меткой `dup`.

## Обнаружение блокировки по IP

Некоторые адреса серверов блокируются на уровне IP: до сервера ничего не доходит, и никакая стратегия обхода не помогает. CDN часто отдаёт в DNS несколько адресов, из которых заблокированы лишь некоторые, и сайт работает или зависает в зависимости от того, какой адрес выбрало устройство. Обнаружение находит такие адреса, а страница [Трафик](../../connections.md) отмечает их соединения меткой `ip`. Остальные поля появляются, когда обнаружение включено.

| Поле | Что делает | По умолчанию |
| --- | --- | --- |
| **Включить обнаружение блокировки по IP** | Обнаруживает адреса, которые не отвечают, и реагирует на них. | Выкл. |
| **Исправлять DNS-ответы** | Дополнительно убирает недоступные адреса из DNS-ответов. Если недоступны все адреса, отдаётся последний, который для этого домена работал. | Выкл. |
| **Обнаруживать SYN без ответа** | Ловит блокировки по адресу, при которых соединение вообще не открывается. | Вкл. |
| **Порог SYN** | Сколько попыток соединения без ответа нужно, чтобы роутер сам проверил адрес. Ничего не происходит, пока не провалится и эта проверка. | `3` |
| **Порог повторных передач** | Сколько безответных повторов ClientHello нужно, чтобы признать адрес заблокированным. Это случай блокировки, которая пропускает соединение, а потом поглощает рукопожатие. Низкий порог может принять медленный сервер за блокировку. | `3` |
| **Таймаут обнаружения** | Признаёт адрес заблокированным и тогда, когда на первую попытку столько миллисекунд нет ответа. | `3000` |
| **TTL исправленного ответа** | TTL в исправленных DNS-ответах, в секундах. С коротким значением устройства быстро подхватывают восстановившийся адрес. | `60` |
| **Кэшировать заблокированные IP** | Запоминает заблокированные адреса, чтобы новые соединения к ним сразу сбрасывались, без ожидания. Адрес, заблокированный для любого имени сайта, [банится](#banned-addresses). | Вкл. |

Сколько адрес остаётся отмеченным, задаёт **Интервал перепроверки (секунды)** в [Настройки > Основные](../../settings/core.md#ip-block-detection).

### Забаненные адреса {#banned-addresses}

Некоторые провайдеры блокируют адрес для любого имени сайта: соединение открывается, но ни один сайт на этом адресе не отвечает. Когда сет с включённым **Кэшировать заблокированные IP** ловит адрес, b4 проверяет, отвечает ли адрес на другие имена сайтов. Адрес, который не отвечает ни на одно из них, банится. Адрес, который на них отвечает, не банится, и другие сайты на нём продолжают работать.

Пока адрес забанен:

- Новые соединения с ним сразу сбрасываются во всех сетах, где включены обнаружение блокировки по IP и **Кэшировать заблокированные IP**. Устройство может перейти к следующему адресу сайта, если он есть.
- Из DNS-ответов для доменов всех сетов он убирается. Если забанены все адреса ответа, b4 отдаёт адрес, который раньше работал для этого домена, если такой известен.
- Страница [Трафик](../../connections.md) отмечает сброшенные соединения меткой `бан`.

По умолчанию бан длится 24 часа. Адрес, забаненный снова в течение 30 дней после окончания прошлого бана, банится на 7 дней. С интервалом из поля **Интервал перепроверки (секунды)** b4 заново проверяет забаненный адрес и снимает бан досрочно после трёх успешных проверок подряд. Баны сохраняются после перезапуска и изменения сетов.

Панель [Забаненные адреса](../../dashboard.md#banned-addresses) на дашборде показывает список банов, а **Разбанить** сразу снимает бан. Переключатель и сроки банов находятся на карточке **Обнаружение блокировки по IP** в [Настройки > Основные](../../settings/core.md#ip-block-detection).

Если первым срабатывает условие [эскалации](../escalation.md) сета, хост переносится в запасной сет, а его адрес не банится.

## Защита от RST-инъекций

| Поле | Что делает | По умолчанию |
| --- | --- | --- |
| **Включить защиту от RST-инъекций** | Отбрасывает сбросы соединения, которые похожи на вставленные DPI, а не отправленные сервером. | Выкл. |
| **Допуск TTL** | Наибольшая допустимая разница между TTL сброса и TTL ответов сервера. | `3` |

Проверки описаны на странице [Защита от RST-инъекций](./rst-protection.md).

## MSS Clamping

Ограничивает максимальный размер TCP-сегмента (MSS) для соединений сета. С меньшим MSS клиент отправляет ClientHello несколькими сегментами, а собрать их обратно умеет не всякий DPI.

![Раздел MSS Clamping](/img/general/ru/20260815225810.png)

| Поле | Что делает | По умолчанию |
| --- | --- | --- |
| **Включить MSS для сета** | Включает ограничение для сета. Доступно, когда в сете есть цель по IP, GeoIP, ASN или исходному устройству. | Выкл. |
| **Размер MSS (байт)** | MSS, от 10 до 1460. При включении переключателя подставляется `88`. | `88` |

MSS выставляется в первом пакете соединения, раньше, чем становится известно имя сервера. Поэтому где действует ограничение, решают только цели по IP, GeoIP, ASN и исходным устройствам. Домены, категории GeoSite и фильтр версии TLS здесь не участвуют.

| Цели сета | К чему применяется ограничение |
| --- | --- |
| IP-адреса, категории GeoIP или ASN | К соединениям на эти адреса |
| Только исходные устройства | К каждому соединению на порт 443 с этих устройств, куда бы оно ни шло |
| И то и другое | К соединениям с этих устройств на эти адреса |

Сет, у которого цели по IP, GeoIP и ASN пока не дают ни одного адреса, не устанавливает ограничение, пока они не разрешатся. Устройству, добавленному вручную, нужен фиксированный адрес, чтобы им можно было сузить ограничение.

`88` - значение, которое интерфейс предлагает для смарт-ТВ на YouTube. В каждом сегменте тогда не больше 88 байт, поэтому большие загрузки идут медленно, и если соединение работает, но еле ползёт, следующий шаг - значение побольше. Чтобы замедлить HTTPS одного устройства без сета, то же самое делает [MSS у устройства](../../settings/core.md#device-table). MSS сета имеет приоритет над [MSS устройства и глобальным](../../settings/core.md#global-mss-clamping) для тех соединений, которые он покрывает.
