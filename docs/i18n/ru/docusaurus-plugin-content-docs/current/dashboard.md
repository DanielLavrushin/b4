Дашборд - первая страница веб-интерфейса, в меню она называется **Главная**. Он показывает, работает ли b4, совпадают ли сеты с трафиком и что требует внимания.

![Дашборд](/img/dashboard/ru/20261003220000.png)

Данные обновляются каждую секунду. Некоторые панели появляются, только когда им есть что показать: например, **Блокировки** видны, пока включён сет блокировки.

## Строка состояния

Строка вверху страницы показывает состояние сервиса.

![Строка состояния](/img/dashboard/ru/20261003220010.png)

| Поле | Что показывает |
| --- | --- |
| **Состояние** | **Работает** - штатный режим. **Сбой движка** - b4 запущен, но не обрабатывает трафик, см. [ниже](#движок-пакетов-не-запущен). |
| **Движок** | Как b4 получает трафик, `NFQUEUE` или `TUN`, и число рабочих потоков. |
| **Файрвол** | С каким файрволом работает b4, `iptables` или `nftables`. **восстановлены N раз** - что-то на роутере удалило правила b4, и b4 их вернул. Некоторые прошивки делают так постоянно, это не ошибка. **Настраивается вне b4** - включено **Пропустить настройку IPTables/NFTables**, и b4 не ставит своих правил. |
| **Время работы**, **Память b4**, **CPU** | Сколько b4 работает и сколько ресурсов занимает. При наведении курсора на поле видны пиковые значения. |

Если обновления прервались, под строкой появляется сообщение, а панели тускнеют. Страница переподключается сама, кнопка **Повторить** переподключает сразу. После сообщения **Сессия истекла - войдите снова** кнопка **Войти** открывает страницу входа.

### Движок пакетов не запущен

Если движок пакетов не запустился, веб-интерфейс работает, но трафик идёт через роутер без изменений: ни один сет не применяется. Под строкой состояния появляется карточка с ошибкой. b4 сам повторяет запуск до трёх раз, карточка показывает время следующей попытки.

![Карточка движка пакетов](/img/dashboard/ru/20260928134207.png)

- **Переключить на TUN** или **Переключить на NFQUEUE** - попробовать другой режим, например TUN, если в ядре нет модулей для NFQUEUE.
- **Перезапустить b4** - запустить заново, когда причина устранена, например загружен недостающий модуль ядра.
- **Настройки движка** - открыть **Настройки > Основные > Движок пакетов**.

## Требует внимания

Список появляется, только когда что-то требует действий, ошибки идут первыми. Ссылка в строке ведёт туда, где проблема решается.

![Требует внимания](/img/dashboard/ru/20261003220020.png)

| Сообщение | Значение и действие |
| --- | --- |
| **Сет X: прокси ... недоступен** | Прокси [прокси-сета](sets/routing.md#вышестоящий-прокси-socks5) не отвечает: прокси-сервер не работает или его адрес на вкладке **DNS & Маршрутизация** сета указан неверно. |
| **Мост Telegram: ...** | [Telegram через WebSocket](telegram/websocket-bridge.md) не может работать. Причина указана в сообщении, а в разделе [Проблемы с Telegram](telegram/troubleshooting.md#предупреждения-на-карточке-telegram-через-websocket) разобран каждый случай. |
| **Проверки мониторинга не проходят для сета X** | Часть страниц сета перестала открываться. [Мониторинг](watchdog.md) продолжает проверки и начнёт поиск новой стратегии, если сбои не прекратятся. |
| **Мониторинг ищет рабочую стратегию для сета X** | Поиск для сета ждёт очереди или уже идёт. Действий не требуется. |
| **Мониторинг не может проверить сет X** | Ни одну страницу сета нельзя проверить, например потому что их обрабатывает другой сет. Причина указана во второй строке. |
| **Мониторинг прекратил поиск для сета X, его сайты могут не открываться** | Три попытки подряд найти новую стратегию не удались, и мониторинг перестал искать для этого сета. Поиск возобновляется после **Проверить сейчас** на странице **Мониторинг** или когда проверка находит все страницы рабочими, например после ручного запуска [Дискавери](discovery.md) для сета. |
| **Мониторинг выключен, хотя его запрашивают N сетов** | Нужно либо включить мониторинг в **Настройки > Дискавери**, либо выключить **Поддерживать работу сета с помощью мониторинга** в этих сетах. |
| **За последние N в b4 не пришло ни одного пакета** | Если устройствами пользуются, их трафик не доходит до b4, и ни один сет не применяется. Ссылка открывает настройки движка пакетов. Причины и решения перечислены в разделе [Пакеты не доходят до b4](troubleshooting/traffic.md#no-packets). |
| **SOCKS5-сервер не запустился**, **MTProto-сервер не запустился**, **Ошибка веб-сервера** | Эта часть b4 не запустилась. Во второй строке - ошибка, например порт уже занят другой программой. |
| **TLS веб-сервера не работает, вместо него используется обычный HTTP** | Сертификат или ключ из **Настройки > Система > Веб-сервер** не подходит, поэтому веб-интерфейс работает по обычному HTTP. Ошибка указана во второй строке. |
| **Часть целей сетов не загрузилась** | Часть целей сетов не загрузилась. Ошибка указана во второй строке, ссылка открывает **Сеты**. |
| **b4 обновлён на диске, перезапустите сервис** | **Перезапустить** запускает новую версию. |
| **b4 пропустил обход для N пакетов**, **очередь пакетов b4 переполнялась** | b4 на короткое время не успевал за трафиком, и часть соединений прошла без обхода. |
| **Таблица соединений роутера заполнена на N%** | Роутер близок к пределу открытых соединений, новые соединения могут не устанавливаться. Это предел самого роутера, а не настройка b4. |
| **b4 держит N потоков ОС** | b4 использует намного больше потоков, чем обычно, и может остановиться. Перезапуск сбрасывает это состояние. Для [отчёта об ошибке](https://github.com/DanielLavrushin/b4/issues) пригодится `goroutines.txt` из папки логов, если включена запись логов в файл. |
| **Трафик IPv6 обходит все сеты** | У роутера есть IPv6, а b4 обрабатывает только IPv4, поэтому соединения по IPv6 идут мимо сетов. Переключатель **Поддержка IPv6** в **Настройки > Основные > Движок пакетов** подключает IPv6 к сетам. В режиме TUN сообщение звучит как **Режим TUN не обрабатывает IPv6, поэтому трафик IPv6 идёт мимо b4**: этот режим IPv6 не обрабатывает. |

Сбой запуска и сообщение об IPv6 скрываются крестиком.

## Активность

График показывает, сколько соединений b4 проверил за каждую минуту: **в ваших сетах**, если соединение совпало с сетом, и **вне сетов**, если нет.

![Активность](/img/dashboard/ru/20261003220030.png)

- **1 ч** и **24 ч** переключают период, **Таблица** показывает те же числа строками.
- **Живой трафик** открывает страницу [Трафик](connections.md).
- **Домены вне сетов** открывает страницу «Трафик» только с соединениями, которые не совпали ни с одним сетом: это сайты, которых ещё нет в сетах.

История хранится в памяти и начинается заново после перезапуска b4.

### Что учитывается в числе соединений

Каждое TCP-соединение или UDP-поток считается один раз, в момент начала. b4 видит только первые пакеты соединения, поэтому дашборд не показывает, сколько длилось соединение и сколько данных прошло.

Учитываются только соединения на порты, которые отслеживает b4: 443 и порты, добавленные в сетах. Считаются соединения и с устройств, и с самого роутера, а также соединения через прокси-сеты. DNS-запросы, тестовые соединения Дискавери и устройства, исключённые [фильтрацией устройств](settings/core.md#device-filtering), не учитываются.

## Сеты

По строке на каждый включённый сет.

![Сеты](/img/dashboard/ru/20261003220040.png)

В строке - тип сета (**Обход**, **Маршрут**, **Прокси** или **Блокировка**), сколько соединений совпало с ним за последний час и когда было последнее совпадение. У прокси-сетов также видны открытые соединения и пометка **прокси недоступен**, пока их прокси не отвечает. У сетов блокировки - сколько DNS-запросов они заблокировали. Название сета открывает его.

Если у сета нет совпадений, хотя его сайтами пользуются, страница [Трафик](connections.md) показывает, какой сет получают их соединения и получают ли вообще.

У сетов под [мониторингом](watchdog.md) показан его статус: **Работает**, **Сбой**, **Подбор стратегии**, **Поиск прекращён**, **Нельзя проверить**, **Ещё не проверен** или **Мониторинг выкл.** Нажатие на статус открывает вкладку **Дискавери** сета.

## Последние изменения

Что происходило с момента запуска b4, новые события сверху: запуски, применённые настройки, восстановленные правила файрвола, стратегии, которые переключил мониторинг, настройки, которые ИИ-ассистент изменил через [MCP](settings/mcp.md), и ошибки. У большинства записей есть ссылка на нужную страницу. Список хранится в памяти и начинается заново после перезапуска b4.

![Последние изменения](/img/dashboard/ru/20261003220050.png)

## Популярные домены и адреса

**Популярные домены** - имена, к которым устройства подключаются чаще всего. **Популярные адреса** - соединения без имени: приложения Telegram, звонки, игры, VPN-серверы.

![Популярные домены](/img/dashboard/ru/20261009120010.png)

![Популярные адреса](/img/dashboard/ru/20261009120040.png)

Значки показывают сеты, с которыми совпали соединения. **+** отмечает имя или адрес, с которым не совпал ни один сет, и добавляет в сет домен или адрес, его сеть или ASN. Оба списка считаются с последнего [сброса счётчиков](#сброс-счётчиков).

## Активные эскалации

Панель видна, пока какой-то хост перенесён в запасной сет, потому что его собственный сет раз за разом не срабатывал, см. [Эскалация](sets/escalation.md). В строке - хост, сет, в который он перенесён, и когда он вернётся. **Очистить** возвращает все хосты сразу.

![Активные эскалации](/img/dashboard/ru/20261003220100.png)

## Блокировки

Панель видна, пока включён [сет блокировки](sets/blocking.md). **Домены** - что было заблокировано, **Устройства** - какие устройства туда обращались. Нажатие на устройство открывает его трафик.

![Блокировки](/img/dashboard/ru/20261009120020.png)

## Telegram

Панель видна, пока включён [MTProto-прокси](telegram/mtproto-proxy.md) или [Telegram через WebSocket](telegram/websocket-bridge.md). Для прокси - подключённые сети, открытые соединения и трафик по каждому секрету. Для моста - пересланные сессии и сбои, а также пометка **не работает**, если мост не может работать. Шестерёнка открывает **Настройки > Telegram**.

![Telegram](/img/dashboard/ru/20261009120030.png)

## Настройка главной страницы

**Настроить** в меню в правом конце строки состояния переводит панели в режим редактирования:

1. Перетащите панель за ручку, чтобы переместить её, или на другую панель, чтобы поставить их рядом.
2. Перетащите границу между панелями, чтобы изменить ширину.
3. Нажмите на глаз, чтобы скрыть панель. Скрытые панели перечислены в панели редактирования, нажатие возвращает панель на место.
4. Нажмите **Готово**.

**Сбросить раскладку** возвращает исходный вид. Раскладка хранится в b4, поэтому в любом браузере она одинаковая.

![Настройка главной страницы](/img/dashboard/ru/20261009120050.png)

## Сброс счётчиков

**Сбросить счётчики** в меню в правом конце строки состояния начинает отсчёт заново.

![Сброс счётчиков](/img/dashboard/ru/20261003220130.png)

Сбрасываются **Популярные домены**, **Популярные адреса**, счётчики **Блокировок**, число сбросов, отброшенных защитой от RST, и счётчик эскалаций. Сохраняются история **Активности**, **Последние изменения**, время работы, данные Telegram и хосты, которые сейчас в эскалации. Их возвращает кнопка **Очистить** на панели [Активные эскалации](#активные-эскалации).
