description: Сет, который отправляет фейки перед пакетами, открывающими голосовой звонок Discord, для сетей, где звонки не соединяются, а остальной Discord открывается.
---

Настройка добавляет сет, который отправляет фейки перед пакетами, открывающими голосовой звонок Discord. Она нужна, когда звонки не соединяются или обрываются через несколько секунд, а остальной Discord работает.

Адрес голосового сервера заранее не известен. Поэтому у сета нет целей, и он выбирает пакеты по порту и по протоколу, см. [Выбор пакетов по протоколу](../sets/udp.md#protocol-selection).

## Требования

- b4 установлен и запущен.
- Сет, который уже открывает сам Discord: приложение и текстовый чат. Домены Discord добавляются в сет по руководству [Добавление сайтов в сет](./add-sites.md), а нужные этому сету порты перечислены в разделе [TCP-порты сета Discord](#tcp-ports).

## Настройка

1. Откройте **Сеты** и нажмите **Создать сет**.
2. Введите название сета, например `Discord voice`.
3. Оставьте вкладку **Цели** пустой.
4. На вкладке **UDP** введите `19294-19344,50000-50100` в поле **Фильтр портов**.
5. В поле **Протоколы** выберите **Начало голоса Discord** и **STUN**.
6. Оставьте **Режим действия** в значении **Fake & Fragment**. В поле **Payload фейкового пакета** теперь выбрано **(авто: STUN-запрос)**.
7. На вкладке **TCP** оставьте пустым поле **Фильтр портов** в разделе **Основные**.
8. Нажмите **Создать сет**.

| Порты | Голосовые серверы |
| --- | --- |
| `19294-19344` | Голосовые серверы Discord в Cloudflare |
| `50000-50100` | Остальные голосовые серверы, например в Финляндии |

**Начало голоса Discord** выбирает пакет, который открывает голосовое соединение в приложении Discord. **STUN** выбирает запрос, который открывает звонок в браузере, в том числе Discord в браузере. **Количество фейковых пакетов** и **Размер фейкового пакета** остаются по умолчанию.

### Импорт сета {#import}

JSON ниже создаёт такой же сет без шагов выше. Настройки, которых в нём нет, остаются по умолчанию.

```json
{
  "name": "Discord voice",
  "udp": {
    "dport_filter": "19294-19344,50000-50100",
    "filter_l7": ["discord", "stun"],
    "fake_payload_file": "@stun"
  }
}
```

1. Откройте **Сеты** и нажмите **Создать сет**.
2. Перейдите на вкладку **Импорт/Экспорт**, вставьте JSON в поле **JSON конфигурации сета** и нажмите **Импорт**.
3. Нажмите **Создать сет**.

Такой сет может найтись и в [Хабе сообщества](../community/browsing.md). Строка zapret для голоса Discord без собственного списка хостов или ipset, например `--filter-udp=19294-19344,50000-50100 --filter-l7=discord,stun --dpi-desync=fake`, при [импорте](../sets/import.md#домены) превращается в такой же сет.

### TCP-порты сета Discord {#tcp-ports}

Приложение Discord, текстовый чат и сигнальное соединение звонка работают по TCP. Они относятся к сету с доменами Discord: категорией GeoSite `discord` или доменами вроде `discord.com`, `discord.gg` и `discord.media`. b4 перехватывает TCP-порт 443 и порты, указанные в любом сете. Поэтому остальные TCP-порты Discord должны быть в списке этого сета.

1. Откройте сет с доменами Discord.
2. На вкладке **TCP** введите `443,2053,2083,2087,2096,8443` в поле **Фильтр портов** в разделе **Основные**.
3. Нажмите **Сохранить**.

Список ограничивает сет этими портами, а `443` сохраняет за сетом HTTPS.

## Проверка результата

1. Подключитесь к голосовому каналу в Discord.
2. Откройте страницу [Трафик](../connections.md).
3. Включите **Все пакеты**. У голосовых пакетов нет домена, и без этого режима их не видно.
4. Переключитесь на **Сырой поток** в правом верхнем углу.

У пакета, который открывает голосовое соединение, и у STUN-запросов в столбце **Сет** указано название голосового сета, а порт назначения у них из двух диапазонов. У следующих голосовых пакетов сета нет или указан другой сет, который совпал с их адресом. [Метка](../connections.md#метки) `voice` рядом с ними означает, что в этом сете включено **Фильтровать STUN-пакеты** и он пропустил их без изменений.

## Если не работает

**b4 отказывается сохранить голосовой сет.** Предупреждение на вкладке **UDP** называет причину: у сета есть цели, его **Фильтр портов** пуст или на вкладке **TCP** указаны порты. Сет сохраняется без целей, с обоими диапазонами в UDP-поле **Фильтр портов** и с пустым TCP-полем **Фильтр портов**.

**Ни у одного пакета на голосовые порты нет голосового сета.** Голосовой сет не выбрал ни пакет, который открывает звонок, ни STUN-запросы. Их порта нет в его поле **Фильтр портов**, такой вид пакетов не выбран в поле **Протоколы** или сам сет выключен на странице **Сеты**. **Фильтр версии IP** на вкладке **Цели** сета тоже может исключать одну из версий IP.

**Пакетов на голосовые порты нет совсем.** Режим **Все пакеты** выключен, или порта нет в поле **Фильтр портов** голосового сета: b4 видит UDP только на порту 443 и на портах, перечисленных в сетах. Если в [Настройки > Основные](../settings/core.md#protocols) выключена **Поддержка IPv6**, b4 вообще не видит IPv6-пакетов.

**Приложение или звонок не соединяются вообще.** Сет с доменами Discord не обрабатывает TCP-соединения Discord. В его **Фильтр портов** нужно добавить порты из раздела [TCP-порты сета Discord](#tcp-ports), а его стратегия должна открывать Discord, см. [Обход блокировки сайта](./unblock.md).
