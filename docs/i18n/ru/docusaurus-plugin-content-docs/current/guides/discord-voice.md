---
title: Голосовые звонки Discord
description: Сет, который отправляет фейки перед пакетами, открывающими голосовой звонок Discord, для сетей, где звонки не соединяются, а остальной Discord открывается.
---

Настройка добавляет сет, который отправляет фейки перед UDP-пакетами, открывающими голосовой звонок Discord. Она нужна, когда звонок отправляет голосовые пакеты, но не получает ответа или обрывается через несколько секунд, а остальной Discord работает. Если звонок висит на **RTC подключение**, причина в TCP, см. [Если не работает](#when-it-does-not-work).

Адрес голосового сервера заранее не известен. Поэтому у сета нет целей, и он обрабатывает только звонки на голосовых портах, см. [Сеты для звонков](../sets/udp.md#protocol-selection). Когда сет забрал пакет, который открывает звонок, остальные пакеты этого звонка принадлежат сету и проходят без изменений, какие бы другие сеты ни совпадали с их адресом.

## Требования

- b4 установлен и запущен.
- Сет, который уже открывает сам Discord: приложение и текстовый чат. Домены Discord добавляются в сет по руководству [Добавление сайтов в сет](./add-sites.md), а нужные этому сету порты перечислены в разделе [TCP-порты сета Discord](#tcp-ports).

## Настройка

1. Откройте **Сеты** и нажмите **Создать сет**.
2. Введите название сета, например `Discord voice`.
3. Оставьте вкладку **Цели** пустой.
4. На вкладке **UDP** в поле **Звонки** выберите **Обрабатывать только звонки**. В поле **Какие звонки** остаётся **Приложение Discord и браузеры**, а предупреждение просит указать фильтр портов.
5. Нажмите **Подставить порты Discord** в предупреждении или введите `19294-19344,50000-50100` в поле **Фильтр портов**.
6. Оставьте **Режим действия** в значении **Fake & Fragment**. В поле **Payload фейкового пакета** теперь выбрано **(авто: STUN-запрос)**.
7. На вкладке **TCP** оставьте пустым поле **Фильтр портов** в разделе **Основные**.
8. Нажмите **Создать сет**.

| Порты | Голосовые серверы |
| --- | --- |
| `19294-19344` | Голосовые серверы Discord в Cloudflare |
| `50000-50100` | Остальные голосовые серверы, например в Финляндии |

С вариантом **Приложение Discord и браузеры** сет забирает звонки и голосовые каналы в приложении Discord и звонки в браузере, в том числе Discord в браузере. **Количество фейковых пакетов** и **Размер фейкового пакета** остаются по умолчанию.

### Импорт сета {#import}

JSON ниже создаёт такой же сет без шагов выше. Настройки, которых в нём нет, остаются по умолчанию.

```json
{
  "name": "Discord voice",
  "udp": {
    "dport_filter": "19294-19344,50000-50100",
    "filter_l7": ["discord", "stun"],
    "fake_payload_file": "@stun"
  }
}
```

1. Откройте **Сеты** и нажмите **Создать сет**.
2. Перейдите на вкладку **Импорт/Экспорт**, вставьте JSON в поле **JSON конфигурации сета** и нажмите **Импорт**.
3. Нажмите **Создать сет**.

Такой сет может найтись и в [Хабе сообщества](../community/browsing.md). Строка zapret для голоса Discord без собственного списка хостов или ipset, например `--filter-udp=19294-19344,50000-50100 --filter-l7=discord,stun --dpi-desync=fake`, при [импорте](../sets/import.md#домены) превращается в такой же сет.

### TCP-порты сета Discord {#tcp-ports}

Приложение Discord, текстовый чат и сигнальное соединение звонка работают по TCP. Они относятся к сету с доменами Discord: категорией GeoSite `discord` или доменами вроде `discord.com`, `discord.gg` и `discord.media`. b4 перехватывает TCP-порт 443 и порты, указанные в любом сете. Поэтому остальные TCP-порты Discord должны быть в списке этого сета.

1. Откройте сет с доменами Discord.
2. На вкладке **TCP** введите `443,2053,2083,2087,2096,8443` в поле **Фильтр портов** в разделе **Основные**.
3. Нажмите **Сохранить**.

Список ограничивает сет этими портами, а `443` сохраняет за сетом HTTPS.

Для сигнального соединения звонка голосовой сервер выбирает один из этих портов, и стратегия сета должна работать на каждом из них. Стратегия, которая открывает `discord.com` на порту 443, может не работать на порту голосового сервера, а [Проверка голосового сервера](#voice-server-check) проверяет этот порт. [Мониторинг](../watchdog.md) проверяет новую стратегию только на адресах Дискавери сета, а адрес, заданный доменом, проверяется на порту 443. Записанная им стратегия может открывать Discord и ломать звонки, поэтому для этого сета мониторинг обычно оставляют выключенным.

## Проверка результата

1. Подключитесь к голосовому каналу в Discord.
2. Откройте страницу [Трафик](../connections.md).
3. Включите **Все пакеты**. У голосовых пакетов нет домена, и без этого режима их не видно.
4. Переключитесь на **Сырой поток** в правом верхнем углу.

У пакета, который открывает голосовое соединение, и у STUN-запросов в столбце **Сет** указано название голосового сета, а порт назначения у них из двух диапазонов. У следующих пакетов того же соединения тоже указан голосовой сет и [метка](../connections.md#метки) `voice`: сет пропустил их без изменений.

### Проверка голосового сервера {#voice-server-check}

До первого голосового пакета Discord открывает TCP-соединение с голосовым сервером. Его домен оканчивается на `discord.media`, а порт - один из портов в разделе [TCP-порты сета Discord](#tcp-ports).

1. Подключитесь к голосовому каналу в Discord.
2. На странице [Трафик](../connections.md) переключитесь на **Сырой поток** и введите `domain:discord.media` в поле фильтра.
3. Запомните домен последней строки, например `c-xxx.discord.media`, и порт в её адресе назначения.
4. На компьютере за роутером выполните команду ниже с этим доменом и портом.

```sh
curl -s -o /dev/null -w '%{http_code}/%{size_download}\n' https://c-xxx.discord.media:2087/
```

| Вывод | Значение |
| --- | --- |
| `403` и несколько тысяч байт, например `403/4548` | Ответ сервера проходит. |
| `000/0` или `403/0` | Соединение с этим портом обрывается. |

## Если не работает {#when-it-does-not-work}

Пока звонок висит, страница [Трафик](../connections.md) с включённым режимом **Все пакеты** показывает, какая сторона не работает.

| Страница Трафик показывает | Причина |
| --- | --- |
| Нет TCP-строки с доменом `discord.media` | b4 не перехватывает порт голосового сервера: его нет в поле **Фильтр портов** сета с доменами Discord. |
| Есть TCP-строка с доменом `discord.media`, но нет UDP-пакетов на голосовые порты | TCP-соединение с голосовым сервером обрывается, и Discord не отправляет ни одного голосового пакета. [Проверка голосового сервера](#voice-server-check) это подтверждает, а сету с доменами Discord нужна стратегия, которая работает на этом порту, см. [Обход блокировки сайта](./unblock.md). |
| UDP-пакеты на голосовые порты с названием голосового сета | Голосовой сервер на них не отвечает, см. причины ниже. |

В некоторых сетях ни одна стратегия не открывает порт голосового сервера, если это не 443. Проверка тогда показывает `000/0` при любой стратегии, а звонкам через такой сервер нужен [прокси](./proxy.md) или [VPN](./vpn.md) для `discord.media`.

**b4 отказывается сохранить голосовой сет.** Предупреждение на вкладке **UDP** называет причину: у сета есть цели, его **Фильтр портов** пуст или на вкладке **TCP** указаны порты. Сет сохраняется без целей, с обоими диапазонами в UDP-поле **Фильтр портов** и с пустым TCP-полем **Фильтр портов**.

**Ни у одного пакета на голосовые порты нет голосового сета.** Голосовой сет не забрал ни пакет, который открывает звонок, ни STUN-запросы. Их порта нет в его поле **Фильтр портов**, поле **Какие звонки** не включает такой вид звонков или сам сет выключен на странице **Сеты**. **Фильтр версии IP** на вкладке **Цели** сета тоже может исключать одну из версий IP.

**Пакетов на голосовые порты нет совсем.** Режим **Все пакеты** выключен, или порта нет в поле **Фильтр портов** голосового сета: b4 видит UDP только на порту 443 и на портах, перечисленных в сетах. Если в [Настройки > Основные](../settings/core.md#protocols) выключена **Поддержка IPv6**, b4 вообще не видит IPv6-пакетов.

**Звонки на одном сервере Discord не работают, а на других работают.** Голосовой канал использует регион, который Discord выбирает автоматически. Если провайдер блокирует адреса голосовых серверов этого региона, стратегия не помогает. Участник с правом управлять голосовым каналом выбирает для него другой регион в настройках канала в Discord.

**Проверка голосового сервера проходит по IPv4 и не проходит по IPv6.** Со стратегией **TTL** или с включённым **Применять TTL фейка** сет с доменами Discord отправляет фейки с одним значением **TTL фейка** для IPv4 и IPv6. По IPv6 голосовой сервер может быть на меньшем числе хопов, а фейк, который доходит до сервера, ломает соединение. Решение - меньшее значение **TTL фейка** на подвкладке [Фейкинг](../sets/tcp/faking.md#стратегия-фейка), проверенное по обеим версиям IP.

**Discord не открывается вообще.** Сет с доменами Discord не обрабатывает TCP-соединения Discord. В его **Фильтр портов** нужно добавить порты из раздела [TCP-порты сета Discord](#tcp-ports), а его стратегия должна открывать Discord, см. [Обход блокировки сайта](./unblock.md).
