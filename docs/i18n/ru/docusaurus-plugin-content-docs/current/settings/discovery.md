На вкладке **Настройки, Дискавери** две карточки. **Конфигурация тестирования** задаёт время ожидания, эталонный домен и DNS-серверы для запусков [Дискавери](../discovery.md). **Мониторинг** содержит общий переключатель, интервалы [мониторинга](../watchdog.md) и старый список доменов.

![Вкладка «Дискавери»](/img/discovery/ru/20261004000201.png)

Изменения сохраняются кнопкой **Сохранить** в заголовке страницы, см. [Сохранение и перезапуск](./index.md#saving). Перезапуск ни для одного из них не нужен. Изменение действует со следующего запуска Дискавери, а не для уже идущего. Переключатель мониторинга применяется в течение 10 секунд; уже назначенные проверка или пауза сохраняют своё время, а новые интервалы действуют для того, что назначается после них.

## Конфигурация тестирования

| Поле | Действие | Диапазон | По умолчанию |
| --- | --- | --- | --- |
| **Таймаут поиска** | Предел времени на один запрос сайта через один из его адресов, от соединения до конца чтения. Если запрос переходит к другому адресу сайта, отсчёт для него начинается заново. На этом же значении основаны пределы запросов и проверок соединения на этапе DNS. | 3-30 сек | `5` сек |
| **Задержка распространения конфигурации** | Пауза между переключением очереди захвата запуска на новую конфигурацию и первым запросом через неё. Запуск делает такую паузу после загрузки каждого пресета, перед запросами подтверждения и перед проверкой фрагментированного DNS-запроса. Столько же ждёт мониторинг после того, как восстановление записало стратегию в отслеживаемый сет, прежде чем проверять адреса сета. | 500-5000 мс | `1500` мс |
| **Эталонный домен** | Домен, который запрашивается один раз в начале каждого запуска, см. ниже. Пустое значение означает `yandex.ru`. | - | `yandex.ru` |

Сколько запросов подряд должен пройти пресет, на этой вкладке не задаётся. Это выбирается для каждого запуска параметром **Подтверждать каждую стратегию** в разделе [Параметры](../discovery.md#параметры).

В начале каждого запуска Дискавери запрашивает `https://<эталонный домен>/`, читает не больше 100 КБ и записывает скорость в журнал запуска строкой `Network baseline`. Дискавери это значение не использует: вердикты и порядок рабочих стратегий определяются запросами к самим сайтам. Неудачный запрос к эталонному домену записывается в журнал, и запуск продолжается.

:::info Скорость в Дискавери
Каждая скорость в результатах Дискавери, как и базовая скорость в его журнале, получена одним запросом не больше 100 КБ, а время считается от начала запроса, вместе с соединением и TLS-рукопожатием. Эти цифры сравнивают стратегии на одном сайте и не измеряют пропускную способность соединения.
:::

### Настройки DNS

Список запасных DNS-серверов содержит обычные DNS-серверы, к которым этап DNS запуска обращается, когда встроенные DoH-серверы b4 не отвечают. Запуски с выключенным параметром **Проверять подмену DNS** пропускают этап DNS и список не используют; так идёт каждое восстановление, которое начинает мониторинг. Сервер добавляется полем **Добавить запасной DNS сервер** и удаляется крестиком на своём чипе. Запись - IP-адрес, запросы к нему идут на порт 53.

Этап DNS использует список так:

- **Эталонные адреса.** Адреса, которые должны быть у сайта, сначала запрашиваются через встроенные DoH-серверы b4. Если ни один из них не вернул адрес, серверы из списка вместе со встроенными UDP-серверами b4 опрашиваются обычными запросами наперегонки, и используется первый ответ с адресами.
- **Последнее средство для эталона.** Если и это ничего не дало, серверы из списка опрашиваются по одному, и эталонный адрес даёт первый сервер, ответ которого проходит TLS-рукопожатие с именем сайта.
- **Исправление DNS.** Если ответ системного резолвера для сайта оказался ложным, перенаправлением для сета сначала пробуются встроенные DoH-серверы b4. Если ни один из них не ответил, серверы из списка проверяются по очереди, сначала обычным запросом, затем фрагментированным. Первый, вернувший адрес, который обслуживает сайт, становится [перенаправлением DNS](../dns.md#типы-резолверов) в сете, который предлагает Дискавери, а **Фрагментировать DNS-запросы** включается, если сработал только фрагментированный запрос.

По умолчанию в списке `9.9.9.9`, `1.1.1.1`, `8.8.8.8`, `9.9.1.1` и `8.8.4.4`.

:::tip Когда менять список
Список нужен, только когда встроенные DoH-серверы b4 недоступны. Если провайдер к тому же перехватывает обычный DNS к публичным резолверам, серверы из списка могут вернуть подделанные ответы, и в списке нужны серверы, которые честно отвечают из этой сети. Выключенный для запуска параметр **Проверять подмену DNS** пропускает этап DNS целиком.
:::

## Мониторинг

Карточка **Мониторинг** содержит общий переключатель **Включить мониторинг**, по умолчанию выключенный. Он включает и выключает весь мониторинг, и для отслеживаемых сетов, и для старого списка доменов, а интервалы ниже действуют для обоих. Если выключить переключатель во время поиска восстановления, поиск отменяется и ничего не записывается. Сет, который ждал своей очереди на восстановление, возвращается в статус **В очереди** и снова проверяется после повторного включения.

Остальные поля видны, только пока переключатель включён:

| Поле | Действие | Диапазон | По умолчанию |
| --- | --- | --- | --- |
| **Интервал проверки** | Как часто проверяется каждый отслеживаемый сет или домен, пока всё работает | 60-1800 сек | `300` сек |
| **Интервал после ошибки** | Как часто сет или домен проверяется снова после неудачной проверки | 10-300 сек | `60` сек |
| **Перерыв между discovery** | Пауза после попытки восстановления перед следующей проверкой этого сета или домена | 60-3600 сек | `900` сек |
| **Таймаут проверки** | Предел времени на один запрос проверки, в том числе при проверке после восстановления | 3-30 сек | `15` сек |
| **Макс. попыток** | Сколько неудачных проверок подряд ставят восстановление в очередь | 1-10 | `3` |

Проверки, восстановление и статусы описаны на странице [Мониторинг](../watchdog.md). Ещё два значения мониторинга есть только в файле конфигурации, см. [Параметры](../watchdog.md#параметры).

### Старый список доменов

**Старый список доменов** содержит домены, которые проверяются по одному, и каждый восстанавливается через тот сет, в котором он указан в этот момент; см. [Старый список доменов](../watchdog.md#старый-список-доменов). Домен добавляется полем **Добавить домен** и удаляется крестиком на своём чипе. Запись - домен, который проверяется как `https://<домен>/`, или полный URL, который проверяется как есть. Тот же список редактируется в разделе **Старый список доменов** на странице мониторинга.

:::info Мониторинг сета
Сет ставится на мониторинг на его собственной [вкладке Дискавери](../sets/discovery.md#мониторинг) переключателем **Поддерживать работу сета с помощью мониторинга**. Тогда его адреса Дискавери проверяются вместе, а восстановление записывает только в этот сет. Чтобы проверялся хоть один сет, **Включить мониторинг** всё равно должен быть включён.
:::
