На вкладке **Настройки, Дискавери** две карточки. **Конфигурация тестирования** задаёт время ожидания и доверенный DNS-сервер для запусков [Дискавери](../discovery.md). **Мониторинг** содержит общий переключатель, интервалы [мониторинга](../watchdog.md) и старый список доменов.

![Вкладка «Дискавери»](/img/discovery/ru/20261004190000.png)

Изменения сохраняются кнопкой **Сохранить** в заголовке страницы, см. [Сохранение и перезапуск](./index.md#saving). Перезапуск ни для одного из них не нужен. Изменение действует со следующего запуска Дискавери, а не для уже идущего. Переключатель мониторинга применяется в течение 10 секунд; уже назначенные проверка или пауза сохраняют своё время, а новые интервалы действуют для того, что назначается после них.

## Конфигурация тестирования

| Поле | Действие | Диапазон | По умолчанию |
| --- | --- | --- | --- |
| **Таймаут поиска** | Предел времени на один запрос сайта через один из его адресов, от соединения до конца чтения. Если запрос переходит к другому адресу сайта, отсчёт для него начинается заново. На этом же значении основаны пределы запросов и проверок соединения на этапе DNS. | 3-30 сек | `5` сек |
| **Задержка распространения конфигурации** | Пауза между переключением очереди захвата запуска на новую конфигурацию и первым запросом через неё. Запуск делает такую паузу после загрузки каждого пресета и перед запросами подтверждения. Столько же ждёт мониторинг после того, как восстановление записало стратегию в отслеживаемый сет, прежде чем проверять адреса сета. | 500-5000 мс | `1500` мс |

Сколько запросов подряд должен пройти пресет, на этой вкладке не задаётся. Это выбирается для каждого запуска параметром **Подтверждать каждую стратегию** в разделе [Параметры](../discovery.md#параметры).

:::info Скорость в Дискавери
Каждая скорость в результатах Дискавери получена одним запросом не больше 100 КБ, а время считается от начала запроса, вместе с соединением и TLS-рукопожатием. Эти цифры сравнивают стратегии на одном сайте и не измеряют пропускную способность соединения.
:::

### Доверенный DNS-сервер

**Доверенный DNS-сервер** находится в разделе **Настройки DNS** карточки. При включённом **Проверять подмену DNS** Дискавери сравнивает адрес каждого сайта от резолвера роутера с адресом от резолвера, которому доверяет, и так определяет, выдаёт ли DNS неверный адрес. **Доверенный DNS-сервер** задаёт этот резолвер. Если поле пустое, Дискавери опрашивает публичные резолверы, встроенные в b4: сначала DNS поверх HTTPS, затем обычный DNS. Запуски с выключенным параметром **Проверять подмену DNS** пропускают этап DNS и сервер не опрашивают; так идёт каждое восстановление, которое начинает мониторинг.

| Форма | Транспорт |
| --- | --- |
| `9.9.9.9`, `2620:fe::fe`, `127.0.0.1:53053`, `udp://9.9.9.9` | Обычный DNS по UDP, с повтором по TCP, если ответ обрезан |
| `tcp://9.9.9.9` | Обычный DNS только по TCP |
| `tcp+udp://127.0.0.1:53053` | Сначала UDP, по TCP - если UDP не сработал |
| `https://dns.google/dns-query` | DNS поверх HTTPS; если в URL нет пути, добавляется `/dns-query` |

По умолчанию используется порт 53. Обычному DNS нужен IP-адрес: имя хоста работает только в URL `https://`. DNS поверх TLS и другие транспорты напрямую не поддерживаются; их покрывает локальный DNS-прокси, который их умеет, если указать здесь его адрес.

Указанный здесь сервер - единственный эталон. Его ответы считаются верными адресами сайтов, его NXDOMAIN - признаком несуществующего имени, а публичные резолверы рядом с ним не опрашиваются. Перед началом запуска сервер один раз опрашивается об одном из имён, которые проверяет запуск; если ответ не приходит или сервер отказывает в запросе, запуск останавливается с ошибкой. Ответ с ошибкой об этом имени, например SERVFAIL, запуск не останавливает, а запуск, все имена которого закреплены, сервер не опрашивает. Если сервер перестаёт отвечать позже, сайт, о котором его спрашивали, остаётся без сравнения DNS.

Если резолвер роутера выдаёт сайту неверный адрес, предложенный сет получает исправление DNS - первое сработавшее из:

1. самого доверенного сервера, если сет может им пользоваться: публичный IP-адрес на порту 53, ответивший по UDP и не принадлежащий этому хосту, или URL `https://`;
2. встроенного сервера DNS поверх HTTPS, который возвращает верный адрес сайта;
3. встроенного обычного DNS-сервера, который возвращает его же, при обычном запросе, а затем при фрагментированном;
4. [закрепления](../dns#закреплённые-адреса) в сете адресов, полученных от DNS поверх HTTPS или доверенного сервера, если ни один резолвер, доступный сету, их не возвращает; ответ встроенных обычных DNS-серверов не закрепляется никогда, потому что его можно подделать по пути.

Доверенный сервер, которым сет пользоваться не может, например локальный прокси на другом порту, резолвер в локальной сети или сервер `tcp://`, всё равно определяет, какие адреса верные, а журнал запуска объясняет, почему он не попал в сет. Резолвер в локальной сети не подходит потому, что DNS-перенаправление сета пропускает собственные запросы такого резолвера к вышестоящему серверу без изменений, только если они приходят ровно с того адреса, который указан в сете (см. [Типы резолверов](../dns#типы-резолверов)), а его запросы с любого другого адреса возвращает ему же. URL `https://` попадает в сет как есть, где бы ни работал его сервер.

То же поле есть в [параметрах запуска Дискавери](../discovery#параметры), где оно действует только на этот запуск.

## Мониторинг

Карточка **Мониторинг** содержит общий переключатель **Включить мониторинг**, по умолчанию выключенный. Он включает и выключает весь мониторинг, и для отслеживаемых сетов, и для старого списка доменов, а интервалы ниже действуют для обоих. Если выключить переключатель во время поиска восстановления, поиск отменяется и ничего не записывается. Сет, который ждал своей очереди на восстановление, возвращается в статус **В очереди** и снова проверяется после повторного включения.

Остальные поля видны, только пока переключатель включён:

| Поле | Действие | Диапазон | По умолчанию |
| --- | --- | --- | --- |
| **Интервал проверки** | Как часто проверяется каждый отслеживаемый сет или домен, пока всё работает | 60-1800 сек | `300` сек |
| **Интервал после ошибки** | Как часто сет или домен проверяется снова после неудачной проверки | 10-300 сек | `60` сек |
| **Перерыв между discovery** | Пауза после попытки восстановления перед следующей проверкой этого сета или домена | 60-3600 сек | `900` сек |
| **Таймаут проверки** | Предел времени на один запрос проверки, в том числе при проверке после восстановления | 3-30 сек | `15` сек |
| **Макс. попыток** | Сколько неудачных проверок подряд ставят восстановление в очередь | 1-10 | `3` |

Проверки, восстановление и статусы описаны на странице [Мониторинг](../watchdog.md). Ещё два значения мониторинга есть только в файле конфигурации, см. [Параметры](../watchdog.md#параметры).

### Старый список доменов

**Старый список доменов** содержит домены, которые проверяются по одному, и каждый восстанавливается через тот сет, в котором он указан в этот момент; см. [Старый список доменов](../watchdog.md#старый-список-доменов). Домен добавляется полем **Добавить домен** и удаляется крестиком на своём чипе. Запись - домен, который проверяется как `https://<домен>/`, или полный URL, который проверяется как есть. Тот же список редактируется в разделе **Старый список доменов** на странице мониторинга.

:::info Мониторинг сета
Сет ставится на мониторинг на его собственной [вкладке Дискавери](../sets/discovery.md#мониторинг) переключателем **Поддерживать работу сета с помощью мониторинга**. Тогда его адреса Дискавери проверяются вместе, а восстановление записывает только в этот сет. Чтобы проверялся хоть один сет, **Включить мониторинг** всё равно должен быть включён.
:::
