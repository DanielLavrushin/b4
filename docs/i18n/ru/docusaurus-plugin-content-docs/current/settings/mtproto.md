Вкладка **Telegram** раздела **Настройки** настраивает три способа, которыми b4 переносит трафик Telegram, и то, как b4 доходит до дата-центров Telegram. Руководства по каждому способу собраны в разделе [Telegram](../telegram/index.md).

Карточки **Секреты** и **WEB-прокси Telegram Desktop** видны, пока включён MTProto-прокси.

## Telegram через WebSocket

Карточка включает [Telegram через WebSocket](../telegram/websocket-bridge.md) для всей сети, без участия сетов.

![Карточка «Telegram через WebSocket»](/img/telegram/ru/20260925200001.png)

| Поле | Что делает | По умолчанию |
| --- | --- | --- |
| **Включить Telegram через WebSocket** | Пропускает Telegram со всех устройств за b4 и с самого роутера через мост. [Фильтрация устройств](./core.md#device-filtering) действует. MTProto-прокси не нужен. | Выкл |

Пока настройки не сохранены, в заголовке стоит **Сохраните, чтобы применить**. После сохранения там **Работает** или **Не работает**, а подсказка на статусе называет, чего не хватает.

Блок **Состояние моста** показывает:

| Элемент | Что показывает |
| --- | --- |
| **Порт слушателя** | Порт моста, `13443`, и семейства адресов, на которых он слушает, либо **не запущен** |
| **Активные соединения** | Соединения через мост, открытые сейчас |
| **Диапазоны Telegram** | Сколько диапазонов адресов используется, их источник (**telegram.org**, **зеркало b4**, **сохранённая копия**, **файл GeoIP** или **встроенный список**) и когда они обновлялись |
| **Переправлено сессий** | Сколько сессий переправил мост и когда была последняя |
| Строка счётчиков | **Передано без разбора**, **ошибок подключения к дата-центру** и **закрыто без рукопожатия**; появляется, когда хотя бы один больше нуля. См. [Счётчики под состоянием моста](../telegram/troubleshooting.md#счётчики-под-состоянием-моста) |

| Кнопка | Что делает |
| --- | --- |
| **Проверить снова** | Повторяет проверку TPROXY в ядре, затем устанавливает правило файрвола моста или возвращает его выше правила другой программы |
| **Обновить адреса** | Сразу скачивает список адресов Telegram и сообщает число диапазонов или ошибку |

Каждое предупреждение над блоком разобрано в разделе [Предупреждения на карточке Telegram через WebSocket](../telegram/troubleshooting.md#предупреждения-на-карточке-telegram-через-websocket).

## MTProto Прокси {#прокси-сервер}

[MTProto-прокси](../telegram/mtproto-proxy.md), к которому Telegram подключается по секрету. Поля карточки скрыты, пока выключен её переключатель.

| Поле | Что делает | По умолчанию |
| --- | --- | --- |
| **Включить MTProto прокси** | Запускает прокси-сервер. | Выкл |
| **Адрес привязки** | Адрес, на котором слушает прокси. `0.0.0.0` - все адреса, `127.0.0.1` - только сам хост. | `0.0.0.0` |
| **Порт** | Порт, к которому подключается Telegram. | `3128` |
| **Доступ из интернета** | Добавляет правило файрвола, которое принимает соединения на порт с любого адреса, по IPv4 и IPv6. Выключенный переключатель не добавляет правил и ничего не блокирует. См. [Доступ из интернета](./security.md#expose-to-internet). | Выкл |
| **Домен для Fake SNI** | Домен, который предъявляет TLS-рукопожатие прокси, и сайт, на который передаётся соединение, не прошедшее проверку секрета. Новые секреты генерируются для него. | `storage.googleapis.com` |

### Дополнительно

| Поле | Что делает | По умолчанию |
| --- | --- | --- |
| **Макс. подключений** | Наибольшее число одновременно открытых клиентских соединений, пробы тоже считаются. Каждый клиент Telegram открывает несколько. На WEB-прокси не распространяется. | `2048` |
| **TCP User Timeout (сек)** | Закрывает клиентское соединение после стольких секунд неподтверждённых данных, поэтому ушедший из сети телефон обнаруживается примерно за две минуты. `-1` отключает. | `120` |
| **Тайм-аут простоя (сек)** | Закрывает сессию после стольких секунд без трафика в обе стороны. `-1` отключает. | `300` |

В обоих тайм-аутах `0` означает значение по умолчанию.

## Секреты

Отдельная запись для каждого человека позволяет выдавать и отзывать доступ по одному. Лог называет секрет, которым воспользовалось соединение.

| Поле | Что делает | По умолчанию |
| --- | --- | --- |
| Переключатель | Включает и выключает запись. Клиент с выключенным секретом отклоняется. | Вкл |
| **Имя / комментарий** | Имя записи, которое видно в логе и на странице «Трафик». | Пусто |
| **Макс. сетей** | Отказывает новым соединениям с секретом, когда он уже используется из стольких сетей одновременно. Устройства за одним подключением к интернету считаются одной сетью. `0` - без ограничения. | `0` |
| **Secret** | Сам секрет. **Сгенерировать Secret** заменяет его новым для текущего значения поля **Домен для Fake SNI**. Принимаются только fake-TLS секреты: hex, начинается с `ee`. | Сгенерирован |

**Добавить secret** добавляет запись со сгенерированным секретом. Кнопка «поделиться» (**Поделиться ссылкой**) открывает ссылку и QR-код, см. [Добавление прокси в Telegram](../telegram/mtproto-proxy.md#добавление-прокси-в-telegram). Кнопка с корзиной (**Удалить secret**) удаляет запись.

## WEB-прокси Telegram Desktop

[WEB-прокси](../telegram/web-proxy.md) отдаёт MTProto-прокси как HTTPS-сайт для Telegram Desktop 7.1.1 и новее.

| Поле | Что делает | По умолчанию |
| --- | --- | --- |
| **Включить WEB-канал** | Отдаёт прокси на хосте релея. | Выкл |
| **Хост релея** | Публичное DNS-имя только для релея, с публично доверенным сертификатом на порту 443. Без схемы, порта и пути; для международных имён - punycode. | Пусто |
| **Порт relay** | Пусто: релей работает на порту веб-интерфейса, только по хосту релея. Порт: у релея свой слушатель, где любое другое имя или IP-адрес получает страницу-заглушку. При первом включении канала заполняется значением `443`. | Пусто |
| **Доступ из интернета** | Виден, пока задан порт релея. Открывает порт релея для соединений с любого адреса. Без собственного порта релей доступен снаружи только вместе с веб-интерфейсом. | Выкл |
| **Сертификат для хоста relay** | Виден, пока задан порт релея. **Файл сертификата** и **Файл закрытого ключа** в формате PEM, только для порта релея. Пусто: сертификат веб-сервера. | Пусто |
| **Страница-заглушка** | Страница, которую видит каждый посетитель, кроме Telegram. Загруженный HTML-файл до 1 МиБ заменяет встроенную страницу, а **Удалить** возвращает её. | Встроенная |

## Транспорт к Telegram (общий) {#транспорт-к-telegram}

Как b4 доходит до дата-центров Telegram - и для MTProto-прокси, и для Telegram через WebSocket, даже при выключенном прокси. Маршруты описаны на странице [Транспорт к Telegram](../telegram/upstream.md).

| Поле | Что делает | По умолчанию |
| --- | --- | --- |
| **Режим транспорта** | Как MTProto-прокси доходит до Telegram: **Прямой TCP**, **Авто (WebSocket → TCP)** или **Только WebSocket**. Telegram через WebSocket всегда использует Авто. | **Авто (WebSocket → TCP)** |
| **DC Relay** | `host:port` VPS, который пересылает трафик к дата-центрам; поле видно в режимах **Прямой TCP** и **Авто (WebSocket → TCP)**. Кнопка **?** показывает команды `socat`. Telegram через WebSocket его не использует. См. [DC Relay](../telegram/dc-relay.md). | Пусто |
| **Домен Cloudflare Worker** | Одно или несколько имён `*.workers.dev` через запятую. См. [Релей на Cloudflare Worker](../telegram/cloudflare-worker.md). | Пусто |
| **Обрабатывать соединения с Worker сетами** | Виден, когда задан домен Worker. Разрешает сету, цели которого покрывают Worker, применять свою стратегию DPI к соединениям b4 с ним. См. [Обработка DPI](../telegram/websocket-bridge.md#обработка-dpi). | Выкл |
| **Свой WebSocket-домен** | Домен, который передаёт WebSocket-трафик к Telegram. b4 подставляет `kws1.`, `kws2.` и так далее по дата-центрам. | Пусто |
| **IP edge-сервера Telegram (расширенное)** | Заменяет адрес собственного WebSocket-узла Telegram. | `149.154.167.220` |
| **Имя для фронтинга WS-узла Telegram (расширенное)** | TLS-имя, например `sprinthost.ru`, которое пробуется на узле Telegram, когда рукопожатие под его собственными именами остаётся без ответа. См. [Имя для фронтинга WS-узла](../telegram/upstream.md#имя-для-фронтинга-ws-узла). | Пусто (выключено) |

**Проверить соединение** пробует каждый настроенный маршрут к дата-центру 2 и показывает результат каждого. Кнопка **Прямой TCP** пробует дата-центр 2 по прямому TCP, в обход DC Relay.

### Резервные источники

| Поле | Что делает | По умолчанию |
| --- | --- | --- |
| **CF-резерв** | Использует ротируемый пул доменов за Cloudflare для дата-центров, которые не обслуживает собственный узел Telegram. | Вкл |
| **URL списка CF-доменов** | Откуда раз в час обновляется пул. | Список tg-ws-proxy |
| **Резервное зеркало списка DC** | Берёт список дата-центров Telegram с зеркала ниже, когда собственный эндпоинт Telegram недоступен. | Вкл |
| **URL зеркала списка DC** | Зеркало. Зеркало по умолчанию размещено автором b4 и получает IP-адрес запрашивающего, и ничего кроме. | Зеркало автора b4 |
| **Ожидание рукопожатия в мосте (сек)** | Сколько Telegram через WebSocket ждёт первого байта от клиента, прежде чем закрыть соединение. `-1` - ждать без ограничения. | `180` |

b4 скачивает эти списки, только пока включён MTProto-прокси, Telegram через WebSocket или включённый сет в этом режиме маршрутизации.

## Сохранение изменений

Вкладка применяется кнопкой **Сохранить**, без перезапуска сервиса.

- Изменение полей **Включить MTProto прокси**, **Адрес привязки**, **Порт**, **Домен для Fake SNI**, **Режим транспорта**, **Свой WebSocket-домен**, IP edge-сервера, имени для фронтинга или настроек CF-резерва перезапускает MTProto-прокси.
- Секреты применяются без перезапуска. Выключенный или удалённый секрет теряет открытые соединения.
- Переключатель и хост WEB-прокси действуют со следующего запроса. Новый порт релея или сертификат перезапускает только слушатель релея.
