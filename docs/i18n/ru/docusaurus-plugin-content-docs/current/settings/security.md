По умолчанию веб-интерфейс открывается без пароля для любого, кто дотянется до его порта. Вход по паролю и HTTPS защищают его, а переключатели **Доступ из интернета** определяют, доступен ли он или прокси b4 из интернета.

## Требования

- Доступ к веб-интерфейсу.
- Для HTTPS - сертификат и закрытый ключ в виде PEM-файлов на роутере.

## Вход по паролю {#authentication}

1. Откройте **Настройки > Система > Веб-сервер**.
2. В разделе **Аутентификация** заполните **Имя пользователя** и **Пароль**.
3. Нажмите **Сохранить**.

После этого веб-интерфейс запрашивает логин. Вход по паролю работает, только когда заполнены оба поля. Сессия длится до перезапуска b4 или до 24 часов без использования. Новый пароль не закрывает уже открытые сессии, их закрывает перезапуск. После 5 неудачных попыток входа за 15 минут вход с этого адреса блокируется на 5 минут. Поля описаны в разделе [Веб-сервер](./system.md#web-server).

## Включение HTTPS {#https}

Без HTTPS логин, пароль и каждая сессия передаются по сети без шифрования.

1. Скопируйте сертификат и ключ на роутер, например в папку файла конфигурации.
2. Откройте **Настройки > Система > Веб-сервер**.
3. Укажите пути к ним в полях **TLS Сертификат** и **TLS Ключ**.
4. Нажмите **Сохранить**, затем **Перезапустить сервис**.
5. Откройте веб-интерфейс по тому же адресу через `https://`.

Для локальной сети достаточно самоподписанного сертификата:

```bash
openssl req -x509 -newkey rsa:2048 -keyout server.key -out server.crt -days 365 -nodes -subj "/CN=b4"
```

Ключ должен быть PEM-файлом без пароля. Сохранение отклоняется, если файла нет, у ключа есть пароль или сертификат не подходит к ключу. Пароль снимается командой `openssl pkey -in key.pem -out key-plain.pem`. b4 читает файлы при запуске, поэтому обновлённый сертификат начинает действовать после перезапуска.

## Доступ из интернета {#expose-to-internet}

У каждого слушателя из таблицы ниже рядом с портом есть переключатель **Доступ из интернета**, по умолчанию выключенный. Если он включён, b4 добавляет на своём хосте правило файрвола, которое принимает TCP-соединения на этот порт с любого адреса, по IPv4 и IPv6. b4 возвращает правило после перезагрузки файрвола роутера и удаляет его, когда переключатель выключают или b4 останавливается. Переключатели применяются при сохранении.

| Слушатель | Переключатель | Порт открывается, только если |
| --- | --- | --- |
| Веб-интерфейс | **Настройки > Система > Веб-сервер** | Заданы имя пользователя и пароль |
| MTProto-прокси | **Настройки > Telegram > MTProto Прокси** | Прокси включён |
| Порт relay WEB-прокси | **Настройки > Telegram > WEB-прокси Telegram Desktop** | Включены MTProto-прокси и его WEB-прокси, а в поле **Порт relay** указан порт |
| SOCKS5-прокси | **Настройки > Основные > SOCKS5** | Прокси включён с логином или списком **Разрешённые источники**, а у веб-интерфейса, если он работает, задан логин |

Чтобы открыть веб-интерфейс из интернета:

1. Настройте вход по паролю и HTTPS, как описано выше.
2. Включите **Доступ из интернета** в **Настройки > Система > Веб-сервер**.
3. Нажмите **Сохранить**.

Порт веб-интерфейса обслуживает также API, [MCP-сервер](./mcp.md) и, если у WEB-прокси нет своего порта relay, сам relay, поэтому переключатель открывает их все вместе. После смены порта правило переезжает на новый порт при следующем перезапуске.

Клиент SOCKS5 может подключиться к любому адресу, в том числе к портам самого роутера и к веб-интерфейсу. Поэтому для открытия прокси нужен ещё и логин веб-интерфейса. SOCKS5 передаёт свой логин без шифрования. Правило покрывает только TCP, поэтому на хосте, который отбрасывает входящие соединения, UDP через прокси снаружи не работает.

Выключенный переключатель не добавляет правил, но и порт не блокирует. На хосте, который принимает входящие соединения, например на VPS без файрвола, любой слушатель на `0.0.0.0` доступен из интернета при любом положении переключателя. Закрытым слушатель остаётся благодаря полю **Адрес привязки** с адресом LAN или `127.0.0.1` либо собственному файрволу хоста.

:::warning Без входа по паролю
Любой, кто дотянется до веб-интерфейса без пароля, получает полное управление b4. Без имени пользователя и пароля b4 не открывает веб-интерфейс в интернет, но на хосте без файрвола адрес по умолчанию `0.0.0.0` всё равно доступен из интернета.
:::

## Что переключатель открыть не может {#expose-limits}

Правило открывает порт только на хосте, где работает b4.

| Ситуация | Что нужно |
| --- | --- |
| CGNAT: WAN-адрес из `100.64.0.0/10` | Из интернета до него по IPv4 не дойти. Публичный IPv6-адрес на WAN это не затрагивает. |
| Роутер или модем перед b4: частный WAN-адрес, например `192.168.x.x` | Проброс порта ещё и на этом устройстве, если провайдер его допускает. |
| Облачный файрвол: группы безопасности AWS, сетевые группы безопасности Azure, правила файрвола Google Cloud, списки безопасности Oracle Cloud | Отдельное правило в файрволе провайдера. |
| b4 в контейнере MikroTik | Правило `dst-nat` на RouterOS, см. [MikroTik](../install/mikrotik.md#access-from-the-wan). |
| firewalld, который владеет своей таблицей nftables, как в Fedora 42, RHEL 10 и Debian 13 | Открыть порт в самом firewalld: `firewall-cmd --permanent --add-port=<порт>/tcp`, затем `firewall-cmd --reload`. Лог называет эти команды. |
| Включено **Пропустить настройку IPTables/NFTables** | Ничего: b4 не добавляет правил, а переключатели неактивны. |

Как устроены эти правила, описано в разделе [Перехват пакетов](../internals/capture.md#expose-to-internet-rules).

## Проверка результата

- В приватном окне браузера веб-интерфейс запрашивает логин.
- С HTTPS адрес открывается через `https://`.
- Каждое изменение лог записывает строкой, начинающейся с `Expose:`. В ней названы открытые порты, включённый переключатель, который ничего не открыл, и правила, возвращённые после перезагрузки файрвола.
- Для MTProto-прокси окно **Поделиться подключением MTProto** предупреждает, если порт не открыт.

## Если не работает

- **Вход отклоняется после нескольких попыток.** Адрес заблокирован на 5 минут.
- **Пароль забыт.** b4 хранит только его хеш. Если остановить b4, удалить имя пользователя и пароль веб-сервера из [файла конфигурации](../advanced/config.md#paths-system) и снова запустить b4, вход по паролю отключится.
- **Интерфейс по-прежнему открывается по HTTP.** Дашборд показывает **TLS веб-сервера не работает, вместо него используется обычный HTTP** с причиной, например перемещённым или заменённым файлом.
- **Порт не открывается снаружи.** Причину называют строки `Expose:` в логе, а внешние причины перечислены в разделе [Что переключатель открыть не может](#expose-limits).
