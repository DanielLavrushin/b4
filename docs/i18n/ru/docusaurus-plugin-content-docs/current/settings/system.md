На вкладке **Система** собраны настройки самого сервиса, на подвкладках **Сервис**, **Веб-сервер** и **Бэкап**. Некоторые поля применяются только после перезапуска, см. [Сохранение и перезапуск](./index.md#saving).

## Сервис {#service}

На подвкладке две карточки, **Сервис** и **Логирование**.

![Подвкладка «Сервис» с карточками «Сервис» и «Логирование»](/img/system/ru/20261003230500.png)

### Перезапустить сервис {#restart}

**Перезапустить сервис** после подтверждения перезапускает b4. Веб-интерфейс на несколько секунд становится недоступен и перезагружается, когда b4 снова отвечает.

Если у b4 есть менеджер сервиса, например systemd или init-скрипт, перезапуск идёт через него. Иначе, например в Docker, b4 перезапускается на месте, и контейнер не перезапускается. Какой способ используется, показывает строка **Менеджер сервиса** в окне [Информация о системе](#system-info).

### Информация о системе {#system-info}

**Информация о системе** открывает окно **Диагностика системы** с отчётом о роутере и о b4.

| Раздел | Содержимое |
| --- | --- |
| **Система** | Имя хоста, дистрибутив, ядро, архитектура, CPU и память, а если b4 работает в контейнере, ещё строка **Контейнер** |
| **B4** | Версия, сборка, **Менеджер сервиса**, идентификатор процесса, потребление памяти и время работы |
| **Процесс** | Память, потоки и открытые файлы процесса b4 |
| **Пути** | Бинарник b4, файл конфигурации, каталог данных, лог ошибок и файлы геоданных |
| **Геоданные** | Базы GeoSite и GeoIP и кэш ASN |
| **Движок** | NFQUEUE или TUN, ошибка запуска, если движок не запустился, а при TUN ещё его устройство и захват |
| **Firewall** | Бэкенд файрвола, установленные сеты маршрутизации, **Flow Offloading**, сколько раз b4 восстанавливал свои правила, и правила b4 |
| **Сеть** | Интерфейсы с состоянием и адресами |
| **Модули ядра**, **Возможности ядра** | Есть ли модули, которые использует b4, и какие пакеты дают недостающий |
| **Firewall (нужна хотя бы одна)**, **Необходимые утилиты**, **Опциональные утилиты** | Какие команды нашёл b4, с их версиями |
| **Хранилище** | Свободное место и режим записи на обычных точках монтирования |

Если **Flow Offloading** показывает, что offloading идёт в обход b4, роутер переводит соединения на быстрый путь раньше, чем b4 увидит нужные ему пакеты, и этот трафик до b4 не доходит.

**Копировать JSON** копирует весь отчёт, например для [отчёта об ошибке](https://github.com/DanielLavrushin/b4/issues). Отчёт не маскируется: в нём есть имя хоста, адреса и MAC-адреса интерфейсов, правила файрвола и адрес прокси каждого прокси-сета. Что содержит каждая часть отчёта об ошибке, перечислено в разделе [Что может быть личным](../troubleshooting/reporting.md#what-can-be-private).

### Настройки сервиса {#service-settings}

| Поле | Что делает | По умолчанию |
| --- | --- | --- |
| **Язык** | Язык веб-интерфейса, English или Русский. | English |
| **Часовой пояс** | Часовой пояс меток времени в логе. **Авто (система)** берёт часовой пояс системы. | **Авто (система)** |
| **Лимит памяти** | Мягкий лимит памяти b4: `auto` или пусто - половина памяти системы, размер вида `128MiB`, `256m` или `1g`, либо `off`. Возле лимита b4 чаще освобождает память, а превышение лимита b4 не останавливает. | `auto` |
| **Зеркала обновления** | Адреса `https` через запятую, к которым b4 обращается раньше встроенных зеркал, когда скачивание с GitHub не удаётся, см. [Скачивание b4, когда GitHub заблокирован](../advanced/update-mirrors.md). | Пусто |

**Лимит памяти** меньше 32 МиБ поднимается до 32 МиБ. Тот же минимум действует для `auto` на роутере, где памяти меньше 64 МиБ.

### Логирование {#logging}

Карточка **Логирование** задаёт подробность лога и место его хранения.

| Поле | Что делает | По умолчанию |
| --- | --- | --- |
| **Уровень логирования** | Подробность лога. **Ошибка** - ошибки и предупреждения, **Инфо** добавляет основные события, **Трассировка** - подробности обработки пакетов и DNS, **Отладка** - отладочный вывод. | **Инфо** |
| **Папка логов** | Папка для `errors.log` с ошибками и предупреждениями при запуске и `update.log` с последним обновлением, запущенным из веб-интерфейса. Пустое поле отключает запись логов в файл. | `/var/log/b4` |
| **Мгновенный сброс** | Записывает каждую строку лога сразу, а не порциями. | Вкл |
| **Syslog** | Отправляет лог ещё и в системный лог с тегом `b4`. | Выкл |

Обычный уровень - **Инфо**, для поиска проблемы - **Трассировка** или **Отладка**. На уровне **Ошибка** страница [Логи](../logs.md) показывает только ошибки и предупреждения. Страница [Трафик](../connections.md) от уровня не зависит, кроме DNS-запросов: они видны начиная с уровня **Инфо**. Флаги командной строки `--log-dir`, `--instaflush` и `--syslog` важнее этих полей, см. [Параметры командной строки](../advanced/cli.md#логирование).

## Веб-сервер {#web-server}

Подвкладка настраивает сервер веб-интерфейса, через который работают также API и [MCP-сервер](./mcp.md). Как настроить вход, HTTPS и доступ из интернета, описано в руководстве [Защита веб-интерфейса](./security.md).

![Подвкладка «Веб-сервер»](/img/system/ru/20261003230600.png)

| Поле | Что делает | По умолчанию |
| --- | --- | --- |
| **Адрес привязки** | Адрес, на котором слушает сервер. `0.0.0.0` - все адреса, IPv4 и IPv6, `127.0.0.1` - только сам роутер. | `0.0.0.0` |
| **Порт** | Порт веб-интерфейса. Порт, занятый другой программой или другим слушателем b4, отклоняется при сохранении. | `7000` |
| **Доступ из интернета** | Добавляет правило файрвола, открывающее порт для любых адресов. Нужны имя пользователя и пароль, см. [Доступ из интернета](./security.md#expose-to-internet). | Выкл |
| **TLS Сертификат** | Путь к файлу сертификата, `.crt` или `.pem`. Если оба поля TLS пустые, интерфейс работает по обычному HTTP. | Пусто |
| **TLS Ключ** | Путь к файлу закрытого ключа, `.key` или `.pem`, без пароля. Задаётся вместе с сертификатом. | Пусто |

### Аутентификация {#authentication}

| Поле | Что делает | По умолчанию |
| --- | --- | --- |
| **Имя пользователя** | Логин. Пустое поле отключает вход по паролю и удаляет сохранённый пароль. | Пусто |
| **Пароль** | Пароль, хранится только в виде хеша. Пустое поле оставляет сохранённый пароль. | Пусто |

Вход по паролю работает, только когда заполнены оба поля. Без TLS-сертификата логин и сессия передаются по сети без шифрования. В обоих случаях карточка показывает предупреждение.

## Бэкап {#backup}

Подвкладка сохраняет, восстанавливает и сбрасывает конфигурацию.

![Подвкладка «Бэкап» с четырьмя карточками](/img/system/ru/20261003230700.png)

### Скачать бэкап {#download-backup}

**Скачать бэкап** сохраняет архив `.tar.gz` с папкой конфигурации. Кроме конфигурации, в нём история [Дискавери](../discovery.md#история) и [DPI-детектора](../detector.md#история), [пэйлоады](./payloads.md) и [забаненные адреса](../sets/tcp/general.md#banned-addresses). Базы GeoSite и GeoIP, список производителей для фильтрации устройств и авторский ключ хаба сообщества в архив не попадают. Авторский ключ переносится на другой роутер кодом восстановления, см. [Интеграции](./integrations.md#community-hub).

:::warning В архиве есть секреты
Конфигурация попадает в архив как есть: с хешем пароля, токенами и секретами, а также с сохранёнными API-ключами AI. Делиться можно [безопасной копией](#safe-copy).
:::

### Восстановить из бэкапа {#restore-backup}

**Загрузить и восстановить** принимает бэкап `.tar.gz` размером до 50 МиБ и записывает его файлы в папку конфигурации. Файл из архива заменяет текущий, остальные файлы остаются. Копию заменяемой конфигурации b4 не сохраняет, поэтому перед восстановлением стоит скачать свежий бэкап.

После восстановления открывается окно **Перезапуск сервиса B4**. Восстановленная конфигурация начинает действовать после перезапуска. Сохранение до перезапуска записывает поверх неё старую конфигурацию.

### Скачать конфигурацию {#download-configuration}

**Скачать конфигурацию** сохраняет конфигурацию, с которой работает b4, одним JSON-файлом в формате [файла конфигурации](../advanced/config.md).

| Кнопка | Содержимое |
| --- | --- |
| **Скачать безопасную копию** | Конфигурация со скрытыми учётными данными, секретами и именами хостов роутера и relay владельца, чтобы отправить её, когда нужна помощь. Сеты с доменами и адресами прокси остаются как есть |
| **Скачать как есть** | Полная конфигурация с хешем пароля, всеми токенами и секретами |

#### Безопасная копия {#safe-copy}

В безопасной копии нет пароля веб-интерфейса, а `[redacted]` стоит вместо:

- имён пользователей, паролей, токенов и секретов;
- имён хостов роутера и relay владельца;
- учётных данных и путей в URL и приватных адресов DNS-over-HTTPS;
- зеркал обновления.

Сеты с целями, стратегиями и адресами прокси, устройства, интерфейсы и порты остаются как есть.

Конфигурацию, в которой в скрытом поле остался `[redacted]`, b4 не сохраняет. Файл конфигурации с такой заглушкой не загружается. b4 тогда стартует с настройками по умолчанию и берёт из файла только порт и адрес привязки веб-сервера, поэтому веб-интерфейс открывается без входа по паролю. Следующее сохранение заменяет файл.

### Сбросить конфигурацию к значениям по умолчанию {#reset}

**Сбросить** после подтверждения возвращает конфигурацию к значениям по умолчанию. Сохраняются:

- сеты;
- настройки веб-сервера вместе со входом, языком и MCP-сервером;
- настройки геоданных.

Всё остальное возвращается к значениям по умолчанию: вкладка **Основные**, остальное на вкладке **Система**, вкладки **Дискавери** и **Telegram**, IPinfo, AI-помощник, хаб сообщества и раскладка дашборда. Файлы рядом с конфигурацией, например истории, пэйлоады и сохранённые ключи AI, остаются. Поля, которым нужен перезапуск, начинают действовать после следующего перезапуска.
