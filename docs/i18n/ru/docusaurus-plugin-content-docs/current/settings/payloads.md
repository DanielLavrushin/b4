Вкладка **Пэйлоады** хранит файлы, которые фейковые пакеты могут нести вместо встроенного пэйлоада. Пэйлоад генерируется по доменному имени или загружается из файла. Генерация, загрузка и удаление выполняются на роутере сразу, без кнопки **Сохранить**.

![Вкладка «Пэйлоады»](/img/payloads/ru/20261004000203.png)

## Зачем нужен пэйлоад {#why-payloads-exist}

Некоторые стратегии отправляют перед настоящим пакетом фейковый. DPI разбирает фейк, а **Стратегия фейка** сета не даёт серверу его принять, см. [Фейкинг](../sets/tcp/faking.md). Данные, которые несёт фейк, и есть пэйлоад. TLS-пэйлоады предназначены для фейков, которые сет отправляет по TCP, QUIC-пэйлоады - для фейков по UDP.

## Типы пэйлоадов

Поле **Тип фейкового payload** сета (**TCP > Фейкинг > Фейковые SNI-пакеты**) выбирает, что несёт фейк:

| Тип | Содержимое |
| --- | --- |
| **Случайное** | 1200 случайных байт, новых для каждого соединения |
| **Пресет: Google (классический)** | Записанный TLS ClientHello для `www.google.com`. С этого типа начинает новый сет |
| **Пресет: DuckDuckGo** | Записанный TLS ClientHello для `staticcdn.duckduckgo.com` |
| **Пресет: STUN** | STUN Binding Request, без TLS |
| **Свой файл payload** | Пэйлоад с этой вкладки, выбранный в поле **Сгенерированный payload** |
| **Все нули** | 1200 нулевых байт |
| **Инвертированный оригинал** | Содержимое настоящего пакета, в котором инвертирован каждый бит |
| **Сгенерированный из домена** | ClientHello, собранный так же, как пэйлоады этой вкладки, для имени из поля **Домен** сета |

Пока у типа **Свой файл payload** не выбран пэйлоад или его файл не читается, а у типа **Сгенерированный из домена** пусто имя, фейк несёт **Пресет: Google (классический)**. Отправная точка - тип пэйлоада из результата [Дискавери](../discovery.md).

## Сгенерировать пэйлоад {#generating-a-payload}

Карточка собирает TLS ClientHello для имени из поля **Домен**. Имя, например `youtube.com`, и кнопка **Сгенерировать** или клавиша Enter добавляют пэйлоад в список.

ClientHello собирается на самом роутере. Соединение не устанавливается, имя не резолвится и не проверяется. Префикс `http://` или `https://` и путь отбрасываются, имя приводится к нижнему регистру. У каждого имени один пэйлоад на протокол: если у имени уже есть TLS-пэйлоад, сгенерированный или загруженный, вкладка оставляет его и сообщает, что он уже существует.

В каждом сгенерированном ClientHello расширение SNI стоит первым. Генератор рассчитан на особенность ТСПУ: если SNI - первое расширение, имя сверяется с белым списком, и разрешённое имя проходит по ускоренному пути. Срабатывает ли это, зависит от оборудования провайдера.

## Загрузить свой пэйлоад {#uploading-a-payload}

Карточка добавляет пэйлоад из файла `.bin`.

| Поле | Что делает |
| --- | --- |
| **Имя/Домен** | Имя, под которым пэйлоад виден в сетах и в Дискавери. С содержимым файла оно не связано. Если поле пустое, при выборе файла оно заполняется по имени файла: `tls_youtube_com.bin` даёт `youtube.com` |
| **Протокол** | **TLS (для TCP-фейков)** или **QUIC (для UDP-фейков)**. При выборе файла определяется по его первым байтам |
| **Выбрать файл...** | Открывает окно выбора файла |
| **Загрузить** | Отправляет файл. Доступна, когда выбран файл и задано имя |

Файл должен быть меньше 64 КБ и не пустым. b4 сохраняет его как есть, без проверки содержимого. Загрузка под уже существующими именем и протоколом заменяет пэйлоад без подтверждения.

[Общий сет](../sets/sharing.md) несёт файл пэйлоада, только если файл разбирается. Для TCP-фейков это TLS ClientHello с именем сервера, для UDP-фейков - QUIC Initial с читаемым ClientHello, в обоих случаях не больше 16 КБ. Пэйлоады, установленные из общего сета, появляются на этой вкладке.

## Пэйлоад в сете {#using-in-sets}

**TCP-фейки.** На вкладке **TCP** сета, подвкладка **Фейкинг**, при включённом **Включить фейковый SNI** тип **Свой файл payload** в поле **Тип фейкового payload** показывает поле **Сгенерированный payload**. В нём перечислены все пэйлоады этой вкладки с именем и размером.

**UDP-фейки.** На вкладке **UDP** сета, когда **Режим действия** - **Fake & Fragment**, поле **Payload фейкового пакета** задаёт тело фейковых пакетов:

| Вариант | Тело |
| --- | --- |
| **(заполнение нулями)** | Нули. Этот вариант использует новый сет |
| **(авто: QUIC Initial)** | Новый QUIC Initial со случайным содержимым для каждого фейка |
| **QUIC preset 1**, **QUIC preset 2** | Встроенные QUIC Initial на 1200 и 1357 байт |
| Пэйлоад с этой вкладки | В списке выглядит как `[quic] example.org (1250 bytes)`, QUIC-пэйлоады идут первыми |

Длина тела всегда равна **Размер фейкового пакета**: длинный пэйлоад обрезается, короткий дополняется нулями. Новый сет отправляет 64 байта, поэтому полный QUIC Initial уходит целиком, только когда размер увеличен до его длины. Остальные настройки фейков описаны на странице [UDP](../sets/udp.md).

## Пэйлоад в Дискавери {#using-in-discovery}

Поле **Захваченный ClientHello как содержимое фейков** в панели **Параметры** страницы [Дискавери](../discovery.md) предлагает TLS-пэйлоады этой вкладки. Дискавери пробует выбранные пэйлоады раньше встроенных, а стратегия, найденная с одним из них, использует **Свой файл payload** с этим пэйлоадом. Если со встроенными пэйлоадами запуск ничего не находит, его можно повторить с пэйлоадами, сгенерированными для нескольких имён.

## Сгенерированные пэйлоады {#management}

Список показывает все пэйлоады на роутере, сгенерированные, загруженные или установленные из общего сета, с именем, размером, протоколом и временем добавления. Кнопки здесь - иконки, ниже указаны их подсказки.

| Кнопка | Что делает |
| --- | --- |
| **Просмотр/Копирование hex** | Открывает **Hex данные пэйлоада** с содержимым в hex. **Копировать и закрыть** копирует его в буфер обмена |
| **Скачать .bin** | Сохраняет пэйлоад в файл |
| **Удалить** | Сразу удаляет пэйлоад, без подтверждения |
| **Обновить список** | Заново загружает список с роутера |
| **Очистить все** | Удаляет все пэйлоады после подтверждения |

:::warning Удаление пэйлоада, который использует сет
Удаление пэйлоада не меняет сеты, которые на него ссылаются. При следующем запуске или сохранении конфигурации b4 пишет в лог ошибку об отсутствующем файле, а эти фейки переходят на **Пресет: Google (классический)** для TCP и на нули для UDP.
:::

## Где хранятся пэйлоады {#where-payloads-are-stored}

Пэйлоады - файлы в каталоге `captures/` рядом с [конфигурационным файлом](../advanced/config.md#расположение-по-платформам), а `payloads.json` в том же каталоге их перечисляет. Вкладка показывает то, что записано в `payloads.json`, поэтому файл `.bin`, скопированный в каталог вручную, на ней не появляется. Добавить его можно загрузкой.
