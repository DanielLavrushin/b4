# Геоданные

## Что такое GeoSite и GeoIP

**GeoSite** и **GeoIP** - это базы данных в формате [V2Ray](https://github.com/v2fly/v2ray-core), которые позволяют работать с целыми категориями сайтов и IP-адресов вместо того, чтобы добавлять их по одному.

- **GeoSite** (`sitedat.dat`) - файл с доменами, сгруппированными по категориям. Например, категория `youtube` содержит все домены, связанные с YouTube (youtube.com, googlevideo.com, ytimg.com и т.д.)
- **GeoIP** (`ipdat.dat`) - файл с IP-диапазонами, сгруппированными по странам и ASN

:::info Зачем это нужно
Вместо того, чтобы вручную добавлять десятки доменов YouTube или Discord, достаточно выбрать нужную категорию в настройках сета. При обновлении базы новые домены подхватываются автоматически.
:::

## Источники

b4 поддерживает несколько предустановленных источников, а также позволяет указать свой URL.

| Источник | Что содержит | Ссылка |
| --- | --- | --- |
| **Loyalsoldier** | Глобальная база доменов и IP (Китай + мир) | [GitHub](https://github.com/Loyalsoldier/v2ray-rules-dat) |
| **RUNET Freedom** | База, оптимизированная для российских блокировок | [GitHub](https://github.com/runetfreedom/russia-v2ray-rules-dat) |
| **b4geoip** | Официальная GeoIP база b4 - IP-диапазоны по ASN (только GeoIP) | [GitHub](https://github.com/DanielLavrushin/b4geoip) |

:::tip Для российских пользователей
Рекомендуется **RUNET Freedom** для GeoSite (домены) и **b4geoip** для GeoIP (IP-диапазоны).
:::

### b4geoip

Официальная GeoIP база проекта b4. Собирается автоматически из данных [RIPE NCC](https://stat.ripe.net/) - реальные анонсированные IP-префиксы по ASN. Содержит категории для:

- **Облачные провайдеры** - AWS, Google Cloud, Azure, DigitalOcean, Hetzner, OVH, Scaleway, Oracle Cloud, Contabo, AEZA
- **CDN** - Cloudflare, Akamai, Fastly, CDN77
- **Игровые компании** - Roblox, Valve/Steam, Sony/PlayStation, Nintendo, EA, Riot Games, Ubisoft, Epic Games, Wargaming, Bungie, Take-Two, CCP
- **Платформы** - Telegram, GitHub, Apple, Adobe, Amazon, Blizzard

В отличие от баз по странам, b4geoip группирует IP именно по сервисам - это позволяет точно маршрутизировать трафик конкретных платформ.

## Настройка

<!-- screenshot: секция геоданных с выбором источника и статусом -->

1. Перейдите в **Настройки → Geodat настройки**
2. Укажите **Директорию назначения** - куда сохранять файлы (по умолчанию `/etc/b4`)
3. Выберите **Источник** из выпадающего списка или укажите URL вручную
4. Нажмите **Скачать**

Статус файла отображается рядом с названием:

- **Active** - файл найден, показывается размер и дата
- **Not Found** - путь задан, но файл отсутствует, нужно скачать
- **Disabled** - путь не задан, база не используется

Файлы можно также загрузить вручную через кнопку **Загрузить** (upload `.dat` файла).

### Смена директории назначения

Директория назначения не является сохраняемой настройкой, поэтому правка поля не активирует кнопку **Сохранить**. Значение применяется при следующем **Скачать** или **Загрузить**: файл пишется в новую директорию, а копия, ранее записанная b4 по старому пути, удаляется. Файлы с именем, которое b4 не записывал сам (любое, кроме `geosite.dat` / `geoip.dat`), не трогаются.

## Удаление базы

Кнопка **Удалить** на карточке стирает файл с диска и очищает его путь и URL источника. База остаётся отключённой до следующего скачивания или загрузки - автообновление по расписанию и при старте её не вернёт, поскольку URL источника больше нет.

Стираются только файлы, записанные самим b4, то есть `geosite.dat` или `geoip.dat` вне исключённых системных директорий. Если путь указывает на что-то другое - на базу, общую с другой программой, или на файл с произвольным именем - база всё равно отключается, но файл остаётся на диске, о чём сообщает строка статуса.

Сеты, ссылающиеся на категории удалённой базы, сохраняют свой список категорий, но до восстановления базы эти категории ничего не матчат. Диалог подтверждения называет затронутые сеты.

:::tip Освобождение места
На устройстве с малым объёмом памяти удаление базы, которая не используется ни в одном сете, освобождает сразу весь объём файла. `geoip.dat` часто не нужен, если сеты матчат только по доменам.
:::

:::warning Размер файлов
Файлы GeoSite и GeoIP занимают от нескольких МБ до более чем 70 МБ (GeoSite от RUNET Freedom). Новая копия пишется рядом с текущей и только потом её заменяет, поэтому для обновления нужно место под обе сразу. Если места не хватает, обновление завершается ошибкой, а текущий файл остаётся.
:::

## Использование в сетах

После загрузки баз категории становятся доступны в настройках сетов (вкладка **Цели**):

- **Категории GeoSite** - выбрать категории доменов для обхода
- **Категории GeoIP** - выбрать категории IP для обхода

При выборе категории рядом отображается количество доменов/IP в ней. Можно нажать на категорию, чтобы просмотреть содержимое.

## Обновление

**Скачать** заменяет базу по запросу, новые данные b4 подхватывает без перезапуска. В разделе **Автообновление** параметр **Обновлять при запуске** перекачивает оба файла при каждом старте b4, а **Расписание** (Ежедневно, Еженедельно, Ежемесячно) обновляет их в фоне. Если задан URL источника и включён веб-сервер, отсутствующий или повреждённый файл скачивается заново примерно через 45 секунд после старта независимо от этих параметров.

### Проверка перед заменой файла

Скачанный или загруженный файл пишется во временный файл в директории назначения и заменяет текущий только после проверки: он должен целиком разбираться как база GeoSite или GeoIP, а первые записи должны содержать домены (GeoSite) или диапазоны адресов (GeoIP). Страница ошибки или блокировки, пустой ответ, оборванная закачка и файл GeoIP, загруженный как GeoSite, отклоняются, текущий файл при этом остаётся на месте. Закачка, по которой 60 секунд не приходит данных или которая идёт дольше часа, прерывается. Отклонённая закачка источника с GitHub повторяется через [зеркала обновлений](../advanced/update-mirrors.md).

Инсталлятор показывает размер файла каждого источника. Если источник ещё не задан, он предлагает рекомендованный (RUNET Freedom для GeoSite, b4geoip для GeoIP), когда этот файл помещается в целевой директории рядом с текущим, а иначе самый маленький из помещающихся; при переустановке остаётся уже заданный источник. Файлы он скачивает рядом с текущими, пока b4 ещё работает, сверяет каждый с файлом `.sha256sum`, который источник публикует рядом, и переносит их на место только после остановки b4. При неудачной или отклонённой закачке остаётся текущий файл, а файл, контрольная сумма которого уже совпадает с опубликованной, заново не скачивается. `B4_GEO_MAX_TIME` задаёт лимит времени одной попытки закачки в секундах (по умолчанию 3600, `0` - без лимита).

### Повреждённые файлы

Файл всё равно может оказаться повреждённым, например оборванным при закачке прежней версией инсталлятора или при заполненном диске. Тогда b4 запускается с теми категориями, которые удаётся прочитать, и пишет в лог каждую непрочитанную категорию вместе с сетами, которые работают без неё. Такой сет матчит только свои остальные цели (домены, адреса, ASN); сет, у которого других целей нет, не матчит ничего, и фильтр портов не превращает его в сет только по портам. Если задан URL источника и включён веб-сервер, b4 скачивает повреждённый файл заново примерно через 45 секунд после старта. Если это не удаётся, следующая попытка идёт через два часа, а после каждой новой неудачи интервал удваивается, но не превышает суток.
