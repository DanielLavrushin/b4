DC Relay направляет прямые соединения MTProto-прокси с Telegram через VPS. Он нужен, когда b4 работает внутри сети с блокировками, где заблокированы и адреса Telegram, и маршруты WebSocket. На VPS работает только `socat`, пересылающий TCP: ни ключей, ни программ для Telegram там не нужно.

## Требования

- VPS за пределами блокировки, до которого доходит b4.
- Пять свободных портов на VPS, по одному на каждый основной дата-центр, открытые в его файрволе.
- **Режим транспорта** **Прямой TCP** или **Авто (WebSocket → TCP)** на карточке **Транспорт к Telegram (общий)**. Режим **Только WebSocket** не создаёт прямых соединений, и релей в нём ни на что не влияет.

Релей работает только для [MTProto-прокси](./mtproto-proxy.md). [Telegram через WebSocket](./websocket-bridge.md) его не использует.

## Настройка

1. Установите `socat` на VPS:

   ```bash
   apt install -y socat
   ```

2. В b4 откройте **Настройки > Telegram** и укажите **DC Relay** на карточке **Транспорт к Telegram (общий)**: адрес VPS с базовым портом, например `my-vps.com:7007`.
3. Нажмите кнопку **?** рядом с полем. Окно **Настройка socat для DC Relay** показывает готовую команду `socat` для каждого дата-центра.
4. Нажмите **Копировать всё** и выполните команды на VPS.
5. Откройте в файрволе VPS порты, которые окно перечисляет в последней строке.
6. Чтобы команды работали после перезагрузки, запускайте их из `/etc/rc.local` или юнита systemd.
7. Нажмите **Сохранить** в b4.

![Окно настройки socat для DC Relay](/img/telegram/ru/20260826233006.png)

Каждая команда пересылает один порт VPS, базовый порт плюс номер дата-центра минус один, на порт 443 этого дата-центра. Медиа-дата-центр 203 использует порт дата-центра 2, и отдельная команда для него не нужна. В режиме **Авто (WebSocket → TCP)** b4 сначала пробует релей, а затем маршруты WebSocket.

## IPv4 или IPv6

Переключатель **Версия адресов** в окне выбирает, по IPv4 или по IPv6 команды подключаются к Telegram. IPv6 нужен для VPS, который достаёт до Telegram по IPv6, но не по IPv4. Переключатель меняет только сторону Telegram в каждой команде:

```bash
# IPv4
socat TCP-LISTEN:7007,fork,reuseaddr TCP:149.154.175.50:443 &

# IPv6
socat TCP-LISTEN:7007,fork,reuseaddr TCP6:[2001:b28:f23d:f001::a]:443 &
```

Сторона прослушивания следует адресу в поле **DC Relay**. IPv6-адрес там записывается в квадратных скобках, `[2001:db8::1]:7007`, и тогда команды слушают тоже по IPv6.

У медиа-дата-центра 203 нет адреса IPv6, и он идёт через команду дата-центра 2. Если после перехода на IPv6 медиа перестали загружаться, эту одну команду возвращают на IPv4.

## Проверка результата

**Проверить соединение** на карточке **Транспорт к Telegram (общий)** пробует дата-центр 2 по каждому настроенному маршруту, включая релей. Кнопка **Прямой TCP** пробует его в обход релея, и это отделяет проблему релея от проблемы самого Telegram.

## Если не работает

Если соединения через релей не проходят, значит `socat` не запущен на VPS, порт закрыт в его файрволе или адрес релея указан неверно. Строка лога и проверки описаны в разделе [Не удаётся подключиться](./troubleshooting.md#не-удаётся-подключиться).
