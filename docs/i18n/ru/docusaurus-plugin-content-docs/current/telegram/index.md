b4 переносит трафик Telegram тремя способами. Они независимы и могут работать одновременно.

- **[MTProto-прокси](./mtproto-proxy.md)** - прокси-сервер на b4, к которому Telegram подключается по секрету. Его поддерживают все клиенты Telegram, и он доступен отовсюду, где открыт его порт, например с телефона в мобильной сети.
- **[Telegram через WebSocket](./websocket-bridge.md)** - один переключатель, который пропускает Telegram со всех устройств за b4 и с самого роутера. На устройствах ничего настраивать не нужно.
- **[WEB-прокси Telegram Desktop](./web-proxy.md)** - MTProto-прокси в виде обычного HTTPS-сайта, для Telegram Desktop 7.1.1 и новее.

## Как выбрать

| | MTProto-прокси | Telegram через WebSocket | WEB-прокси |
| --- | --- | --- | --- |
| Где настраивается в **Настройки > Telegram** | Карточка **MTProto Прокси** | Карточка **Telegram через WebSocket** или режим маршрутизации сета | Карточка **WEB-прокси Telegram Desktop** |
| На устройстве | Запись прокси с секретом | Ничего | Запись прокси из ссылки |
| Какие устройства | Любой клиент Telegram, в сети и за её пределами | Все устройства за b4 и сам роутер | Telegram Desktop 7.1.1 и новее |
| Нужен включённый MTProto-прокси | Да | Нет | Да |
| Нужен публичный хост | Только для устройств вне локальной сети | Нет | Да, с публично доверенным сертификатом |
| Нужен TPROXY в ядре | Нет | Да | Нет |

В домашней сети Telegram через WebSocket не требует ничего на устройствах. Телефону вне дома нужен MTProto-прокси. WEB-прокси подходит для b4 на VPS со своим хостом и сертификатом.

## Общие настройки

Все три способа доходят до Telegram через общие настройки [транспорта к Telegram](./upstream.md). Если не загружаются медиа, добавляют [Cloudflare Worker](./cloudflare-worker.md), а [DC Relay](./dc-relay.md) помогает там, где заблокированы и маршруты WebSocket.

Симптомы и способы их устранения собраны на странице [Проблемы с Telegram](./troubleshooting.md), а все поля вкладки описаны в разделе [Настройки > Telegram](../settings/mtproto.md).
