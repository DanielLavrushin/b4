# Telegram

b4 переносит трафик Telegram тремя способами. Они независимы, могут работать одновременно, и выбор зависит от того, что можно изменить на клиенте.

- **[MTProto-прокси](./mtproto-proxy.md)** - прокси-сервер, к которому клиент подключается по секрету, указанному в настройках прокси самого Telegram. Его поддерживают все клиенты Telegram, и он доступен отовсюду, где открыт его порт, поэтому это единственный вариант для телефона в мобильной сети.
- **[Telegram через WebSocket](./websocket-bridge.md)** - переключатель в разделе Настройки, Telegram. b4 направляет TCP-соединения Telegram со всех устройств за ним и с самого роутера в мост, который их ретранслирует, поэтому на устройстве ничего не настраивается. Режим маршрутизации сета направляет трафик в тот же мост только для выбранных устройств или интерфейсов.
- **[WEB-прокси Telegram Desktop](./web-proxy.md)** - тот же поток поверх обычного HTTPS на отдельном хосте. Telegram Desktop 7.1.1 и новее открывает этот хост в скрытом WebView, поэтому клиент вообще не открывает MTProto-сокет.

| | MTProto-прокси | WebSocket-мост | WEB-прокси |
| --- | --- | --- | --- |
| Где настраивается | Настройки, Telegram, **MTProto Прокси** | Настройки, Telegram, **Telegram через WebSocket**, или режим маршрутизации сета | Настройки, Telegram, **WEB-прокси Telegram Desktop** |
| На клиенте | Запись прокси с секретом | Ничего | Запись прокси из ссылки |
| Какие клиенты | Любой клиент Telegram | Все устройства за b4 и сам роутер | Telegram Desktop 7.1.1 и новее |
| Нужен включённый прокси-сервер | Да | Нет | Да |
| Нужен публичный хост | Только для клиентов вне локальной сети | Нет | Да, с публично доверенным сертификатом |
| Нужен TPROXY в ядре | Нет | Да | Нет |

Все три доходят до дата-центров Telegram через общие настройки [транспорта к Telegram](./upstream.md), которые действуют даже при выключенном прокси-сервере. Два маршрута требуют отдельной настройки и вынесены на свои страницы: [релей на Cloudflare Worker](./cloudflare-worker.md) и [DC Relay](./dc-relay.md) для сети, где заблокирован и WebSocket-транспорт.

Симптомы и строки лога, по которым они опознаются, собраны в разделе [Устранение неполадок](./troubleshooting.md).
