MTProto-прокси - это прокси-сервер Telegram на b4. Telegram подключается к нему по секрету из локальной сети или снаружи, например с телефона в мобильной сети. Его поддерживают все клиенты Telegram. Для сети соединение выглядит как HTTPS к домену из поля **Домен для Fake SNI**.

## Требования

- Для устройств вне локальной сети порт прокси доступен из интернета. Переключатель **Доступ из интернета** открывает его на хосте с b4. Роутеру или модему перед хостом нужен ещё и проброс порта, а до WAN-адреса за CGNAT по IPv4 снаружи не дойти вовсе. См. [Доступ из интернета](../settings/security.md#expose-to-internet).
- Часы хоста с b4 и устройств расходятся не больше чем на две минуты. Для этого на обоих нужен NTP.

## Настройка

1. Откройте **Настройки > Telegram**.
2. На карточке **MTProto Прокси** включите **Включить MTProto прокси**.
3. Укажите **Порт**. По умолчанию это `3128`. Часто выбирают `443`, потому что трафик и так похож на TLS.
4. Для устройств вне локальной сети включите **Доступ из интернета**.
5. Оставьте **Домен для Fake SNI** по умолчанию или укажите домен, который доступен из этой сети и несёт обычный трафик.
6. На карточке **Секреты** нажмите **Добавить secret**. Новая запись сразу получает сгенерированный секрет.
7. Укажите в поле **Имя / комментарий**, для кого этот секрет.
8. Нажмите **Сохранить**.

Отдельный секрет для каждого человека позволяет отзывать доступ по одному: у каждой записи свой переключатель и своя ссылка, а лог называет секрет, которым воспользовалось соединение. Принимаются только fake-TLS секреты: hex, начинается с `ee`. Секрет в другом формате, например скопированный из другого прокси, b4 пропускает и пишет в лог `skipping invalid secret`.

Некоторые изменения, например новый порт, перезапускают прокси при сохранении.

На VPS за пределами блокировки достаточно режима **Прямой TCP** в [транспорте к Telegram](./upstream.md). На роутере внутри блокировки режим по умолчанию **Авто (WebSocket → TCP)** доходит до Telegram без VPS, а если заблокирован и WebSocket, следующий шаг - [DC Relay](./dc-relay.md).

## Добавление прокси в Telegram

1. На карточке **Секреты** нажмите кнопку «поделиться» у нужного секрета (**Поделиться ссылкой**).
2. В верхней части окна выберите **Локальная сеть** для устройств в той же сети или **Интернет** для устройств снаружи. В режиме **Интернет** подставляется публичный адрес, который нашёл b4, а вместо него можно ввести DDNS-имя.
3. Откройте ссылку `tg://proxy` на устройстве или отсканируйте QR-код.

Вручную прокси добавляется в Telegram через **Настройки > Данные и память > Прокси > Добавить прокси > MTProto**: в поле **Сервер** - адрес b4, затем порт и секрет.

## Проверка результата

- В режиме **Интернет** окно предупреждает, если ссылка снаружи работать не должна, и называет причину.
- Проверка из той же Wi-Fi-сети ничего не говорит о доступе снаружи: многие роутеры не заворачивают соединение к своему публичному адресу обратно в локальную сеть. Телефон в мобильной сети подключается снаружи.
- Панель **Telegram** на [дашборде](../dashboard.md#telegram) показывает подключённые сети, соединения и трафик по каждому секрету.
- Страница [Трафик](../connections.md) показывает соединения прокси с именем секрета.

## Если не работает

Каждый симптом разобран на странице [Проблемы с Telegram](./troubleshooting.md): Telegram [висит на «Подключение»](./troubleshooting.md#telegram-висит-на-подключение), [клиент отклонён](./troubleshooting.md#клиент-отклонён), Telegram [выключает прокси](./troubleshooting.md#telegram-сообщает-что-прокси-настроен-неверно-и-выключает-его) или [не удаётся подключиться](./troubleshooting.md#не-удаётся-подключиться).

## Что видит нераспознанное соединение

Соединение, которое не прошло проверку секрета, например проба со стороны сети, передаётся на домен Fake SNI на порт 443, и отвечает ему настоящий сайт, а не b4. Данные, которые вообще не похожи на TLS-рукопожатие, отбрасываются.
