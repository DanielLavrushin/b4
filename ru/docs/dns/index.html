DNS для сетов

Сет может сам отвечать на DNS-запросы к доменам, на которые он нацелен: отправлять их на другой резолвер, отвечать фиксированными адресами или убирать часть ответа. Имена, на которые не нацелен ни один сет, без изменений уходят на резолвер, который выбрало устройство.

Все настройки находятся на вкладке DNS & Маршрутизация сета, в разделе Перенаправление DNS, см. DNS & Маршрутизация.

Какой DNS видит b4​

b4 видит DNS-запросы на порт 53 - от устройств сети и от самого роутера. Зашифрованный DNS, который устройство отправляет само (DoH, DoT или DoQ), проходит мимо b4, и сеты к нему не применяются. Обычно это защищённый DNS в браузере, например в Chrome или Firefox, Android Private DNS и DoH-резолвер, настроенный на самом устройстве. Сеты начинают действовать на такое устройство, когда на нём выключен зашифрованный DNS.

Зашифрованный форвардер на самом роутере не мешает: устройства по-прежнему обращаются к роутеру на порт 53. Как устроен перехват, описано в разделе Как b4 обрабатывает DNS.

Как сет обрабатывает запрос​

Имя из запроса сверяется с сетом так же, как имя сервера: домен покрывает свои поддомены, а домен, явно указанный в одном сете, важнее записи regexp: в другом. Первым отвечает сет блокировки, затем закрепления сета, затем резолвер сета, если включён переключатель Включить перенаправление DNS. Иначе запрос без изменений уходит на резолвер устройства. Перед отправкой ответа b4 может убрать из него ключи ECH и IPv6-адреса, см. полную последовательность.

Отдельный резолвер для доменов сета​

Резолвер сета помогает, когда DNS провайдера отвечает на домены сета неверными адресами.

  1. Откройте Сеты и нужный сет.
  2. На вкладке DNS & Маршрутизация в разделе Перенаправление DNS включите переключатель Включить перенаправление DNS.
  3. В поле Тип резолвера выберите Обычный DNS (UDP) и укажите IP DNS-сервера или выберите DNS-over-HTTPS и укажите URL DNS-over-HTTPS. Адрес можно ввести вручную или выбрать из списка рекомендуемых.
  4. Нажмите Сохранить.
Тип резолвераКогда подходит
Обычный DNS (UDP)Обычный DNS к сторонним серверам доходит без подмены. Фрагментировать DNS-запросы разбивает каждый запрос на IP-фрагменты - против DPI, который читает имена в DNS-запросах.
DNS-over-HTTPSПровайдер подменяет и обычный DNS к сторонним серверам, либо резолвер работает только по DoH. Запросы уходят зашифрованными.

Запросы от собственного резолвера сета уходят без изменений, поэтому резолвер в локальной сети тоже может обслуживать сет. Для резолвера на самом роутере есть ещё одно условие, см. Если не работает.

Сервису, который проверяет адрес, с которого пришло соединение, нужен другой выход в интернет, а не другой резолвер, см. Маршрутизация сайтов через VPN.

Запросы, которые b4 делает сам​

Когда b4 сам разрешает имена сета - для маршрутизации, значения DSCP или upstream прокси, - он использует резолвер сета, пока включено перенаправление DNS, а иначе резолвер роутера, см. Как b4 обрабатывает DNS.

Когда резолвер не отвечает​

Если резолвер сета не ответил, b4 отдаёт последний удачный ответ для этого имени, а если такого нет - спрашивает резолвер, к которому обращалось устройство. Сколько ждать резолвер, задаёт Таймаут запроса в разделе Настройки > Основные > DNS.

Переключатель Отдавать SERVFAIL, если резолвер недоступен отключает этот запасной путь. Устройство получает ошибку (SERVFAIL), и имена сета разрешаются только через его резолвер или не разрешаются вовсе.

предупреждение

С этим переключателем недоступный резолвер останавливает разрешение всех имён сета, даже если стратегия обхода работает. На подключении с цензурой сам DoH-сервер тоже могут заблокировать.

Закреплённые адреса​

Закрепление отвечает на имя фиксированными адресами - без правки hosts на каждом устройстве. Оно помогает, когда DNS раз за разом отдаёт адрес, который не отвечает.

Поле Домен и адреса в разделе Закреплённые адреса заполняется как файл hosts, по строке на адрес: сначала адрес, затем имена, на которые он отвечает.

157.240.0.174 www.instagram.com
157.240.205.63 scontent.cdninstagram.com scontent-a.cdninstagram.com
  • Закрепление действует на имя и его поддомены. Побеждает самая длинная подходящая запись.
  • Закрепление работает только для имени, на которое нацелен сет. Для других имён редактор предлагает Добавить в домены сета.
  • Закрепления работают и при выключенном перенаправлении и важнее резолвера сета.
  • Закрепления - это весь ответ с адресами: имя, закреплённое только за IPv4-адресами, не получает IPv6-адресов.
  • В сете без маршрутизации b4 убирает из ответа закреплённые адреса, которые не отвечают на TCP-порт 443. Проверка идёт при запуске, при сохранении и с интервалом из поля Интервал перепроверки (секунды) карточки Обнаружение блокировки по IP. Если не отвечает ни один адрес, закрепления всё равно отдаются.

Откат на IPv4​

Пока Поддержка IPv6 выключена, b4 обрабатывает только IPv4, и сайт с IPv6-адресами открывался бы по IPv6 мимо всех сетов. Поэтому b4 убирает IPv6-адреса (записи AAAA) из ответов для имён, совпавших с сетом, и устройство подключается по IPv4. Остальные имена получают полный ответ.

  • Переключатель Форсировать IPv4 для совпавших доменов находится в карточке IPv4 / IPv6 раздела Настройки > Основные > Движок пакетов. По умолчанию он включён и не используется, пока включена Поддержка IPv6.
  • Сет, у которого в поле Фильтр версии IP выбрано IPv6, сохраняет свои IPv6-ответы.
  • Адрес, который уже есть у устройства - в кеше, в hosts или из собственного зашифрованного DNS, - по-прежнему ведёт по IPv6. Этот путь закрывает Поддержка IPv6.

Удаление ключей ECH​

Сайты за некоторыми CDN публикуют в DNS ключ Encrypted ClientHello (ECH). Браузер, получивший ключ, например Chrome, отправляет ClientHello с общим именем CDN вместо имени сайта: cloudflare-ech.com для любого сайта Cloudflare. Там, где DPI отбрасывает такие ClientHello, перестают открываться сразу все эти сайты.

Убирать ключи ECH из ответов DNS в блоке Encrypted ClientHello (ECH) вынимает ключ из ответа, и браузер отправляет обычный ClientHello с именем сайта. Переключатель работает и при выключенном перенаправлении. Ключ убирается, когда:

  • запрошенное имя совпадает с сетом, например steamdb.info в списке сета;
  • публичное имя ключа - домен, совпадающий с сетом. Сет с cloudflare-ech.com убирает ключ из ответов всех сайтов Cloudflare.

Пока Поддержка IPv6 выключена, b4 в режиме NFQUEUE убирает ключ и из ответов, которые приходят по IPv6. Сет, у которого заданы Исходные устройства, такие ответы не трогает: b4 не знает, к какому устройству они идут. Исключение - устройство, добавленное вручную по IPv6-адресу.

Дискавери предлагает такой сет без изменения пакетов для сайта, который открывается без ECH, но не с ним. Ключ, уже лежащий в кеше браузера, используется, пока не истечёт.

Весь DNS через DoH​

Сет, нацеленный на все имена, отправляет DNS всей сети и самого роутера на один DoH-резолвер. Домены, явно указанные в других сетах, по-прежнему уходят на резолверы своих сетов.

  1. Откройте Сеты и нажмите Создать сет.
  2. На вкладке Импорт/Экспорт вставьте конфигурацию ниже в поле JSON конфигурации сета и нажмите Импорт.
  3. Чтобы использовать другой резолвер, замените URL DNS-over-HTTPS на вкладке DNS & Маршрутизация.
  4. Нажмите Создать сет.
{
  "b4_version": "dev",
  "name": "all DOH",
  "tcp": { "dport_filter": "53" },
  "udp": { "dport_filter": "53" },
  "fragmentation": { "strategy": "none" },
  "faking": { "sni": false },
  "targets": { "sni_domains": ["regexp:.*"] },
  "enabled": true,
  "dns": {
    "enabled": true,
    "doh_url": "https://wikimedia-dns.org/dns-query"
  }
}

Сет не меняет пакеты, а фильтры портов со значением 53 не дают ему забирать соединения TLS и QUIC. Имена роутера и имена в .lan перестают разрешаться: публичный резолвер о них не знает. Нужные имена можно закрепить. Когда резолвер недоступен, все имена уходят на запасной путь, поэтому доступность резолвера с этого подключения важнее его возможностей.

Общие настройки DNS​

В разделе Настройки > Основные > DNS находятся перехват DNS поверх TCP и таймауты для всех сетов. Без Перехватывать DNS поверх TCP устройство, повторившее запрос по TCP, доходит до своего резолвера мимо сета.

Проверка результата​

  1. Откройте Трафик.
  2. Введите в фильтр flags:dns, чтобы оставить только DNS-запросы.
  3. Откройте на устройстве сайт из сета.

У каждого запроса видны сет, с которым он совпал, и метка:

МеткаЗначение
doh <сервер>, forward <адрес>Разрешено через DoH-сервер или обычный DNS-сервер сета
pin, pin emptyОтвечено из закреплений; пустой ответ, если в них нет адреса запрошенного типа
ipv4 only, no echИз ответа убраны IPv6-адреса или ключ ECH
heal, heal + ipv4 onlyНедоступные адреса убраны или заменены функцией Исправлять DNS-ответы
sinkhole, blockСет блокировки ответил «имя не существует» или отбросил запрос
fallback-cache, fallback-upstreamРезолвер сета не ответил: отдан последний удачный ответ или ответил резолвер устройства
servfailРезолвер сета не ответил, и ответить больше было некому, либо сет настроен отдавать SERVFAIL
passthrough, bad target, from target, ipv6 offЗапрос ушёл без изменений: у сета нет резолвера, в IP DNS-сервера некорректный адрес, запрос пришёл от собственного резолвера сета или пришёл по IPv6 при выключенной поддержке IPv6
escalate <сет>Запросы к имени раз за разом не удавались, и на этот ответил резервный сет Эскалации

Лог записывает те же решения в виде dns-doh->, dns-pin и так далее. Решения по DNS видны и там, и на странице «Трафик», пока Уровень логирования - Инфо (по умолчанию) или подробнее.

Если не работает​

Что происходитПричина и решение
Запросы устройства не появляются на странице «Трафик»Устройство использует зашифрованный DNS. Если выключить защищённый DNS в браузере или Android Private DNS, запросы пойдут через роутер.
Сайт по-прежнему открывается по старому адресуУстройство пользуется уже полученным ответом, пока у него не истечёт срок.
servfail, fallback-cache или fallback-upstreamРезолвер сета недоступен с этого подключения. Следующий шаг - другой резолвер или DoH вместо обычного DNS.
Имена сета разрешаются медленно или не разрешаются, а резолвер сета работает на роутереРезолвер на роутере, а также резолвер роутера, если резолвер в сети использует его как вышестоящий, должен обращаться к своему вышестоящему резолверу по DoH или DoT: их b4 не перехватывает.
Браузер по-прежнему использует ECH, а резолвер в сети проверяет DNSSEC, например BIND или UnboundРезолвер получает исходный ответ путём, которого b4 не видит: DoT или DoH к вышестоящему резолверу, интерфейс, не вошедший в Интерфейсы захвата, или TCP, пока Перехватывать DNS поверх TCP выключено. При включённом Перехватывать DNS поверх TCP обычный DNS через интерфейс, который захватывает b4, закрывает эти пути, см. Ключи ECH.

На KeeneticOS и старых ядрах​

На KeeneticOS и на некоторых других роутерах со старым ядром b4 работает с копиями DNS-запросов и заменяет ответ резолвера ответом сета. Так ли это на конкретном роутере, показывает строка DNS-запросы копируются, а не задерживаются (NFLOG) в окне Информация о системе. Резолвер, которого спросило устройство, тогда всё равно получает каждый запрос, а резолвер за пределами роутера должен ответить, прежде чем устройство получит ответ сета. Запросы, которые правило nat уводит на другой порт или которым NAT меняет порт источника, сеты не обрабатывают, см. Копии запросов.
