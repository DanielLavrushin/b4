Конфигурационный файл

b4 хранит конфигурацию в одном JSON-файле, по умолчанию /etc/b4/b4.json. Флаг --config указывает другой путь.

Расположение по платформам​

ПлатформаПуть
Linux/etc/b4/b4.json
OpenWRT (с extroot или USB-накопителем)/opt/etc/b4/b4.json
OpenWRT (без USB-накопителя)/etc/b4/b4.json
ASUS Merlin/opt/etc/b4/b4.json
Keenetic/opt/etc/b4/b4.json
Docker/etc/b4/b4.json внутри контейнера

Без --config b4 ищет b4.json и config.json в каталогах /etc/b4 и /opt/etc/b4, а если не находит, берёт /etc/b4/b4.json. Выбранный путь пишется в лог при запуске.

Карточка Скачать конфигурацию в разделе Настройки > Система > Бэкап сохраняет конфигурацию в том виде, в каком b4 записывает этот файл. Её безопасная копия маскирует учётные данные и частные имена хостов для передачи другим, а конфигурацию, в которой остались заглушки [redacted], b4 не загружает и не сохраняет.

Хранится только то, что отличается от умолчаний​

Файл разрежённый. Настройка со встроенным значением по умолчанию в него не попадает, поэтому свежая установка даёт очень короткий файл, а раздел, в котором ничего не менялось, отсутствует. Отсутствующий ключ - не пропавшая настройка, и дописывание его с тем же значением ничего не меняет. Сохранения из веб-интерфейса, через API и через MCP записывают файл так же.

Пример показывает часть разделов и часть их ключей. В реальном файле есть только ключи, которые отличаются от умолчаний.

  • system.mtproto.secrets - список именованных секретов, у каждого есть id, name, secret и enabled. Файл, записанный до версии конфигурации 50, содержал одну строку mtproto.secret, и миграция переносит её в список записью с именем default.
  • system.socks5.allowed_sources отсутствует, пока список пуст. Это значение по умолчанию, и прокси тогда принимает соединения с любого источника. Каждая запись - IP-адрес или CIDR-диапазон. 0.0.0.0/0, ::/0 и некорректные записи отклоняются при загрузке и сохранении файла.

Раздел queue​

КлючСмыслПо умолчанию
start_numПервый номер NFQUEUE537
threadsКоличество рабочих потоков4
markМетка очереди, см. Метки пакетов32768
ipv4Обрабатывать IPv4-трафикtrue
ipv6Обрабатывать IPv6-трафикfalse

udp_conn_bytes_limitТо же для UDP8

tcp_conn_bytes_limit и udp_conn_bytes_limit действуют для всех сетов. Собственные tcp.conn_bytes_limit и udp.conn_bytes_limit сета ни на что не влияют, и поля для них в веб-интерфейсе нет.

queue.ipv6 определяет, обрабатывает ли IPv6 сам b4, а не пользуется ли им роутер. При выключенном значении, а оно по умолчанию, b4 обрабатывает только IPv4 и не пишет IPv6-правил файрвола ни для одного сета, поэтому клиент, открывший сайт по IPv6, проходит мимо сетов. b4 тогда убирает IPv6-адреса из DNS-ответов для доменов, с которыми совпадают сеты, см. DNS. Исключение - режим NFQUEUE, пока у включённого сета включено dns.strip_ech. В этом режиме b4 пишет IPv6-правила для DNS-ответов и DNS поверх TCP, но только чтобы убрать из них ключи ECH. Изменение действует в полном объёме после перезапуска. --ipv6 задаёт то же самое на один запуск.

Раздел sets​

Каждый сет - объект в массиве sets, несущий всю свою конфигурацию. Его ключи соответствуют вкладкам редактора сета:

  • targets - домены, IP, категории GeoSite и GeoIP, ASN, устройства-источники
  • tcp - общие настройки TCP, desync, window, incoming, защита от RST
  • fragmentation - метод фрагментации и его параметры
  • faking - SNI faking, SYN-фейки, мутация
  • udp - фильтр QUIC, фильтр портов, обработка звонков и режим действия для UDP
  • dns - резолвер сета, DoH URL и закреплённые адреса
  • routing - режим маршрутизации, выходной интерфейс, вышестоящий прокси или блокировка
  • dscp - собственное значение DSCP сета
  • discovery - адреса Дискавери сета и переключатель его мониторинга
  • escalate - на какой сет переключаться, когда этот перестаёт работать

Вкладка Импорт/Экспорт редактора сета показывает сет в виде JSON и принимает вставленный обратно. В экспортируемом JSON нет значений, равных умолчаниям, и настроек выключенных функций. В нём нет и идентификатора сета, устройств-источников, targets.ip_priority, переключателя мониторинга и настроек эскалации, а если у сета есть устройства-источники, то и его dscp. Сет, в который импортируется JSON, сохраняет собственное значение targets.ip_priority.

dscp сета​

КлючСмыслПо умолчанию
dscp.enabledВключить DSCP для сета: записывать собственное значение сета в пакеты к адресам сета, см. DSCPfalse
dscp.valueЗначение, которое записывается в поле DSCP, 0-63. 0 обнуляет поле0

Каждый ключ хранится, только пока отличается от умолчания: включённый переключатель со значением 0 сохраняется как "dscp": {"enabled": true}, значение при выключенном переключателе - как "dscp": {"value": 12}. Пока dscp.enabled равно true, dscp.value вне 0-63 отклоняется, а не подрезается: веб-интерфейс не даёт сохранить такое значение, а файл с ним останавливает b4 при запуске. Ни один из ключей нельзя изменить через MCP, и ни один не передаётся в общем сете.

Звонки сета: udp.filter_stun и udp.filter_l7​

Поле Звонки на вкладке UDP сета хранится в двух ключах, см. Сеты для звонков.

ЗвонкиКак хранится
Пропускать начало звонковudp.filter_stun равно true, это значение по умолчанию
Обрабатывать как остальной UDPudp.filter_stun равно false
Обрабатывать только звонкиudp.filter_l7 перечисляет звонки из поля Какие звонки: ["discord", "stun"] для Приложение Discord и браузеры, ["discord"] для Приложение Discord, ["stun"] для Браузеры

Непустой udp.filter_l7 означает Обрабатывать только звонки при любом значении udp.filter_stun, и udp.filter_stun тогда ни на что не влияет. Пустой список не хранится. Сету с этим списком нужен udp.dport_filter, у него не должно быть targets.sni_domains, targets.ip, targets.geosite_categories, targets.geoip_categories и targets.asns, а tcp.dport_filter должен быть пустым. Сет, который нарушает это правило, отклоняется: веб-интерфейс не даёт его сохранить, а файл с таким сетом останавливает b4 при запуске. escalate.to, который указывает на сет с этим списком, очищается, а b4 пишет предупреждение в журнал. Неизвестный элемент остаётся в списке, ни с каким трафиком не совпадает, а b4 пишет о нём предупреждение в журнал. (авто: STUN-запрос) - это "fake_payload_file": "@stun" в udp. udp.filter_l7 можно изменить через MCP, допустимы только элементы discord и stun, и ключ передаётся в общем сете.

Правка вручную​

version в начале файла - версия формата конфигурации. b4 читает её, чтобы понять, что нужно мигрировать, поэтому при правке остального её не меняют.

предупреждение

Значения в файле проверяются только при запуске b4, и файл, не прошедший проверку, останавливает b4 с ошибкой invalid configuration. b4 читает файл только при запуске, поэтому ручная правка вступает в силу после перезапуска. Любое сохранение до перезапуска записывает в файл работающую конфигурацию, и ручная правка теряется. Сохраняют веб-интерфейс, MCP, восстановление мониторингом, закачка геоданных и обновление префиксов ASN.

Миграции​

Когда формат меняется между выпусками, b4 мигрирует файл при запуске: новые поля приходят со значениями по умолчанию, переименованные переносятся. Прежде чем что-либо изменить, b4 кладёт рядом резервную копию с именем по версии, с которой мигрирует, например b4.json.v51.bak.

Файл, который не удаётся прочитать при запуске, например обрезанный при пропадании питания или с синтаксической ошибкой JSON, копируется рядом как b4.json.corrupt. Если там уже лежит копия с другим содержимым, имя будет b4.json.corrupt.1 и далее. Лог называет эту копию. Затем b4 запускается со значениями по умолчанию, а следующее сохранение заменяет исходный файл, так что непрочитанные настройки остаются только в копии.

Файл, у которого version выше, чем понимает запущенная сборка, загружается как есть, с предупреждением. Незнакомые этой сборке настройки отбрасываются при следующем сохранении.
