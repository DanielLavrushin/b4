Подключение ИИ-ассистента

ИИ-приложение, например Claude Desktop, LM Studio, Cursor или Jan, может читать состояние b4 по протоколу Model Context Protocol (MCP). Затем оно отвечает на вопросы о нём: какой сет совпадает с доменом, дошёл ли трафик до b4, что написано в логе. Модель работает внутри этого приложения. b4 не обращается ни к какому ИИ-провайдеру и не требует API-ключа.

Требования​

  • ИИ-приложение, которое подключается к MCP-серверам по HTTP.
  • Доступ из этого приложения к веб-интерфейсу b4. Точка доступа MCP использует адрес, порт и TLS-сертификат веб-сервера и недоступна, пока веб-сервер выключен.

Настройка​

  1. Откройте Настройки > Интеграции и включите Включить MCP-сервер на карточке MCP-сервер.
  2. Нажмите Создать рядом с полем Токен доступа.
  3. Нажмите Сохранить. Токен записывается только при сохранении.
  4. Нажмите Копировать под блоком Настройка клиента. Запись содержит точку доступа, то есть адрес, по которому открыт веб-интерфейс, с /api/mcp на конце, и заголовок Authorization с токеном.
  5. Вставьте запись в настройки MCP ИИ-приложения.

VS Code читает .vscode/mcp.json в рабочей папке или пользовательский mcp.json. Блок inputs заставляет редактор спрашивать токен, а не хранить его в файле:

{
  "inputs": [
    {
      "id": "b4-token",
      "type": "promptString",
      "description": "b4 MCP token",
      "password": true
    }
  ],
  "servers": {
    "b4-asuswrt": {
      "type": "http",
      "url": "https://192.168.1.1:7000/api/mcp",
      "headers": {
        "Authorization": "Bearer ${input:b4-token}"
      }
    }
  }
}

LM Studio использует такой же файл с ключом верхнего уровня mcpServers и без type. Записей может быть несколько, например роутер и локальный экземпляр:

{
  "mcpServers": {
    "b4-asuswrt": {
      "url": "https://192.168.1.1:7000/api/mcp",
      "headers": {
        "Authorization": "Bearer <токен>"
      }
    },
    "b4-local": {
      "url": "http://localhost:7000/api/mcp",
      "headers": {
        "Authorization": "Bearer <токен>"
      }
    }
  }
}

Приложение без аналога inputs хранит токен в файле открытым текстом, поэтому такой файл не стоит класть в репозиторий.

Токен​

Пока токен задан, точка доступа MCP принимает только его, а остальные части b4 его не принимают. Токен продолжает работать после перезапуска b4. Пересоздать заменяет его, и приложению после этого нужен новый токен.

Без токена точка доступа принимает вместо него токен входа в веб-интерфейс. Такой токен истекает после суток без использования и сбрасывается при каждом перезапуске, поэтому настроенное на него приложение вскоре теряет доступ.

Токен в недоверенной сети

Токен передаётся в заголовке каждого запроса. По обычному HTTP его может прочитать и использовать любой на пути следования, поэтому без HTTPS порт должен быть доступен только в доверенной сети. Если нет ни MCP-токена, ни имени пользователя и пароля в Настройки > Система > Веб-сервер, любой, кто доберётся до порта, может пользоваться сервером: читать статус, конфигурацию и диагностику b4, а также менять настройки и запускать проверки, когда это разрешено.

Инструменты​

По умолчанию ассистент только читает. Он может сообщить состояние и счётчики b4, показать конфигурацию и сеты и проверить, какой сет покрывает домен. Ещё он может найти категории GeoSite и GeoIP, прочитать последние соединения, лог ошибок и лог обновления и запустить диагностику. Все инструменты и разрешение, которое нужно каждому, перечислены на странице API и инструменты MCP.

Также ассистент может прочитать описание REST API b4 для задач, которых нет среди его инструментов. Пока у веб-интерфейса заданы имя пользователя и пароль, запросы к этому API требуют их. b4 велит ассистенту сначала спросить их у пользователя. С ними ассистенту доступно всё, что доступно в веб-интерфейсе, независимо от переключателей ниже.

Изменение настроек​

Два переключателя на карточке расширяют возможности ассистента. Оба по умолчанию выключены и работают независимо друг от друга.

ПереключательЧто ассистенту разрешено
Разрешить изменение настроекМенять настройки внутри сетов, настройки MTProto и SOCKS5 и настройки логирования. Создавать, перемещать, включать и удалять сеты, править их цели и отменять свои изменения
Разрешить активные проверкиЗагружать домен с роутера, чтобы проверить, открывается ли он, и запускать Дискавери для подбора рабочей стратегии. Частные и локальные адреса отклоняются

Изменение проходит те же проверки, что и сохранение в веб-интерфейсе, и применяется сразу. Оно появляется в Последние изменения на дашборде как ИИ-агент изменил настройку.

Часть настроек остаётся недоступной ассистенту при любых переключателях, потому что неверное значение может отрезать доступ к роутеру или открыть его в интернет:

  • учётные данные, настройки веб-сервера и самого MCP;
  • движок захвата и бэкенд файрвола;
  • переключатели Доступ из интернета и любое изменение, которое открыло бы порт, пока один из них включён;
  • метки пакетов, таблицы маршрутизации и значения DSCP;
  • идентификатор сета, его адреса Дискавери и переключатель его мониторинга: их меняют только действия мониторинга, по своим разрешениям;
  • каталог логов и расположение файлов геоданных.

Подробности - на странице API и инструменты MCP.

Отмена изменения​

Просьба отменить изменение, например «стало хуже, верни как было», восстанавливает конфигурацию, какой она была до последнего изменения ассистента, и сразу её применяет. Повторная просьба отступает ещё на одно изменение. История охватывает только изменения через MCP с момента запуска b4, правки в веб-интерфейсе в неё не входят.

Отмена отклоняется, если после отменяемого изменения конфигурация менялась: в веб-интерфейсе, мониторингом или другим инструментом. Изменения на карточке MCP-сервер не в счёт, и отмена оставляет её настройки как есть. Она отклоняется и тогда, когда включила бы мониторинг или вернула бы адреса, которые мониторинг проверяет, пока Разрешить активные проверки выключено. После включения и сохранения этого переключателя та же отмена проходит.

Что вырезается​

Вывод инструментов может попасть к сторонней модели, поэтому b4 убирает из него пароли, токены и секреты. Имена хостов и URL передаются как настроены, а диагностика содержит имя хоста роутера, адреса его интерфейсов и правила файрвола. Что именно убирается, перечислено на странице API и инструменты MCP.

Проверка результата​

На вопрос «Работает ли b4 и какой движок захвата активен?» ассистент отвечает с версией и движком захвата. Каждый вызов инструмента добавляет строку в лог на странице Логи с названием инструмента и адресом вызывающего.

Если не работает​

  • Приложение не подключается. MCP-сервер выключен, токен в приложении отличается от сохранённого или порт веб-сервера недоступен с этого компьютера. Страница Логи показывает каждый отклонённый запрос с причиной. Сам токен в лог не попадает.
  • Тестовый запрос получает 405. Точка доступа отвечает только на POST, поэтому GET из браузера или скрипта получает 405. Это нормально.
  • Веб-страница не может обратиться к точке доступа. Запрос со страницы в браузере принимается, только если её origin - собственный адрес b4, записанный как IP-адрес или localhost. ИИ-приложения origin не отправляют, и это их не касается. Имя хоста разрешается добавлением в список разрешённых origin в конфигурационном файле.
  • Ассистент говорит, что не может изменить настройку. Выключено Разрешить изменение настроек, или это настройка, которую MCP не меняет никогда.
  • Ассистент не видит инструмент после включения переключателя. Переключатель действует сразу после сохранения настроек, без перезапуска, но уже подключённое приложение хранит список инструментов, полученный при подключении. Повторное подключение приложения к MCP-серверу загружает текущий список.
