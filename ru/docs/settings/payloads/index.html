Payloads

Вкладка Payloads хранит файлы, которые фейковые пакеты могут нести вместо встроенного payload, и показывает встроенные payload. Payload генерируется по доменному имени или загружается из файла. Ещё payload приходят вместе с сетами: при импорте командной строки zapret или byedpi с фейковыми данными и из общего сета. Генерация, загрузка, повторная генерация и удаление выполняются на роутере сразу, без кнопки Сохранить, и сеты, которые используют payload, получают изменение тоже сразу.

Зачем нужен payload​

Некоторые стратегии отправляют перед настоящим пакетом фейковый. DPI разбирает фейк, а Стратегия фейка сета не даёт серверу его принять, см. Фейкинг. Данные, которые несёт фейк, и есть payload. TLS-payload предназначены для фейков, которые сет отправляет по TCP, QUIC-payload - для фейков по UDP.

Типы payload​

Поле Тип фейкового payload сета (TCP > Фейкинг > Фейковые SNI-пакеты) выбирает, что несёт фейк:

Пресет: VKTLS ClientHello для vk.com размером 517 байт
Пресет: STUNSTUN Binding Request, без TLS

Сгенерировать payload​

Карточка собирает TLS ClientHello, в котором имя сервера - имя из поля Домен. Имя, например youtube.com, и кнопка Сгенерировать или клавиша Enter добавляют payload в раздел Ваши payload.

ClientHello собирается на самом роутере. Соединение не устанавливается, имя не резолвится. Схема вроде https://, путь и порт отбрасываются, имя приводится к нижнему регистру. Интернациональное имя записывается в punycode: пример.рф превращается в xn--e1afmkfd.xn--p1ai. IP-адрес и текст, который не похож на имя хоста, отклоняются.

У каждого имени один TLS-payload. Если у имени он уже есть, вкладка оставляет его и сообщает, что он уже существует. Сгенерированный ClientHello помещается в один пакет. Его случайные значения выбираются при генерации и не меняются, пока его не пересоберёт Сгенерировать заново.

Загрузить свой payload​

Карточка добавляет payload из файла размером до 64 КБ. b4 проверяет выбранный файл до загрузки и показывает, что в нём найдено: тип, имя сервера и размер.

ПолеЧто делает
Выбрать файл...Открывает окно выбора файла. Выбранный файл сразу проверяется
Имя/ДоменИмя, под которым payload виден в сетах и в Дискавери, до 200 символов. Пока имя не введено вручную, при выборе файла сюда подставляется имя сервера из файла, а если его там нет - имя файла без расширения
ПротоколTLS (для TCP-фейков) или QUIC (для UDP-фейков). Определяется по файлу, если b4 его распознаёт
ЗагрузитьСохраняет payload. Доступна, когда проверка закончена и имя задано

Предупреждения проверки загрузку не останавливают. Это те же предупреждения, что на карточках payload, см. Ваши payload. Пустой файл и файл больше 64 КБ загрузить нельзя, и карточка называет причину.

Если payload с таким именем и протоколом уже есть, загрузка спрашивает, заменить ли его, и называет сеты, которые его используют. После Заменить эти сеты сразу отправляют новый файл.

Ваши payload​

Раздел перечисляет payload, сохранённые на роутере. Каждая карточка описывает один payload:

ЧастьЧто показывает
Имя и меткаИмя payload и TLS или QUIC - протокол, под которым он сохранён
Первая строкаЧто это за файл (TLS ClientHello, QUIC Initial, STUN-сообщение, DTLS ClientHello или нераспознанные данные), его размер и помещается ли он в один пакет
Вторая строкаИмя сервера (SNI), если оно есть в файле. Для TLS ClientHello ещё число расширений и ECH, если в нём есть расширение ECH
Третья строкаОткуда payload, Сгенерирован, Загружен или Импортирован с сетом, и когда он сохранён
Используют сетыСеты, которые используют этот payload

Предупреждение на карточке называет проблему payload:

ПредупреждениеЧто означает
Файла нетФайл пропал с роутера. Сеты, которые используют payload, отправляют Пресет: Google (классический) по TCP и нули по UDP, пока не выбран другой payload
Файл пустТо же, что при пропавшем файле
Больше одного пакетаПо TCP сет с выключенным Подгонять размер фейка не отправляет этот фейк на канале с MTU 1500 байт. По UDP уходит только начало файла
Не распознанФайл не TLS ClientHello, не QUIC Initial, не STUN и не DTLS. Он отправляется как есть
Поля с ошибкамиПоля ClientHello, которые строгий парсер отвергает, перечислены по имени. В сгенерированном payload их исправляет Сгенерировать заново
Тип не совпадает с протоколомQUIC Initial, STUN или DTLS, сохранённый как TLS, или TLS ClientHello, сохранённый как QUIC

Кнопки на карточке - иконки, ниже указаны их подсказки:

КнопкаЧто делает
Просмотр/Копирование hexОткрывает Hex-данные payload с байтами payload в hex. Копировать и закрыть копирует их в буфер обмена
Скачать .binСохраняет payload в файл
Сгенерировать зановоЕсть только у сгенерированных payload. После подтверждения собирает новый ClientHello под тем же именем и в тот же файл, с новыми случайными значениями и исправленными полями с ошибками. Сгенерированному payload с пропавшим файлом возвращает файл
УдалитьУдаляет payload. Если его используют сеты, сначала спрашивает подтверждение и называет их

У карточки с пропавшим файлом нет Просмотр/Копирование hex и Скачать .bin. Ещё две иконки находятся рядом с кнопкой Сгенерировать: Обновить список заново загружает список, а Удалить все payload удаляет все payload этого раздела после подтверждения, в котором названы сеты, которые их используют. Встроенные payload остаются.

Удаление, замена и повторная генерация сразу доходят до сетов, которые используют payload. После удаления эти сеты отправляют Пресет: Google (классический) по TCP и нули по UDP, после замены или Сгенерировать заново - новые байты. Если b4 не удаётся перезагрузить эти сеты, появляется сообщение.

Payload в сете​

TCP-фейки. На вкладке TCP сета, подвкладка Фейкинг, тип Свой файл payload в поле Тип фейкового payload показывает список Сгенерированный payload. В нём TLS-payload этой вкладки, у которых есть непустой файл, по алфавиту, у каждого строка с происхождением, типом, размером и числом полей с ошибками. Список и его предупреждения описаны на странице Фейкинг.

UDP-фейки. На вкладке UDP сета, когда Режим действия - Fake & Fragment, поле Payload фейкового пакета предлагает payload этой вкладки рядом со встроенными вариантами, QUIC-payload первыми. Фейк несёт столько байт payload, сколько задано в Размер фейкового пакета: длинный payload обрезается, короткий дополняется нулями. Если размер меньше payload, вкладка сообщает, сколько байт уходит, и предлагает Взять размер файла. Варианты описаны на странице UDP.

Payload в Дискавери​

Поле Сгенерированный или загруженный ClientHello как содержимое фейков в панели Параметры страницы Дискавери предлагает TLS-payload этой вкладки, у которых есть файл. Дискавери пробует выбранные payload раньше встроенных, а стратегия, найденная с одним из них, использует Свой файл payload с этим payload. Если со встроенными payload запуск ничего не находит, его можно повторить с payload, сгенерированными для нескольких имён.

Где хранятся payload​

Payload - это файлы в папке captures рядом с конфигурационным файлом. Вкладка показывает только payload, которые сохранил сам b4: файл, скопированный в эту папку вручную, на ней не появляется. Добавить его можно загрузкой.
